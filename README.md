## ✨ Why this project?

### 우리가 이걸 왜 만들까요?

새로운 LLM의 특징을 이해하려면 벤치마크 점수뿐 아니라, 그 결과를 만든 구조·데이터·학습 방법을 살펴봐야 합니다. Technical Report는 이러한 설계 선택과 실험 결과를 확인할 수 있는 자료입니다.

우리는 보고서가 전제하는 배경지식을 함께 공부하고, 각 모델이 어떤 문제를 어떻게 풀었는지 토론합니다. 이를 통해 새로운 모델의 발표를 따라가는 데서 더 나아가, 기술의 변화와 선택의 이유를 이해하고자 합니다.

### 🎯 우리가 풀고 싶은 문제

> “LLM Technical Report를 읽고 싶은 사람들이 본문에서 충분히 설명되지 않은 배경지식 때문에 핵심 기법과 설계 선택을 이해하는 데 어려움을 겪고 있다.”

## 🎯 Goal

### 이번 시즌의 목표

- [ ] LLaMA 1·Llama 2를 포함한 22편을 읽고, 핵심 기법이 해결하려는 문제와 이전 방법과의 차이를 설명합니다.
- [ ] 같은 보고서를 다섯 관점으로 분석해, 구조·데이터·학습의 연결과 설계 선택을 뒷받침하는 실험 근거를 정리합니다.
- [ ] 시즌 안에 주차별 공동 Markdown 문서 16개를 완성합니다. 각 문서에는 논문별 학습목표, 배경 개념, 다섯 팀의 분석, 원문 근거와 토론 내용을 담습니다.

## 🗺️ 16주 커리큘럼과 핵심 주제

LLaMA 1·Llama 2 기초 읽기를 포함해 22편을 16주 동안 읽습니다.

### 논문 선정 원칙

- 공식 Technical Report와 원문을 우선합니다.
- 설명의 깊이와 준비 분량, 모델 간 설계 차이를 함께 고려합니다.
- 새 보고서의 공개와 진행 상황에 따라 선정 논문은 조정될 수 있습니다.

## 👥 Analysis Teams

정규 참여자는 관심 있는 분석팀을 직접 선택해 시즌 동안 해당 관점의 분석을 맡습니다. 팀당 2명을 기본으로 하되, 관심 분야와 모집 상황에 따라 팀 구성과 인원은 달라질 수 있습니다.

### 1. Architecture & Pre-training

모델이 어떤 구조로 설계되었고 사전학습이 어떻게 이루어졌는지 분석합니다.

- Dense, MoE와 hybrid architecture
- attention, context length와 모델 규모
- pre-training objective와 학습 단계
- scaling strategy, training stability와 infrastructure
- 구조·학습 방식에 따른 품질, 연산 비용, 지연 시간과 메모리 사용량 비교

### 2. Data & Synthesis

모델 성능의 기반이 되는 데이터의 구성과 생성 과정을 분석합니다.

- 데이터 출처, 규모와 도메인 구성
- filtering, deduplication과 quality control
- data mixture와 curriculum
- synthetic data 생성, 정제와 검증
- 데이터 구성·정제·합성이 성능에 미친 영향과 contamination 점검
- 공개되지 않은 데이터 정보와 재현성 한계

### 3. Post-training

사전학습된 모델을 실제 사용 목적에 맞게 조정하는 지도학습 중심의 과정을 분석합니다.

- supervised fine-tuning과 instruction tuning
- 목적별 adaptation·mid-training과 SFT의 경계
- distillation의 학습 데이터·teacher 신호와 model specialization
- tool use, coding과 agent task를 위한 학습 구성
- 학습 전후의 능력 변화, 증류 효과와 과제별 성능 trade-off

### 4. Alignment & RL

모델의 응답을 사람의 의도와 과제 목표에 맞추는 정렬 및 강화학습 과정을 분석합니다.

- preference data와 reward modeling
- RLHF, RLVR와 reinforcement learning objective
- DPO의 선호쌍 기반 최적화와 GRPO의 group-relative 강화학습
- safety alignment와 behavior control
- 학습 안정성, reward hacking과 alignment trade-off
- 보상 증가가 실제 과제 성능·안전성 개선으로 이어지는지 검토

### 5. Background

해당 보고서를 이해하는 데 필요한 배경지식과 선행 연구를 연결합니다.

- 핵심 기법이 등장한 배경과 이전 방법의 한계
- 본문 이해에 필요한 개념, 수식과 표기

## 🧑‍🤝‍🧑 How We Work

1. **모임 전 — 읽기·준비:** 모두 해당 주차의 논문 전체를 읽고, 소속 팀의 관점에서 발표를 준비합니다. 두 편을 묶은 주차는 두 편 모두 읽습니다. 분석 내용과 원문 근거, 이해되지 않은 개념과 토론할 질문을 주차별 공동 문서에 모읍니다.
2. **토요일 모임 — 발표·토론:** 다섯 팀이 준비한 내용을 공유합니다. 배경 개념을 짚고, 주요 설계 선택과 실험 결과를 함께 검토하며 준비한 질문을 토론합니다.
3. **모임 후 — 공동 문서 정리:** 토론에서 확인한 내용과 남은 질문을 반영해 그 주의 문서 하나로 정리합니다. 참여자들이 돌아가며 주간 편집자를 맡아 팀별 내용을 취합하고 중복된 설명과 원문 링크를 점검합니다.

## 🔭 시즌 이후: LLM 계보와 기술 변화 정리 (선택)

시즌 종료 후에는 주간 기록을 바탕으로 **모델 계보와 기법의 변화 과정을 연결한 서베이형 문서**를 함께 정리합니다. 모델별 요약을 모으는 데 그치지 않고, 어떤 문제에서 기법이 등장했고 후속 모델에서 무엇이 유지·변경되었는지 살펴봅니다.

- **모델 계열별 변화:** 세대별 구조·데이터·학습·평가의 공통점과 변경점
- **기법별 흐름:** attention과 메모리, 학습 안정성, 합성 데이터, 증류·RL 등 주제별 해법의 변화와 분기
- **근거를 갖춘 비교:** 원문이 밝힌 계승 관계와 학습을 위한 비교를 구분하고, 성능·비용 수치의 조건과 미공개 범위를 함께 정리

구성 방향은 [LLM Internals: 언어 모델의 계보와 알고리즘 진화](https://speakerdeck.com/inureyes/llm-internals-language-model-genealogy-and-algorithm-evolution-2023-2026)를 참고합니다. 새로운 보고서가 나오면 비교 자료와 계보를 업데이트합니다.
