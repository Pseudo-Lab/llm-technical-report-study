# 논문 파트별 내용·분량 추출

기술보고서를 읽고 스터디의 다섯 파트가 **무엇을 설명할 수 있어야 하는지**를 정리한 한국어 읽기 지도를 만든다. 결과는 근거 원본 Markdown과 같은 내용을 한 페이지씩 넘기는 HTML이다. 담당자가 첫 페이지만 보고 자기 파트의 범위와 분량, 함께 할 파트를 알 수 있어야 한다.

## 결과의 구성

| 순서 | 페이지 | 담을 것 |
| --- | --- | --- |
| 0 | 파트별 볼 범위 | 담당 배정에 바로 쓰는 짧은 목록. 파트마다 `절 제목 ~ 절 제목 (N~M page)` 줄과 그 범위에서 볼 것 한 줄 |
| 1 | 다섯 파트가 다루는 내용 | 파트마다 이번 논문에서 다루는 내용 한 줄 · 필수 원문(절·표) · 개념 수 · 분량 막대 |
| 2 | 분량과 함께 할 파트 | 파트 간 분량 차이, 같은 원문이나 같은 신호를 공유하는 곳, 묶어서 준비할 조합 제안 |
| 3– | 파트별 질문 | 파트당 1페이지. `RQ1. …?` 형식의 질문마다 필수 원문과 나오는 개념 목록(개념 페이지 링크) |
| | 개념 페이지 | **개념당 1페이지.** 무엇인가 · 원문 어디에 나오나 · 설명할 수 있어야 하는 것(체크 2–4개) · 함께 볼 개념 |
| | Background 빈 영역 | 지금까지 스터디에서 다루지 않았고, 그 사이에 나온 논문에서 처음 등장해 이번 논문이 가져다 쓴 개념의 표 |
| 끝 | 입력과 검토 상태 | 판본·확인한 범위·사람 검토 상태 한 페이지 |

파트 순서는 **Architecture & Pre-training → Data & Synthesis → Post-training → Alignment & RL → Background**로 고정한다. K ID, 주관/공동 참조 원장, 항목별 상태표처럼 관리용 장치를 본문에 두지 않는다. 근거는 각 페이지의 원문 위치 링크로 충분하다.

## 입력

- 기술보고서 원문/PDF와 정확한 버전.
- 이 저장소에서는 해당 주차의 `docs/weeks/wNN/README.md`(학습목표), `docs/background/wNN.md`, `docs/background/workload.md`.
- **이전 주차까지 다룬 개념**: `docs/weeks/` 아래 이전 주차 읽기 지도·학습목표. Background의 빈 영역 판정에 쓴다. 첫 주차라면 스터디 참여 전제(README의 Transformer·LLM 기본 학습 과정)만 이미 다룬 것으로 본다.
- 출력 위치는 사용자가 지정한 곳을 따른다. 지정이 없으면 Markdown만 채팅으로 돌려준다. 주간 문서·학습목표를 덮어쓰지 않는다.

## 작성 절차

0. **파트별 볼 범위 먼저.** 담당 범위가 아직 없으면 읽기 지도보다 이 목록을 먼저 채팅으로 돌려주고, 사람이 담당자를 붙여 확정한 뒤 나머지를 쓴다. 범위가 이미 정해졌으면 그대로 옮긴다. 형식은 아래와 같다.

   ```text
   [Architecture & Pre-training] - {담당 또는 미정}
   * Qwen : 2.3 Architecture (page 6) ~ 2.6 Experimental Results (page 9)
   * Qwen2 : 2.2 Model Architecture (page 4~5) + 3.2 Long-context Training (page 6)
     → MHA→GQA · RoPE 확장(NTK → YaRN · DCA) · MoE 초기화 · Table 1
   ```

   - 원문을 직접 열어 절 제목을 원문 표기 그대로, 쪽은 **인쇄 쪽수**로 적는다. 파일 페이지와 다르면 둘 다 적는다. 부록은 본문 범위 뒤에 `+ 47 page`처럼 붙인다.
   - 범위는 절 경계로 자른다. 한 절의 일부만 넘기면 `Tokenizer 제외`처럼 무엇을 뺐는지 적는다.
   - 본문의 모든 절이 어느 파트에 들어가거나 “배정 밖”에 나열되게 한다. 서론 · 결론은 공통으로 둔다.
   - 같은 주제가 방법(본문)과 평가(뒤쪽 절)로 나뉘면 같은 파트에 묶는다(예: 긴 문맥 학습 §3.2 + 긴 문맥 평가 §5.2.3).
   - 주 자료가 둘 이상이면(전작 · 후속작 보고서, 출시 글 · config) 파트 안에서 **자료마다 한 줄**(`* 자료 : 절 (page)`)로 나눠 적고, 쪽수는 자료마다 따로 센다. 보고서가 아닌 자료는 종류를 표시한다. 자료 이름은 원문 제목을 따른다(예: arXiv 2309.16609는 Qwen1.5가 아니라 Qwen 보고서).
   - 절의 본문과 그 절의 표 · 그림이 다른 쪽에 있으면 끝 쪽을 표까지 늘려 적는다.
   - 범위를 나눈 뒤 파트별 분량(본문 쪽 · 표 수 · 개념 수 · 읽을 원전)을 표로 보이고, 배정 밖으로 남은 절을 쪽수와 함께 나열한다.
   - 분량이 한쪽으로 몰리면 나눌 곳을 한 줄로 제안한다. 담당자 이름은 사용자가 준 것만 쓴다.
1. **원문 범위 확인.** 판본, 읽은 절·부록·표를 적는다. PDF는 파일 페이지 기준으로 링크한다. 읽지 못한 범위는 검토 페이지에 남기고 “없음”으로 단정하지 않는다.
2. **파트별 질문 정하기.** 파트마다 이번 논문이 실제로 답하는 질문을 1–4개 `RQ1. …?`로 쓴다. 학습목표가 있으면 그 문장에서 출발한다. 질문 하나에는 필수 원문(절·표·그림)과 그 질문에 답하려면 알아야 하는 개념을 붙인다.
3. **개념 뽑기.** 필수 원문에 등장하고, 발표자가 설명하지 못하면 질문에 답할 수 없는 용어·기법만 개념으로 올린다. 같은 개념은 한 파트에만 페이지를 두고 다른 파트에서는 링크한다. 원문이 이름만 언급하고 설명하지 않는 개념은 “원문은 채택 사실만 기술”이라고 적는다.
4. **개념 페이지 쓰기.** 각 개념은 다음 네 필드로 쓴다. 필요하면 `왜 그런가` · `그 뒤의 흐름 (논문 밖)` · `계산해 보면` 필드를 더한다. “무엇을 바꾸는가”의 실행 경로를 길게 풀지 말고, 발표자가 말로 설명할 수 있어야 할 것을 체크 목록으로 남긴다.
   - **무엇인가:** 한두 문장 정의.
   - **원문:** 이 논문의 절·표 링크와 원문이 실제로 말하는 범위.
   - **설명할 수 있어야 하는 것:** `- [ ]` 체크 2–4개. 비교 대상·수치·조건이 핵심이면 포함한다.
   - **함께 볼 개념 / 원전:** 다른 개념 페이지 링크, 처음 제안한 논문과 읽을 절(선택).
5. **Background 빈 영역 표.** 이번 논문이 쓰는 개념 중 (a) 이전 주차에 다루지 않았고 (b) 스터디 전제(원 Transformer) 이후의 중간 논문에서 처음 나온 것을 고른다. 열은 `개념 | 처음 나온 논문(연도) | 이번 논문에서 쓰인 곳 | 이전 주차 | 같이 볼 파트`. 원 제안 논문과 이를 먼저 채택한 모델을 구분한다(예: SwiGLU는 Shazeer 2020 제안, PaLM이 채택). Background는 이 표와, 다른 파트에 속하지 않는 배경 개념(스케일링 법칙 등)의 개념 페이지를 가진다. 원문이 한 줄이나 출처 표기로 넘어간 주제(예: LLaMA 1의 Scaling Law · Tokenizer · RoPE · 품질 분류기)는 따로 묶는다. 주제마다 **원문이 한 말 · 다음 주에 깊게 볼 것 · 담당 파트**를 적고, 등장 배경 → 이 논문 → 이후를 한 장으로 보는 로드맵을 둔다. 담당 파트는 Background에 몰지 말고 그 주제가 쓰이는 파트로 정한다(RoPE → Architecture & Pre-training, 품질 분류기 → Data & Synthesis). 발표자료는 이 묶음을 부록 Background와 본편의 “다음 주 깊게 다시 다룰 내용” 표시로 옮긴다.
6. **분량과 협업.** 분량은 `개념 수`와 `필수 원문 분량(쪽·절·표 수)`으로 매기고 `■■■□□ 중간`처럼 다섯 칸 막대와 낮음/중간/높음으로 표시한다. 점수나 시간처럼 측정값으로 만들지 않는다. 분량이 적은 파트는 어느 파트의 질문을 함께 맡으면 좋은지, 많은 파트는 어느 질문을 나눌 수 있는지 2쪽에 제안한다. 같은 표·같은 데이터·같은 신호를 두 파트가 보면 그 연결을 적는다. 제안은 사람이 정한다.

## 깊이 기준

읽기 지도는 원문을 한 번 더 요약하는 문서가 아니다. 발표자가 “왜 그렇게 했나, 그 뒤 어떻게 됐나”까지 답할 수 있어야 한다.

- **논문의 출발점이 되는 개념은 여러 페이지로 나눈다.** 예: 보고서가 특정 선행 결과를 다시 읽는 데서 시작하면(LLaMA의 Chinchilla 스케일링 법칙) 선행 연구의 질문 · 결론 · 핵심 식과 수치, 이 논문이 바꾼 기준을 각각 한 페이지로 쓴다. 원문의 핵심 문장은 짧게 인용한다.
- **데이터는 소스마다 한 페이지.** 각 소스의 비율 · 반복량 · 크기, 무엇이 들어 있는지, 언어, 그 소스만의 전처리(필터 · 중복 제거 단위 · 라이선스)를 원문 그대로 적는다. 언어 구성은 따로 한 페이지로 모은다. 표의 수치로 계산할 수 있는 것(예: 고유 토큰 = 비율 × 총 토큰 ÷ epochs)은 계산해 보인다.
- **설정값은 출처와 비교한다.** optimizer · 스케줄 · warmup 같은 하이퍼파라미터는 라이브러리 기본값과 선행 모델의 값을 같은 표에 두고, 원문이 이유를 밝혔는지 적는다. 밝히지 않았으면 “원문 미기술”과 일반적 설명을 구분한다.
- **구현 · 시스템 숫자는 직접 계산한다.** GPU 수 · 처리량 · 기간이 나오면 서로 맞는지, compute · MFU · 메모리가 얼마인지 계산하고 가정을 적는다.
- **평가는 결과보다 “무엇을, 어떻게”가 먼저다.** 벤치마크마다 무엇을 평가하는지, 입력 형식(보기 수 · 지문 유무), 지표, shot 수를 표로 쓴다. 실제 문항을 옮기지 않을 때는 설명용 예시임을 표시한다. 원문이나 부록에 프롬프트 형식이 있으면 zero-shot · few-shot 프롬프트를 그대로 보여준다. 채점 방식(likelihood 순위 · 생성 후 exact match · 다수결 · pass@k)은 같은 문항으로 한 단계씩 계산해 보이고, 정규화(길이 · 조건부 확률)가 **왜 필요한지**를 수치 예시로 설명한다. 원문이 밝힌 벤치마크 수와 실제로 나열된 수가 다르면 그대로 적는다.
- **그림이 말하는 현상에 “왜”를 붙인다.** 예: 큰 모델일수록 loss가 낮은 이유와 그것이 깨지는 조건.
- **파트마다 “이전 → 이 논문 → 현재”로 비교한다.** 핵심 주제(예: 모델 크기와 스케일링 법칙, 데이터, 평가)마다 이 논문 이전의 관행과 그 이유, 이 논문의 선택과 그 이유, 읽는 시점의 현재 관행을 한 페이지로 둔다. 현재 열은 확인한 최신 보고서의 수치와 출처를 쓰고, 이 스터디 커리큘럼에서 다시 나오는 주차를 표시한다. 같은 계열 후속 모델의 미래 예측은 쓰지 않는다.
- **후속 연구 페이지를 둔다 (논문 밖).** 핵심 데이터 · 학습 설정이 같은 계열의 후속 모델과 다른 연구에서 어떻게 이어지거나 바뀌었는지, 확인한 출처 링크와 함께 쓴다. 이 스터디의 다른 주차에서 다시 나오면 그 주차를 적는다. 2차 출처만 확인한 사실은 그렇게 표시한다.
- **중간 과정을 생략하지 않는다.** 개념 페이지는 읽는 사람이 그 페이지만 보고 따라갈 수 있게, 입력 → 중간 결과 → 출력을 실제 값으로 적는다. 용어 · 약어는 처음 나오는 곳에서 풀고, 같은 숫자가 두 의미면(예: BPE 순위 = token_id) 둘 다 적는다. 원문에 없는 개념을 설명용으로 들이면 그렇게 표시한다.

## 정확성 원칙

- 원문에 **기술됨 / 기술되지 않음(미기술) / 하지 않았다고 명시**를 구분한다. 미기술을 미수행으로 쓰지 않는다.
- 저자 설명·실험 결과·저자 가설·추출자 해석을 섞지 않는다. 해석이면 “추출자 해석”, 가설이면 “저자 가설”이라고 붙인다.
- 비교 수치는 모델·metric·shot·조건과 함께 적는다. 원문에 없는 조건을 다른 표에서 옮기지 않는다.
- 이해를 돕는 축약식·도식은 “설명용”으로 표시한다. 현재 코드의 기본값을 과거 논문 설정으로 옮기지 않는다.
- 비율 · 속도 · 점수와 “누가 무엇을 인용했나”는 원문을 다시 열어 확인한다. 외부 근거는 이 논문이 인용했는지 함께 적는다. 인용한 원전의 수치는 어느 설정의 값인지까지 옮긴다.
- 토크나이저 · 공개 설정 파일처럼 직접 돌릴 수 있는 것은 돌린 결과를 쓴다(예: 어떤 음절이 어휘에 있는지). 분류를 세우면 반례를 먼저 찾는다(예: “공개 데이터 = 약한 모델” 대 The Pile).
- 개념 페이지의 “왜”는 두 단계 아래까지 쓴다(예: Pre-norm이 안정적이다 → 잔차 경로가 x₀를 정규화 없이 그대로 더한다 → 아래층까지 gradient가 직접 흐른다). 기호는 처음 나오는 곳에서 정의한다.
- 사람 검토 상태의 기본값은 **미검토**다. AI 재검토를 사람의 승인으로 바꾸지 않는다.

[출력 양식](assets/reading-map-template.md)을 채운다. 규칙은 단순하다.

- H2 앞에 `<!-- part: overview|architecture|data|post|alignment|background|common -->` 마커를 둔다.
- **H3 하나가 HTML 한 페이지**다. 개념 페이지 H3 바로 앞에 `<a id="c-영문-slug"></a>`를 두면 다른 페이지의 `[RMSNorm](#c-rmsnorm)` 링크가 그 페이지를 연다.
- 표·목록은 일반 GFM으로 쓴다. 체크 목록은 `- [ ]`를 쓴다.

```sh
node scripts/render_reading_map.mjs input.md output.html --title '보고서 — 다섯 파트 읽기 지도'
node scripts/test_render_reading_map.mjs
```

Node.js와 `marked`가 필요하다. 기본 탐색이 안 되면 `MARKED_MODULE`에 `marked` 모듈 경로를 지정한다. HTML은 첫 페이지(다섯 파트)에서 시작하고 이전/다음·`←`/`→`·`Home`/`End`·페이지 목록·파트 탭으로 이동한다. 링크한 개념 페이지는 해당 파트 탭과 함께 열린다. [HTML shell](assets/reading-map-shell.html)을 직접 열면 양식 미리보기가 보인다.

## 최종 확인

파트별 볼 범위가 본문 절을 빠짐없이 덮는지(배정 밖 포함), 쪽수가 원문과 맞는지, 1쪽만 보고 파트별 내용·필수 원문·분량을 말할 수 있는지, 2쪽에 협업 제안이 있는지, 모든 RQ의 개념이 개념 페이지로 연결되는지, 개념 페이지가 파트당 한 번만 있는지, Background 표가 이전 주차 대비 새 개념만 담는지 확인한다. HTML을 PC와 휴대폰 너비로 열어 이동·링크·표 잘림을 확인하고, 실제로 본 범위만 검토 페이지에 적는다. 발표자료(#169)는 사람이 검토한 범위를 입력으로 쓴다.
