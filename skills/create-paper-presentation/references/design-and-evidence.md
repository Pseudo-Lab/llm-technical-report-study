# 화면 구성과 근거 보존

## 밝은 학술 발표 화면

디자인 참고 출처: [research-idea-deck](https://github.com/choco9966/research-idea/tree/main/skills/research-idea-deck)의 밝은 배경·계층·타이포그래피 원칙. 해당 저장소의 연구 제안 서사와 고정 목차는 적용하지 않는다.

- 배경 `#E9ECF0`, 슬라이드 `#F7F8FA`, 내부 면 `#FFFFFF`. 글자 `#1A1D23`, 보조 글자 `#5D6570`.
- 파랑 `#2E55A5`, 초록 `#2B7858`, 주황 `#A65A2E`을 방법·비교·주의에 사용하되 각 차트의 범례가 의미를 결정한다. 색만으로 구분하지 말고 이름·값·선 모양을 함께 둔다.
- 한국어는 `word-break: keep-all`. 제목은 화면 결론을 짧게 쓰고, 긴 단락은 발표 노트나 연결된 읽기 지도에 둔다. 주의 조건이 결론을 바꾼다면 본문에서 제거하지 않는다.
- 슬라이드 좌표계의 본문은 약 20px 이상, 도식의 핵심 라벨은 약 18px 이상부터 시작한다. 실제 패널에서 축소된 크기도 읽어본다. 출처·보조 주석은 더 작게 둘 수 있으나 핵심 caveat를 출처 크기로 숨기지 않는다.

## 정보별 배치

| 질문 | 적합한 표현 | 확인할 점 |
| --- | --- | --- |
| 어떤 단계로 이어지나? | 전체 폭 흐름도 | 각 단계 입력/출력, 실제 흐름의 방향, 서로 다른 학습 단계 |
| 무엇이 달라졌나? | 전후 블록·경로 비교 | 동일 연산 이름과 위치, residual/분기/공유 연결, 생략 범위 |
| 어느 조건에서 얼마나 다른가? | 동일 축 막대·점 비교 | 단위, 조건, 원수치, 승패가 바뀌는 조건 |
| 무엇을 설정했나? | 단위가 있는 표 | 행·열의 의미, 반올림 모델명, 미기술 설정 |
| 무엇을 아직 모르는가? | 관찰과 열린 질문을 나란히 | 저자 주장·가설·발표자 해석의 주체 |

연속해서 동일한 텍스트 상자 묶음이 나오면, 정보 관계가 보이지 않는지 확인한다. 질문에 맞는 배치를 선택하며, 장수나 도식 수를 채우기 위해 의미 없는 그림을 넣지 않는다.

큰 블록을 여러 패널로 나눴다면 패널 사이의 실제 순서를 표시한다. 중간 차원·출력 차원 라벨은 해당 신호 가까이에 두고, 연결선은 실제 연산이나 합류점에서 끝나게 한다. 곡선·연결선이 라벨을 통과하지 않는지 렌더에서 확인한다.

## 개념 장과 예시

개념 장은 **그림 또는 펼친 식 + 작은 숫자 예시 + 4단계 이내 설명**으로 만든다. 그림이 개념을 더 어렵게 만들면 식과 예시로 바꾼다.

- 펼친 식: 묶어 쓴 식을 층이나 항 단위로 펼친다(예: Post-norm x₁ = LN(x₀ + F₁) 대 Pre-norm x₂ = x₀ + F₁ + F₂, 더하기 위치 표현의 네 항).
- 숫자 예시: 손으로 따라갈 수 있는 크기로 쓴다(예: [2, 4, 6]의 LayerNorm · RMSNorm 결과, Φ(1) = 0.84 · σ(1) = 0.73).
- 규칙은 되는 예와 예외를 나란히 둔다(예: 어휘에 있는 "안" 1토큰 · 없는 "녕" 바이트 3토큰). 데이터 처리는 처리 전 원문과 처리 후 실제 레코드를 나란히 두고, 지어낸 예는 "설명용"으로 표시한다.
- 기호와 용어는 처음 나오는 장에서 한 줄로 정의한다(perplexity, Φ와 σ, GELU와 GLU). "왜"는 두 단계 아래까지 준비한다. 장마다 청중이 할 질문을 하나 적어 보고, 답이 화면이나 대본에 있는지 확인한다.

## 수치와 도식의 근거 계약

각 비교의 작성 메모에는 아래 정보를 모은다. 화면에는 비교를 바꿀 수 있는 조건과 직접 연결되는 원문을 남긴다.

`원문 판본 | 절/표/그림/파일 페이지 | K ID | 모델·stage | task | metric·단위 | shot | sampling/decoding | 관찰 값 | 직접 계산 값 | 미기술`

- 막대 길이는 0 기준 정량 비율로 그린다. 차이만 보여주는 축이면 단위와 0 기준을 명시하고 원수치도 함께 적는다. 서로 다른 metric을 하나의 공통 성능 막대로 합치지 않는다.
- 과제 평균은 원문에서 보고한 평균인지 확인한다. 임의의 benchmark 종합 점수를 만들지 않는다.
- schematic, 개념 곡선, 설명용 토큰 예시는 라벨로 표시한다. 알려지지 않은 총 step 수나 실제 token ID를 채우지 않는다.
- 부품의 채택·전체 recipe의 성능·부품별 ablation은 서로 다른 증거다. 전체 성능을 부품 하나의 인과 효과로 연결하지 않는다.
- 외부 근거는 그 논문이 인용했는지 함께 적는다. 인용하지 않은 후속 · 동시대 연구를 "이 논문의 근거"로 쓰지 않는다. 인용한 원전의 수치는 어느 설정의 값인지까지 옮긴다(예: RMSNorm 7–41% 중 Transformer 6.9%, 64%는 근사판).
- 외부 원전이 설명하는 연산과 해당 논문이 실제로 채택했다고 밝힌 범위를 분리한다. 현재 코드의 기본값을 과거 논문 recipe로 옮기지 않는다.

## 구현과 검토

HTML은 `.slide[data-sec][data-nav]` 안에 `.card > .inner`와 `.src`를 둔다. 기본은 본문/시각자료 분할이며 `.inner.wide`는 넓은 도식에 쓴다. 레이아웃 종류별 CSS를 추가할 수 있다. 각 슬라이드의 `data-section-label`을 같은 구간에서 일관되게 설정한다.

브라우저 확대만으로 가독성을 맞추지 않는다. 좁은 패널에서는 읽기 모드를 선택할 수 있고, 모바일에서는 문장과 그림이 세로로 이어져야 한다. 넓은 표는 그 영역 안에서 스크롤하게 만들고 안내를 표시한다. 세로 터치 스크롤과 표 가로 스크롤이 슬라이드 전환으로 처리되지 않도록 한다.

`check_deck.cjs`는 화면·이동·로컬 링크 존재를 검사하고 렌더를 남긴다. 데스크톱 · 태블릿 · 휴대폰에서 실패가 0건이 될 때까지 고친다. 외부 링크의 HTTP 상태나 논문의 정확성을 증명하는 도구는 아니다. 보고서에 자동 검사 범위와 실제 사람이/AI가 본 범위를 분리해 쓴다.
