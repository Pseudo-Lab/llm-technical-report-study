# 화면 구성과 근거 보존

## 밝은 학술 발표 화면

디자인 참고 출처: [research-idea-deck](https://github.com/choco9966/research-idea/tree/main/skills/research-idea-deck)의 밝은 배경·계층·타이포그래피 원칙. 해당 저장소의 연구 제안 서사와 고정 목차는 적용하지 않는다.

- 배경 `#E9ECF0`, 슬라이드 `#F7F8FA`, 내부 면 `#FFFFFF`. 글자 `#1A1D23`, 보조 글자 `#5D6570`.
- 파랑 `#2E55A5`, 초록 `#2B7858`, 주황 `#A65A2E`을 방법·비교·주의에 사용하되 각 차트의 범례가 의미를 결정한다. 색만으로 구분하지 말고 이름·값·선 모양을 함께 둔다.
- 한국어는 `word-break: keep-all`. 제목은 화면 결론을 짧게 쓰고, 긴 단락은 대본 · 근거 패널 · 연결된 읽기 지도에 둔다. 주의 조건이 결론을 바꾼다면 화면에서 제거하지 않는다(조건 줄 `.cond`).
- 슬라이드 좌표계에서 v2 셸 본문은 20px, 도식의 핵심 라벨은 약 18px 이상부터 시작한다. 조건 줄은 16px 이상이다. 실제 패널에서 축소된 크기도 읽어본다. 출처 · 보조 주석 · 근거 표지는 더 작게 둘 수 있으나 핵심 caveat를 출처 크기로 숨기지 않는다.

## 정보별 배치

| 질문 | 적합한 표현 | 확인할 점 |
| --- | --- | --- |
| 어떤 단계로 이어지나? | 전체 폭 흐름도 | 각 단계 입력/출력, 실제 흐름의 방향, 서로 다른 학습 단계 |
| 무엇이 달라졌나? | 전후 블록·경로 비교 | 동일 연산 이름과 위치, residual/분기/공유 연결, 생략 범위 |
| 어느 조건에서 얼마나 다른가? | 동일 축 막대·점 비교 | 단위, 조건, 원수치, 승패가 바뀌는 조건 |
| 무엇을 설정했나? | 단위가 있는 표 | 행·열의 의미, 반올림 모델명, 미기술 설정 |
| 무엇을 아직 모르는가? | 관찰과 열린 질문을 나란히(본편 끝 '열린 질문 · 토론' 장) | 저자 주장·가설·발표자 해석의 주체 |
| 곱으로 된 결과는 무엇에서 나왔나? | 요인 분해 카드 | 변한 요인 · '동일' 요인, config · 식과 일치 |
| 본문 주장이 표와 맞나? | 주장 주석 표 + 판정 띠 | 범례, 원문 굵게와 발표자 표시 구분, 예외를 같은 줄에 |

연속해서 동일한 텍스트 상자 묶음이 나오면, 정보 관계가 보이지 않는지 확인한다. 질문에 맞는 배치를 선택하며, 장수나 도식 수를 채우기 위해 의미 없는 그림을 넣지 않는다.

큰 블록을 여러 패널로 나눴다면 패널 사이의 실제 순서를 표시한다. 중간 차원·출력 차원 라벨은 해당 신호 가까이에 두고, 연결선은 실제 연산이나 합류점에서 끝나게 한다. 곡선·연결선이 라벨을 통과하지 않는지 렌더에서 확인한다.

## 개념 장과 예시

개념 장은 **그림 또는 펼친 식 + 작은 숫자 예시 + 4단계 이내 설명**으로 만든다. 그림이 개념을 더 어렵게 만들면 식과 예시로 바꾼다.

- 펼친 식: 묶어 쓴 식을 층이나 항 단위로 펼친다(예: Post-norm x₁ = LN(x₀ + F₁) 대 Pre-norm x₂ = x₀ + F₁ + F₂, 더하기 위치 표현의 네 항).
- 숫자 예시: 손으로 따라갈 수 있는 크기로 쓴다(예: [2, 4, 6]의 LayerNorm · RMSNorm 결과, Φ(1) = 0.84 · σ(1) = 0.73).
- 규칙은 되는 예와 예외를 나란히 둔다(예: 어휘에 있는 "안" 1토큰 · 없는 "녕" 바이트 3토큰). 데이터 처리는 처리 전 원문과 처리 후 실제 레코드를 나란히 두고, 지어낸 예는 "설명용"으로 표시한다.
- 기호와 용어는 처음 나오는 장에서 한 줄로 정의한다(perplexity, Φ와 σ, GELU와 GLU). "왜"는 두 단계 아래까지 준비한다. 장마다 청중이 할 질문을 하나 적어 보고, 답이 화면이나 대본에 있는지 확인한다.

펼친 식 · 단계 카드(`.derive`) · 작은 숫자 예시, 그리고 running example의 실제 값 사슬(예: 글자 → 유니코드 번호 → UTF-8 바이트 → token_id)은 값이 적힌 단계 카드로 화면에 둔다. 값 자체가 기제이기 때문이다. 근거 패널로 보내는 것은 식에 숫자를 넣는 산술(`p.subst`)과 긴 대입뿐이다. 두 층을 합치면 장 하나만 보고 처음부터 끝까지 따라갈 수 있어야 한다.

## 수치와 도식의 근거 계약

각 비교의 수치와 주장은 근거 원장(`claims.json`, [claim-ledger.md](claim-ledger.md))에 모은다. 화면에는 비교를 바꿀 수 있는 조건과 직접 연결되는 원문을 남기고, 나머지는 근거 패널로 보낸다. 예전 작성 메모의 칸은 원장 필드로 이렇게 옮긴다.

`원문 판본 | 절/표/그림/파일 페이지 | 읽기 지도 항목 | 모델·stage | task | metric·단위 | shot | sampling/decoding | 관찰 값 | 직접 계산 값 | 미기술`

| 작성 메모 칸 | 원장 · 덱 JSON 자리 |
| --- | --- |
| 원문 판본, 절/표/그림/파일 페이지 | claim `sources[].label`(예: `LLaMA v1 Table 3 (p.4)`) · `url`(`#page=N`) |
| 읽기 지도 항목(파트 · RQ 번호 · 개념 페이지 이름) | 장 `ids`(출처 줄 오른쪽 `.src-ids`). 읽을 수 있는 라벨로 쓰고 `#c-…` 같은 원시 앵커 이름은 쓰지 않는다(예: `지도 · KV cache 계산`) |
| 모델·stage, task, metric·단위, shot, sampling/decoding | claim `conditions`, 결론을 바꾸는 하나는 `screen_condition` |
| 관찰 값 | `kind: "table"` 또는 `"orig"` claim의 `statement` · `value` · `unit` · `display` |
| 직접 계산 값 | `kind: "calc"` claim의 `expr` · `formula` · `inputs` |
| 미기술 | `kind: "nd"` claim, 또는 `conditions`에 "… 미기술" |

- 막대 길이는 0 기준 정량 비율로 그린다. 차이만 보여주는 축이면 단위와 0 기준을 명시하고 원수치도 함께 적는다. 서로 다른 metric을 하나의 공통 성능 막대로 합치지 않는다.
- 과제 평균은 원문에서 보고한 평균인지 확인한다. 임의의 benchmark 종합 점수를 만들지 않는다.
- schematic, 개념 곡선, 설명용 토큰 예시는 라벨로 표시한다. 알려지지 않은 총 step 수나 실제 token ID를 채우지 않는다.
- 부품의 채택·전체 recipe의 성능·부품별 ablation은 서로 다른 증거다. 전체 성능을 부품 하나의 인과 효과로 연결하지 않는다.
- 외부 근거는 그 논문이 인용했는지 함께 적는다. 인용하지 않은 후속 · 동시대 연구를 "이 논문의 근거"로 쓰지 않는다. 인용한 원전의 수치는 어느 설정의 값인지까지 옮긴다(예: RMSNorm 7–41% 중 Transformer 6.9%, 64%는 근사판).
- 외부 원전이 설명하는 연산과 해당 논문이 실제로 채택했다고 밝힌 범위를 분리한다. 현재 코드의 기본값을 과거 논문 recipe로 옮기지 않는다.

외부 원전의 수치 · 실험 조건 · '이 논문 수치 아님' 표시는 근거 패널에 두고, 화면에는 `인용 원전` 표지와 출처 식별자를 남긴다.

## 출처 라벨

- 라벨은 `{자료} {절 · 표 · 그림} (p.N)` 꼴이다(예: `LLaMA v1 Table 3 (p.4)`). PDF 링크는 `#page=N`.
- **HTML판만 읽은 경우**(arXiv HTML 등, 쪽 번호가 없음): 라벨은 `{자료} §X (HTML판, 쪽 미확인)`, 링크는 `https://arxiv.org/html/{id}#{앵커}`(예: `#S2.T1`)로 둔다. 표가 이미지가 아니라 HTML이면 HTML 렌더를 캡처해 crop 자리에 쓰고, 캡션에 'HTML판 렌더, PDF crop 아님'을 적는다. 확인하지 못한 쪽 번호는 검토 기록에 남기고, PDF를 열 수 있게 되면 라벨을 고친다.
- 남의 라벨 · 쪽 번호를 확인 없이 옮기지 않는다(다른 덱 · 예시에 있던 쪽 번호도 원문에서 다시 확인한다).

## 근거 표지 위계

근거 표지는 `<span class="ev-chip" data-ev="{kind}">{라벨}</span>`이다. 라벨 글은 아래 표 그대로 쓴다(측정 도구가 낱말로 센다). 원장 `kind`와 같은 어휘다.

| `data-ev` | 라벨 | 붙이는 곳 | 모양 |
| --- | --- | --- | --- |
| `orig` | 원문 | 원문 문장을 옮긴 주장. 출처 줄로 충분하면 생략 | 회색 테두리 |
| `table` | 표 값 | 원문 표의 값. 출처 줄로 충분하면 생략 | 회색 테두리 |
| `config` | config | 논문이 아니라 공개 설정 파일에서 온 값(예: Llama 2-70B KV head 8) | 회색 테두리 |
| `calc` | 계산 | 원문 · config 값으로 발표자가 직접 계산한 값 | 초록 |
| `est` | 추정 | 원문에 없어 다른 값에서 추론했거나 그림에서 눈으로 읽은 값 | 주황 |
| `assume` | 가정 | 계산에 넣은 가정(dtype 바이트, batch 등) | 주황 |
| `nd` | 미기술 | 원문이 밝히지 않은 것(예: SwiGLU의 정수 폭) | 회색 점선 |
| `interp` | 해석 | 발표자의 해석 | 파랑 |
| `hyp` | 저자 가설 | 저자가 가설로 든 설명(예: LLaMA v1 §3.6 MMLU 차이를 책 · 학술 논문 데이터 양으로 설명) | 파랑 |
| `illus` | 설명용 | 설명을 위해 고르거나 지어낸 예(예: d = 4,096일 때 10,922.7) | 점선 |
| `cite` | 인용 원전 | 그 논문이 인용한 원전의 값 · 문장 | 회색 테두리 |

- **표지는 그 종류가 해당하는 모든 장에 붙인다.** 덱의 첫 장에만 두고 뒤 장에서 빼지 않는다. 장을 따로 떼어 봐도 어느 값이 계산 · 추정인지 보여야 한다.
- **근거 범위마다 같은 종류는 한 번.** 근거 범위 = 같은 근거를 공유하는 값 묶음 하나(표의 열 하나, 요인 분해 카드 하나, 조건 줄 하나, 문단 하나)다. 범위의 첫머리(열 머리 `<th>`, 조건 줄 첫머리, 해당 값 옆)에 한 번 붙인다. 한 장에 범위가 둘이면(예: 원문 표 값 열과 발표자 계산 열) 같은 라벨이 두 번 나올 수 있고, 3번 이상이면 lint 경고(L-CHIP-REPEAT)다.
- **한 번만 쓰는 것은 풀이다.** '왜 추정인가 · 무엇을 가정했나'는 그 근거가 처음 나오는 장의 패널이나 대본에 한 번 쓰고, 이후 장은 표지만 둔다. 같은 경고 문단을 여러 장에 되풀이하지 않는다. 다만 따로 떼어 보면 오해될 장에서는 조건을 다시 적는다.
- **패널에도 표지를 둔다.** 패널의 `p.subst` · 원문 인용 · 가정 풀이 옆에 그 종류의 표지(`계산` · `추정` · `미기술` · `해석` …)를 붙인다. 화면 표지를 패널로 옮기는 것이 아니라 양쪽에 둔다.
- **결론을 바꾸는 추정 · 불일치만 크게.** 추정이 결론을 바꾸면 조건 줄(`.cond`), 본문 주장과 표가 다르면 판정 띠(`.verdict`)로 보인다. 나머지는 작은 표지로 충분하다.
- **제목에는 표지를 넣지 않는다.** 제목 수치가 계산 · 추정이면 조건 줄 첫머리에 표지를 둔다.
- **추정은 파생 수치까지 따라간다.** 추정값에서 계산한 값에도 추정을 표시한다. 원문 정의에서 바로 나오는 값(예: head 차원 128 = 8,192 ÷ 64)은 약하게 표기하거나 표지를 생략할 수 있다.
- **같은 화면의 논문 값과 발표자 계산값은 반드시 구분한다.** 한 표에 섞이면 열(또는 행) 단위로 범위를 나누고, 발표자 계산 열의 머리에 `계산` 표지를 둔다(셀마다 붙이지 않는다). 마크업은 [shell-components.md](shell-components.md) '근거 표지'.
- 원장의 `kind`가 표지 필요 종류(`orig` · `table` 밖)인데 화면이나 패널에 라벨이 없으면 lint가 알린다(L-CHIP-MISSING). `verdict` claim은 표지 대신 장에 `.verdict` 요소를 둔다.
- 밀도를 줄일 때 표지는 줄이지 않는다. 장당 양을 만드는 것은 본문 문단과 설명 상자다. 사전 등록한 '표시 수' 기준이 있으면 초안 빌드로 미리 재서 여유를 확인한다.

## 제목

- 형식: **범위 용어 + 콜론(또는 '…는'으로 시작하는 주제 표시) + 한 줄 주장**. 수치 결론도 된다.
- 좋은 예: `RMSNorm: LayerNorm에서 평균을 빼는 단계를 없앴다`, `SwiGLU: 행렬이 3개라 폭을 (2/3)·4d로 줄여 FFN 크기를 맞췄다`, `KV cache: 토큰당 2,560 → 320 KiB, KV head 64 → 8이 전부다`.
- 나쁜 예: `Table 3 전체`, `LLaMA 평가 결과`, `정규화 비교`처럼 서술어 없이 이름표로 된 제목(라벨형). lint는 3어절 이하 제목과 '전체 · 개요 · 결과 · 정리 · 요약 · 소개 · 목록 · 비교'로 끝나는 이름표 제목을 알린다(L-TITLE-LABEL).
- 기제 장은 '무엇이 어떻게 동작하나'를 쓴다. 근거 상태(본문과 표가 다르다, 원문 미기술)를 말하는 제목은 근거 · 판정 장에만 쓴다.
- 장 JSON에 그 장의 핵심 용어 `term`을 둔다. 값은 배정 블록 항목 이름에서 고르고, 제목 첫 콜론 앞이나 첫 12자 안에 그 용어가 있어야 한다(L-TITLE-TERM).
- 줄바꿈은 `<br>` 대신 `<wbr>`이나 자연 줄바꿈을 쓴다(L-TITLE-BR). 데스크톱(1440)에서 2줄 이하(C-TITLE-LINES). 제목에는 수식 구분자를 쓰지 않는다(L-TITLE-MATH).

## 비교 짝과 첫 등장 정의

- 비교 대상이 있으면 표지나 질문 목차에 **비교 짝 줄**을 둔다: `<p class="pair-line"><b>비교 짝</b> LLaMA-65B ↔ Llama 2-70B · 가중치 계승 아님</p>`. 덱 JSON `compare_pair`에 같은 글을 적으면 lint가 들어가며 장에 있는지 본다(L-PAIR).
- 범위 밖 모델이 처음 나오면 정체와 관계를 한 줄로 적는다(예: Minerva = PaLM을 arXiv · 수학 웹 문서 38.5B 토큰으로 더 학습한 모델, LLaMA v1 Table 7의 비교 대상 · LLaMA v1 §3.4 (p.5)).
- 비교 기준이 바뀌는 장에는 '여기서부터 비교 대상 = X'를 적는다.
- 경계 경고(가중치 계승 아님, 조건 다름 등)는 한 곳에서만 풀어 쓰고, 이후는 표지 · 링크로 잇는다.
- 약어 · 모델 이름 · 기호는 처음 쓰는 장에서 `<dfn>`으로 정의한다. lint는 대문자 2개 이상인 영문 토큰이 본편에서 처음 나온 장까지 정의되지 않으면 알린다(L-DEFINE-FIRST). 정의로 인정하는 것은 `<dfn>` 글, 제목이 '`term`: …' 꼴인 장의 `term`, 덱 `known_terms`다. 정의된 용어 안에 낱말로 들어 있는 토큰(예: `KV cache`의 `KV`)은 정의된 것으로 본다.
- 원전 표기를 쓰면 덱 표기와의 대응을 같은 장에 적는다(예: Shazeer 2020 SwiGLU 식의 W · V · W₂ = gate · up · down).
- 배정 범위 용어는 덱 `scope_terms`에, 범위 밖 용어는 `out_of_scope_terms`에 적어 lint로 확인한다(L-SCOPE-MISSING · L-SCOPE-DEF · L-SCOPE-OUT).

## 같은 조건 비교와 계산 상자

- 두 대상이 비교 조건(총 · 활성 파라미터, hidden 크기, 학습 토큰, shot 등)을 함께 갖지 않으면 '같아도' 문장을 쓰지 않는다. 조건을 고정한 설명용 대안을 만들거나 '조건 다름'을 표시한다.
- 비율을 쓸 때는 분모를 화면에 적는다(예: 65B 대비 ÷ 8).
- 식에서 나온 숫자는 **식 → 대입 → 단위 → 비율 분해** 순서로 보인다. 화면에는 요인 분해 카드(`.factor`, 카드 안에 일반식 한 줄)와 조건 줄, 근거 패널에는 기호 풀이 · KaTeX 식 · 대입 줄(`p.subst`)을 둔다. 일반식을 패널에만 두지 않는다. 화면에 `.factor`나 `계산` 표지가 있는데 화면 · 패널에 `.subst` · `.derive`가 없고 대본에도 '='가 없으면 lint가 알린다(L-CALC-SUBST).
- **요인 분해**: 정량 결과가 여러 구조 요인의 곱 · 합이면 최종 수치만 비교하지 말고 기여 요인을 나눠 주 시각에 둔다. 변하지 않은 항목은 작은 '동일' 표지(`fx-same`)로 남긴다. 분해 수치는 실제 config · 식과 일치해야 하고, 원장 `factors`에 적으면 lint가 곱을 다시 계산한다(L-CLAIM-FACTOR).
  - 예: LLaMA-65B → Llama 2-70B 토큰당 KV cache 2,560 → 320 KiB = KV head 64 → 8(÷ 8) × 층 80 → 80(동일) × head 차원 128 → 128(동일). 대입 2 × 80 × 64 × 128 × 2 B = 2,621,440 B와 2 × 80 × 8 × 128 × 2 B = 327,680 B는 패널에.
- 순서 · 정규화 차이를 다루는 장에는 '같은 입력 · 두 방식' 열을 둔다(예: 같은 x로 post-norm과 pre-norm, 같은 [2, 4, 6]으로 LayerNorm과 RMSNorm).

## 표의 줄과 숫자

- **표의 모든 줄은 같은 열을 채울 수 있는 비교 대상이어야 한다.** 핵심 열(점수)이 '—'인 줄은 넣지 않는다. 예: 데이터 풀은 학습 결과가 없으니 줄이 아니라 캡션으로 적고, 비교는 같은 크기 · 같은 조건의 기준선(무작위 표본 등)으로 한다.
- 점수 · 승률은 **무엇 대비인지**(예: text-davinci-003 대비 승률), 차이가 %인지 %p인지 원문 표 캡션에서 확인한다.
- 같은 열은 같은 단위로 적는다(한 줄은 개수, 한 줄은 비율로 섞지 않는다). 개수 · 규칙 수처럼 다른 것을 센 숫자는 같은 모양으로 나란히 두지 않는다.
- 모델 크기 등은 모든 줄에서 같은 순서(작은 것 → 큰 것)로 적는다.

## 구현과 검토

HTML은 `.slide[data-sec][data-nav]` 안에 `.card > .inner`와 `.src`를 둔다(v1 · v2 공통 계약). 기본은 본문/시각자료 분할이며 `.inner.wide`는 넓은 도식에 쓴다. 레이아웃 종류별 CSS를 추가할 수 있다. 각 슬라이드의 `data-section-label`을 같은 구간에서 일관되게 설정한다. v2 마크업(장 ID · 출처 줄 · 근거 패널 · 대본)은 [deck-json.md](deck-json.md), 화면 부품은 [shell-components.md](shell-components.md)에 있다.

브라우저 확대만으로 가독성을 맞추지 않는다. 좁은 패널에서는 읽기 모드를 선택할 수 있고, 모바일에서는 문장과 그림이 세로로 이어져야 한다. 넓은 표는 그 영역 안에서 스크롤하게 만들고 안내를 표시한다. 세로 터치 스크롤과 표 가로 스크롤이 슬라이드 전환으로 처리되지 않도록 한다.

`check_deck.cjs`는 화면·이동·로컬 링크 존재를 검사하고 렌더를 남긴다. v2 덱에서는 밀도 · 배율 · 대본 접근 · 근거 패널 · 확대 · 본편 끝 · 수식 · 상호참조도 잰다. 데스크톱 · 태블릿 · 휴대폰에서 실패가 0건이 될 때까지 고친다. 외부 링크의 HTTP 상태나 논문의 정확성, 사람이 실제로 이해했는지를 증명하는 도구는 아니다. 보고서에 자동 검사 범위와 실제 사람이/AI가 본 범위를 분리해 쓴다.

## 지킬 것

밀도를 줄여도 이 목록은 없애지 않는다. 줄이는 방법은 층 옮기기(화면 → 패널 · 대본 · 부록)와 '풀이는 한 번, 표지는 장마다'다.

1. **보이는 출처 줄**: 모든 장의 화면에 쪽 번호가 있는 출처 식별자 1–2개(`.src-line`, HTML판만 읽었으면 '쪽 미확인'), 나머지 출처는 패널 '출처 전체'.
2. **대본**: 본편 모든 장에 대본이 있다(`--script` 병합, 빈 장은 빌드 오류).
3. **근거 종류 표지**: 표 값 · 계산 · 추정 · 미기술 · 해석 등을 위 '근거 표지 위계'대로, 해당하는 모든 장과 패널에. 추정은 제목 수치와 파생 수치까지 따라가고, 원문 정의에서 바로 나오는 값은 약하게.
4. **본문 주장 판정**: 원문 주장 → 비교 칸 → 차이값 → 판정. 판정 띠 줄의 `vd-claim`(저자 주장) · `vd-res`(비교 칸 값 · 차이값 · 판정)로 한 줄에 남긴다([screen-budget.md](screen-budget.md) 7절). 화면 수치는 원문을 다시 열어 확인.
5. **유지 · 변경 · 미기술 정리**: 정리 장의 유지 · 바꿈 · 미기술 표(구성요소 | 이전 | 이 논문 | 유지/바꿈/미기술 | 원문 이유, 줄마다 해당 장 링크). 이유가 없으면 `미기술` 표지. 마크업은 [shell-components.md](shell-components.md).
6. **같은 입력 · 두 방식, 조건 맞춤**: 'A와 B는 다르다' 장은 같은 입력으로 양쪽을 나란히.
7. **원전 수치 + 실험 조건 + '이 논문 수치 아님'**: 외부 근거는 인용 여부와 설정까지, 자리는 근거 패널. 그 논문이 인용하지 않은 원전은 따로 표시.
8. **비교 짝과 가중치 계승 구분**: 비교 짝 줄, 비교 기준이 바뀌는 장의 표시.
9. **질문 뼈대**: 질문 목차(RQ) → 관찰 → 열린 질문 · 토론. 정리 장에서 RQ에 답하고, 본편 끝 '열린 질문 · 토론' 장에 RQ별 관찰과 남은 질문을 둔다. 결과 장 대본에는 토론 질문 하나.
10. **같은 축 · 0 기준 · 기준선 · 확대 표기 차트**: '수치와 도식의 근거 계약' 그대로.
11. **원문 그림 · 표와 캡션 규율**: 주장이 원문 Figure · Table에 기대는 장에는 원본이 화면에(주 시각이나 썸네일), 전체 크기 crop은 패널에. crop · 재구성 표 캡션은 원문 · 쪽 · 포함 · 생략 · 발표자 표시.
12. **재빌드 재현성**: 같은 JSON · 원장 · 대본이면 바이트까지 같은 HTML.
13. **이유를 담은 원문 문장**: 화면에 한 문장(풀어 쓴 말 + 출처 식별자)과 패널의 원문 인용을 함께 둔다(대본에만 두지 않는다). "왜"는 두 단계 아래까지 준비한다.
