# 화면 예산 · 층 나누기

목표: **발표 화면은 가볍게 읽히고, 근거를 펼치면 검증되는 덱.** 근거를 지우지 않고 화면에 동시에 보이는 양을 제한한다. 밀도 · 높이 · 시간 · 장 수의 숫자는 이 문서에만 둔다(SKILL.md에는 숫자가 없다). 아래 숫자는 초기 설계 목표이며 실제 덱과 리허설로 보정한다. 측정 정의와 코드는 [deck-json.md](deck-json.md)의 'lint 코드' · '검사 코드'.

## 1. 네 층과 정보의 자리

| 층 | 무엇 | 덱 JSON 자리 |
| --- | --- | --- |
| 화면 | 결론(제목) 1 · 주 시각 1 · 결론을 바꾸는 조건 0–1 · 짧은 출처 줄(식별자 1–2) · 근거가 된 원문 그림 · 표(주 시각이나 썸네일) | `title` · `body` · `visual` · `sources[0..src_visible)` |
| 대본 | 설명 순서: 이전 장 연결 · 도입 질문 · 식 해설 · 예시 · 예상 질문과 답 · 토론 질문 | `script.md` → `--script` → `note` |
| 근거 패널 | 원문 인용 · 전체 크기 crop · 대입 계산 · 단위 환산 · 가정 풀이 · 출처 전체 | `evidence` + 자동 '출처 전체' |
| 부록 | 증명 · 다른 크기/조건 재계산 · 원문 표 전체 · 세부 설정 · 배정 밖 배경 | `part: "appendix"` 장(ID `A-n`) |

| 정보 | 자리 |
| --- | --- |
| 결론 · 핵심 기제 · 결론을 바꾸는 조건 | 화면 |
| 배정 항목 계산의 일반식 | 화면: KaTeX 디스플레이 식 한 줄(요인 분해 카드 안 `data-math` 자리표시 + 휴대폰용 `tex_narrow`) 또는 `.factor`의 요인 이름 |
| running example의 실제 값 사슬 | 화면: 값이 적힌 단계 카드 |
| 설계 선택의 원문 이유 | 화면: 한 문장(풀어 쓴 말 + 출처 식별자). 원문 그대로의 인용은 패널 |
| 근거가 된 원문 Figure · Table | 화면: 주 시각, 또는 HTML 재구성 옆 썸네일(AU 0). 전체 크기 crop은 패널 |
| 반복 설명 · 설명 순서 · 예시 말하기 · 이전 장 연결 · 예상 질문 · 토론 질문 | 대본 |
| 식에 숫자를 넣은 대입(`p.subst`) · 단계 안의 대수 전개 · 단위 환산 · 가정 풀이 · 보조 수치 | 근거 패널 |
| 원문 인용 · 참고 문헌 목록 | 근거 패널(인용 · '출처 전체') |
| 증명 · 다른 크기 · 다른 문맥 길이 재계산 · 원문 표 전체 · 세부 설정 · 배정 밖 배경 | 부록 |
| 다음 주 예고 | 질문 목차 장 한 곳(본편 장에는 부록 링크만) |

주장이 성립하는 데 필수인 정보는 부록에만 두지 않는다. 결론을 바꾸는 조건은 대본이나 패널에만 숨기지 않는다. 배정 항목의 기제와 유도가 본편 · 패널 · 부록 중 어디로 가는지는 6절의 판정표를 따른다.

## 2. 장 하나의 구조

- **결론 1 + 주 시각 1 + 조건 0–1.** 조건이 없으면 조건 줄을 만들지 않고, 빈자리를 다른 설명으로 채우지 않는다.
- **역할 분리.** 제목 = 무엇이 달라졌나 · 주 시각 = 왜 · 어떻게 · 조건 줄 = 언제 성립하나 · 대본 = 어떻게 설명하나. 제목 · 본문 · 그림 · 캡션이 같은 정보를 반복하지 않는다(L-REPEAT-TEXT, L-NOTES-COPY).
- **인과 사슬 하나.** 예: GQA 구조 변경 → KV head 감소 → KV cache 감소. 다른 메시지(다른 문맥 길이로의 환산, 다음 주 예고)는 다른 장 · 부록 · 대본으로 보낸다. 한 장에 독립 주장이 둘이면 먼저 나눈다.
- **주 시각은 고르는 것이다.** 크기를 키우는 것이 아니라 핵심 주장 · 기제를 가장 직접 설명하는 시각을 고르고 `data-main`을 붙인다.
- **조건 줄 · 비교 짝 줄의 자리.** 어디에 두든 AU는 0이다. 다만 `body`(`.txt`) 안에 두면 그 줄의 문장이 본문 문장 수(L-SENTENCES · C-SENTENCES)에 들어가고, `visual` 바로 아래(`.vis > p.cond`)에 두면 들어가지 않는다. 그래서 `visual`에 두는 것이 기본이다.

## 3. 밀도 예산

| 항목 | 목표 | 경고 | 코드 |
| --- | --- | --- | --- |
| 화면 글(공백 제외. 제목 · 캡션 · 표 · SVG · 수식 표시 포함, 머리 라벨 · 출처 줄 · 패널 · 대본 제외) | 본편 중앙값 ≤ 350 | 장 > 550, 본편 p90 > 550 | C-VISIBLE · C-VISIBLE-MEDIAN · C-VISIBLE-P90 (정적 추정 L-DENSITY-VISIBLE) |
| 산문(화면 글에서 제목 · 표 · SVG · 수식 · 근거 표지 · 숫자 묶음 · 캡션 · 범례 · 판정 띠 제외) | 본편 중앙값 ≤ 120 | 장 > 200, 본편 p90 > 200 | C-PROSE · C-PROSE-MEDIAN · C-PROSE-P90 (L-DENSITY-PROSE) |
| 본문 설명 문장 | 0–2 | > 3 | C-SENTENCES · L-SENTENCES |
| 주의 단위(AU) | 2–3, 복잡한 기제 장 4 | > 4 | C-AU |
| 주 시각 면적(`[data-main]` 넓이 ÷ 콘텐츠 영역 = `.inner`의 padding 안쪽 넓이) | ≥ 45% | < 35% (result · mechanism 장) | C-MAINVIS |
| 결론을 바꾸는 조건 | 0–1 | ≥ 2 | C-COND · L-COND-MANY |
| 화면 출처 식별자 | 1–2 | > 2 | C-SRC-IDS (`src_visible`) |
| 제목 줄 수(1440) | ≤ 2 | ≥ 3 | C-TITLE-LINES |
| 같은 근거 표지 | 근거 범위마다 종류별 1번(한 장에 범위가 둘이면 2번까지) | 3번 이상 | L-CHIP-REPEAT |
| 반복 글 | — | 20자 이상 같은 조각이 본편 3장 이상 | L-REPEAT-TEXT |
| 대본 복사 | — | 화면 8글자 조각 중 대본에도 있는 비율 > 0.6 | L-NOTES-COPY |

- 렌더 값(check)이 권위이고, lint는 JSON만 보고 추정한다. 수식 · 표 · 그림 라벨과 산문은 따로 잰다.
- **산문과 화면 글**: 산문은 본문 문단 · 조건 줄 · 상자 안 설명처럼 읽어야 하는 글이다. 캡션(`.cap` · `figcaption`) · 범례(`.claim-legend`) · 판정 띠(`.verdict`)는 산문에서 빼지만 화면 글에는 든다. 그래서 범례는 실제로 쓴 상태만 적고(7절), 캡션은 원문 · 쪽 · 포함 · 생략 · 발표자 표시를 짧게 적는다.
- **주 시각 면적**: 콘텐츠 영역에 제목 · 본문 칸이 들어 있으므로 상한은 split 배치가 약 0.60, wide 배치가 약 0.70이다. 목표 0.45는 두 배치 모두에서 닿는다. 원문 썸네일은 주 시각에 넣지 않는다.

### 높이 예산 (1440×900)

밀도 예산을 모두 지켜도 세로로 넘칠 수 있다. 글자 수보다 높이가 먼저 막히는 부품은 아래 값으로 미리 더해 본다(v2 셸, 1440×900 측정값).

- **`visual` 칸 높이**(`layout: "wide"`): 제목 1줄 · 본문 1줄이면 약 410px, 제목 2줄 · 본문 2줄이면 약 335px. 제목 한 줄은 약 44px, 본문 한 줄은 약 33px를 쓴다.
- **부품 높이**: 표 머리 행 48 · 본문 행 54 · 범례 20 · 판정 띠 한 줄 46 · 캡션 한 줄 22 · 조건 줄 36 · 원문 썸네일(높이 60에 맞춘 것) 약 60. `visual` 안 부품 사이마다 14를 더한다.
  - 예: 주장 주석 표(머리 + 2행 + 범례 + 판정 1줄) 275 + 캡션 22 + 썸네일 60 + 간격 28 = 385 → 제목 1줄 · 본문 1줄(410)에는 들어가고, 제목 2줄 · 본문 2줄(335)에는 넘친다.
- **표**: 화면 표는 본문 행 5개 이하(머리 포함 약 318px)다. 범례 · 판정 띠 · 캡션 · 썸네일이 붙으면 그만큼 행을 줄인다(보통 3행 이하). 행이 넘치면 비교 짝을 한 행으로 합치거나(예: 크기마다 'LLaMA 1 → Llama 2' 한 행) 원문 표 전체를 부록으로 보낸다.
- **넓은 SVG**: wide 장의 SVG는 viewBox 높이 ÷ 폭 ≤ 0.28(폭 1,170px에서 약 330px)로 그린다. 더 높으면 split 배치로 바꾸거나 장을 나눈다.
- 넘치면 check가 `{폭}: slide N overflow or missing source`로 실패를 낸다. 넘침인지 출처 줄 문제인지는 `checks.json`의 `views[].slides[]`에 있는 `innerOverflow` · `cardOverflow` · `hasSource`로 가린다(출처 줄 문제는 C-SRC-HIDDEN으로도 따로 나온다).

## 4. 주의 단위(AU) 세는 법

단위 선택자 `table, svg, img, canvas, [role="img"], .math-block, .bx, .annotation, .derive, .factor, .claim-table, .ba, .profile, .summary-cols, figure, .flow, .compare-panel, .diagram-panel, [data-au]` 중 보이고, `.inner`까지 올라가는 동안 단위 선택자 조상이 없는 요소(뿌리)마다 1(`data-au`면 그 값)을 센다. 뿌리에서 `.cond, .ev-chip, .tag, .cap, figcaption, .scroll-hint`와 그 안은 뺀다. 여기에 `.txt`에 보이는 `p/ul/ol/blockquote`(`.cond` · `.pair-line` 제외)가 있으면 +1, `.vis > p:not(.cap):not(.cond):not(.pair-line)`가 있으면 +1.

| 화면 | AU |
| --- | --- |
| `.g.c2` 안 `.bx` 상자 4개 | 4 (`.g`는 단위가 아니라 상자가 하나씩 뿌리) |
| `data-au="1"` 묶음 안 프로필 카드 2장 | 1 (안쪽은 세지 않음) |
| 요인 분해 카드 `.factor`(막대 + 요인 목록 + 카드 안 일반식 + 합) | 1 |
| 전후 비교 쌍 `.ba` 안 SVG 2개 | 1 |
| 주장 주석 표 `.claim-table`(표 + 범례 + 판정 띠 줄들) | 1 |
| 유지 · 바꿈 · 미기술 표(`table.tbl`) | 1 |
| 원문 썸네일 `figure.crop.crop-thumb[data-au="0"]` | 0 |
| 제목 · 조건 줄 · 비교 짝 줄 · 근거 표지 · 캡션 · 출처 줄 · 축 라벨 | 0 |
| 예: 본문 정의 1문장 + `.factor` + 원문 썸네일 + `.cond` | 1 + 1 + 0 + 0 = 2 |

## 5. 시간 · 장 수

| `kind` | 장 종류 | 기본 초(`seconds` 없을 때) | 범위 |
| --- | --- | --- | --- |
| `intro` | 표지 · 질문 목차 · running example | 30 | 20–40 |
| `result` | 결과 · 비교 · 평가 개요 | 50 | 40–60 |
| `mechanism` | 기제 · 유도 | 80 | 60–100 |
| `summary` | 요약 · 전환 | 20 | 15–30 |
| `summary` + `seconds` | 열린 질문 · 토론 | `seconds` 직접 지정 | 30–60 |

발표 시간 B분(`budget_minutes`)일 때:

- 본편 장 수 목표 round(0.8B)–floor(1.05B), 상한 floor(1.2B) (L-BUDGET-SLIDES · C-BUDGET-SLIDES). 25분 → 20–26 · 상한 30, 7분 → 6–7 · 상한 8.
- 들어가며(`kind: "intro"` 본편 장) ≤ 3 (L-BUDGET-INTRO · C-BUDGET-INTRO). 메타 장(배정 · 자료 규칙 설명)은 만들지 않고 읽기 지도나 검토 기록에 둔다.
- 본편 `seconds` 합 ≤ B × 60 (L-BUDGET-TIME · C-BUDGET-TIME).
- 본편 대본(공백 제외) ≤ 300자/분 × B (L-NOTES-MINUTES · C-NOTES-MINUTES). 25분이면 7,500자. 장 하나는 대략 `seconds` × 5자이고, 그 1.5배를 넘으면 알린다(L-NOTES-LONG). 예: 80초 기제 장 ≈ 400자, 600자 초과 알림.
- **열린 질문 · 토론 장**: 본편 끝(정리 장 뒤)에 하나 둔다. 질문 목차의 RQ마다 관찰 한 줄과 아직 답하지 못한 질문을 나란히 두고(예: `.summary-cols`의 '관찰' · '열린 질문' 두 열), 질문을 내놓는 시간(30–60초)만 예산에 넣는다. 토론 자체는 발표 시간 밖이다. 결과 장 대본에는 토론 질문 하나를 넣는다.

25분 배분 예:

| 묶음 | 장 | 시간 |
| --- | --- | --- |
| 들어가며(표지 · 질문 목차 · running example) | 3 | 3 × 30 = 90초 |
| 범위 주제의 기제 장 | 11 | 11 × 80 = 880초 |
| 범위 주제의 비교 · 수량 장 | 6 | 6 × 50 = 300초 |
| 평가 개요 장(평가 Table마다 1) | 3 | 3 × 50 = 150초 |
| 정리(유지 · 바꿈 · 미기술 표) | 1 | 20초 |
| 열린 질문 · 토론 | 1 | 45초 |
| 합 | 25 (목표 20–26) | 1,485초 = 24분 45초 ≤ 25분 |

배정 항목마다 '기제 장 1 + 비교 · 수량 장 1'이 기본이다. 합이 상한을 넘을 때 줄이는 순서는 6절. 장별 시간은 리허설로 다시 맞춘다.

**한 사람 파트만 담은 덱**: `budget_minutes`는 그 파트의 발표 시간이다. 표지 · 질문 목차는 선택이다. 비교 짝 줄을 둔다면 파트 첫 장에 두고, 그 장이 `kind: "intro"`가 아니면 덱의 `compare_pair`는 비워 둔다(L-PAIR는 intro 장만 본다). 첫 등장 정의(예: GQA · KV head)는 이 덱 안에서 처음 나오는 장에 둔다. 앞 파트에서 정의했어도 다시 정의한다.

## 6. 기제 · 유도는 본편에

배정 블록에 이름이 오른 항목의 기제 · 유도는 본편에 둔다. 형태는 유도 카드(`.derive`, 4단계 이하 + `.dv-end`)나 '정의 그림 → 우리 모델 적용 → 수치 → 원전 근거' 묶음이다.

**판정표** — 단계 하나하나를 이렇게 나눈다.

| 그 단계가 … | 자리 |
| --- | --- |
| 배정 항목의 왜 · 어떻게 질문에 답하는 데 필요하다 | 본편 화면. 4단계를 넘으면 장을 나눈다(L-DERIVE-STEPS) |
| 한 단계 안의 대수 전개, 식에 실제 숫자를 넣은 대입 | 근거 패널(`p.subst` · 펼친 식) |
| 증명, 다른 크기 · 다른 조건의 재계산, 원전 표 전체, 배정 블록에 이름이 없는 배경 개념 · 대안 비교 | 부록 Background |

- 단계마다 식(`.dv-eq`, KaTeX)과 한 줄 이유(`.dv-why`, 한국어는 TeX 밖)를 둔다.
- 마지막 줄 `.dv-end`에 원래 질문의 답을 쓴다. 예: "답: 행렬이 하나 늘어도 폭을 2/3로 줄이면 FFN 크기는 그대로다."
- 단순하면 한 장으로 끝낸다. 단계 수를 맞추려고 논리를 생략하지 않는다.

**장 수 상한을 넘을 때 줄이는 순서**

1. 그 항목의 수량 장을 기제 장의 끝(같은 인과 사슬의 마지막 단계, `.dv-end`나 요인 분해 한 줄)으로 접거나, 수량의 세부를 근거 패널로 옮긴다. 접어서 단계가 4개를 넘으면 접지 말고 2로 간다.
2. 배정 밖 내용을 합치거나 부록으로 뺀다.
3. 배정 항목의 기제를 부록에만 두는 것은 하지 않는다.

부록 첫 장에는 주제 · 원문이 한 말 · 부록에서 볼 것 · 다음 주 담당 파트를 표로 두고 주제별 로드맵을 그 뒤에 몰아 둔다. '다음 주 깊게 다시 다룰 내용' 표시는 질문 목차 장 한 곳에 모으고, 본편 장에는 해당 부록 장 링크(`[[A-1]]`)만 둔다.

## 7. 평가 개요 장

평가 절은 Table마다, 그 Table을 다루는 장 묶음의 첫 장을 개요 장으로 둔다.

- **구성**: 주장형 제목 + 주장 주석 표(`.claim-table`: HTML로 다시 그린 표 + 범례 `.claim-legend` + 판정 띠 `.verdict` 줄들) + 캡션 + 원문 썸네일. 본문(`body`)에는 비교 기준 한 문장 정도만 두고, 저자 주장은 `body`가 아니라 판정 띠 줄로 옮긴다.
- **판정 띠 줄**: 저자 주장 하나에 `.verdict` 하나(`vd-claim` + `vd-res`), 3줄 이하. `vd-claim`은 '저자:' 주어로 옮기고 예외를 같은 줄에 적는다. `vd-res`에는 비교한 칸의 값과 **차이값**을 적는다(예: `표: BoolQ도 앞섬 · +1.6 (85.3 − 83.7)`). 판정은 `vd-ok`(일치) · `vd-part`(부분 · 예외) · `vd-no`(불일치). 이렇게 '원문 주장 → 비교 칸 → 차이값 → 판정'이 한 줄에 남는다.
- **판정 띠를 두는 경우**: 화면에 그 표에 대한 저자 주장이 있으면 판정 결과와 상관없이 늘 둔다(`vd-ok` 포함). 원문이 그 표에 대해 주장하지 않으면 띠 대신 캡션에 '본문 주장 없음'을 적고, 주장 상태 칸(`cl-*`)도 쓰지 않는다(발표자 강조는 `.em`). `cl-x` 셀이 있으면 판정 띠는 반드시 있다(C-VERDICT). 주장 없이 장식으로 띠를 붙이지 않는다.
- **범례**: 실제로 칠한 상태만 적고, 원문 굵게 줄은 늘 적는다('굵게 = 원문 굵게' 또는 '원문 굵게는 옮기지 않음'). 상태: `cl-hi` 본문이 강조한 우위 · `cl-vs` 본문의 비교 대상 · `cl-par` '비슷하다'고 쓴 곳 · `cl-x` 본문 주장과 표 불일치. 발표자 강조 `.em`을 쓰면 '파랑 칸 = 발표자 강조'를 더한다. 칠한 칸은 발표자 표시이고 원문 강조가 아니다.
- **평가표가 아닌 표**: 설정 · 사양 표라도 저자가 그 표의 수치에 대해 주장하면 같은 부품과 판정 띠를 쓴다. 예: Llama 2 Table 1 — 저자 "40% more total tokens" / 표: 1.4T → 2.0T는 +43%, 1.0T → 2.0T는 +100%(`vd-part`).
- 상세 검산은 검산 결과가 그 장의 결론을 바꿀 때만 본편, 나머지는 부록.
- 예: LLaMA v1 Table 3 — `vd-claim` 저자: "BoolQ를 뺀 모든 항목에서 Chinchilla-70B를 앞선다" / `vd-res` 표: BoolQ도 85.3 > 83.7 (+1.6) · 5개 중 5개 앞섬(`vd-no`).

## 8. 요인 분해

- 정량 결과가 구조 요인의 곱 · 합이면 요인 분해 카드(`.factor`)를 주 시각으로 둔다. 막대는 0 기준 같은 축, 변한 요인 `fx-chg`, 변하지 않은 요인은 작고 흐린 '동일' 표지 `fx-same`.
- 일반식은 화면(카드 안 `<span data-math="…"></span>`, 장 `math` 필드에 `tex_narrow` 포함)에, 기호 풀이와 대입은 패널의 `p.subst`에 둔다. 긴 식을 인라인 `\( … \)`로 캡션에 넣으면 휴대폰에서 잘린다. 조건(dtype · K+V · 층 합산 · batch)은 조건 줄 한 줄.
- 원장 claim에 `factors`(요인별 from · to)와 `ratio_of`를 적어 lint가 다시 계산하게 한다(L-CLAIM-FACTOR). 분해 수치는 실제 config · 식과 일치해야 한다.
- **방향**: 원장 `value` = Π(from ÷ to) = **이전 ÷ 새것**(줄어든 배수)이다. 화면은 새것 기준 배율로 써도 된다(이전 대비 2배 · 1/5). 두 방향을 섞지 말고, 요인이 서로 반대로 움직이면 둘 다 적는다.
  - 예: Llama 2-13B → 70B 토큰당 KV cache 800 → 320 KiB. 층 40 → 80(2배), KV head 40 → 8(1/5), head 차원 128 → 128(동일) → 화면 2배 × 1/5 = 0.4배. 원장은 `ratio_of: ["kv-13b", "kv-70b"]` → `value` 2.5, `factors` (40 ÷ 80) × (40 ÷ 8) × (128 ÷ 128) = 0.5 × 5 × 1 = 2.5.
- **`.fx-r` 쓰는 법**: 넓은 화면에서 셸이 항 사이에 '×'를 그린다. 첫 항은 `÷ 8`처럼 써도 되지만, 둘째 항부터는 `÷` · `×`로 시작하지 않고 배율만 쓴다(`2배` · `1/5` · `동일`). 그렇지 않으면 '× ÷ 5'처럼 읽힌다.

## 9. 간결화 순서

1. **구조적 중복부터 없앤다.** 같은 정보를 말하는 문단 · 식 · 시각 · 캡션을 하나로 합친다.
2. **원장 층에 맞게 옮긴다.** 화면 → 근거 패널 · 대본 · 부록. 층은 원장 `layer`를 따르고, 배정 항목의 기제는 6절 판정표를 따른다.
3. **그다음에 문장을 다듬는다.**

근거 표지는 줄이지 않는다. 장당 양을 만드는 것은 근거 표지가 아니라 본문 문단과 설명 상자다(v1 측정: 본문 문단 중앙값 170자 · 시각 칸 기타 산문 65자 · 캡션 40자, 근거 칩은 전체 글의 약 0.5%). 간결화 뒤에는 [claim-ledger.md](claim-ledger.md)의 '근거 손실 확인'을 돌린다.

## 10. 재배치 예 — LLaMA-65B → Llama 2-70B KV cache

| 항목 | v1식 장 | v2 자리 |
| --- | --- | --- |
| 제목 | 'KV cache 비교'류 라벨 + 본문에 결론 문단 | 화면 제목 "KV cache: 토큰당 2,560 → 320 KiB, KV head 64 → 8이 전부다" |
| 결론을 보여 주는 그림 | 두 모델 막대만 | 화면 주 시각 = 요인 분해 카드(두 막대 + KV head ÷ 8 · 층 동일 · head 차원 동일) |
| 일반식 | 화면의 큰 산식 카드 | 화면: 요인 분해 카드 안 디스플레이 식 한 줄 `KV/token = 2 × L × n_kv × d_h × b`(휴대폰은 `tex_narrow`) |
| 기호 풀이 · 대입 | 화면 산식 카드 아래 | 근거 패널: 기호 풀이 한 줄 + `p.subst` 두 줄(2,621,440 B · 327,680 B) + `계산` 표지 |
| 계산 조건 | 본문 · 캡션 · 상자에 흩어진 경고 여러 개 | 화면 조건 줄 1개: "계산 · 공개 config 값 · fp16 2 B · K+V · 80층 합산" |
| 원문 Table 2 | 화면 한쪽 큰 crop | 이 값이 주장의 근거로 처음 쓰이는 장이면 화면 썸네일(AU 0) + 패널 전체 크기 crop. 앞 장에 이미 있으면 패널에서 그 장으로 링크 |
| config 값의 출처 풀이 | 화면 상자 | 근거 패널 `config` 표지 + 한 문장 |
| 문맥 길이별 환산(2,048 토큰 5 GiB · 640 MiB) | 같은 장의 두 번째 그림 | 부록 `A-n` 장(본편 장에서 `[[@kv-2048]]` 링크) |
| 설명 순서 · 예상 질문 | 화면 문단 | 대본 |
| 다음 주 예고 배지 | 장 머리 | 질문 목차 장 한 곳 |
| 출처 3개 | 화면에 모두 | 화면 출처 줄 1–2개 + 패널 '출처 전체' 3개 |

결과: 화면 AU 2(본문 정의 1문장 1 + 요인 분해 1 + 썸네일 0 + 조건 줄 0). 일반식 · 조건 · 원본은 화면에 남고, 대입 · 풀이 · 전체 출처는 패널로 옮겼다. 근거는 하나도 지우지 않았다.

## 11. 평가 관점과 5–10초 점검

세 관점을 따로 본다. 한쪽 점수로 다른 쪽을 대신하지 않는다.

| 관점 | 무엇을 보나 | 어떻게 |
| --- | --- | --- |
| 근거 보존(Evidence Retention) | 주장별 출처 연결 · 계산 재현 · 조건 유지 | `--lint` coverage, 기준선과 비교 |
| 읽기 쉬움(Presentation Readability) | 5–10초 보고 결론을 말할 수 있나 | 아래 점검(패널 닫힌 화면) |
| 발표자 편의(Speaker Usability) | 대본 · 시간 · 패널 · 전체화면 · 키보드 · 확대 | 리허설, check의 대본 접근 · 배율 · 패널 결과 |

- **5–10초 점검**: 패널을 닫은 화면을 5–10초만 보고 화면을 가린 뒤, 결론 한 문장과 그 결론이 성립하는 조건을 말해 본다. 못 하면 글을 더하지 말고 제목(결론)이나 주 시각을 고친다. 다른 사람이나 AI 검토자에게 같은 방식으로 물어도 된다. 자동 검사와 AI 검토는 사람 승인을 대신하지 않는다.
