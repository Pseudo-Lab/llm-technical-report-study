필터링 후, 도메인별 비중을 조정한다

Remixing은 새 문서를 생성하는 것이 아니라, 과소대표된 도메인이 학습 데이터에서 더 많이 나타나도록 구성하는 단계입니다.

→ 리믹싱
조정 후 가상 예시
일반 웹 60%전문 도메인 40%
적게 포함된 분야의 비중 강화
기존 편중 문제많이 수집된 웹 도메인이 학습에서 과대표현될 수 있음

RQ4 / BPB · DEEPSEEK-V2 §3.2.1

왜 토큰당 손실 대신 BPB를 볼까?

Tokenizer는 텍스트를 나누고, 각 Tokenizer를 사용하는 LLM은 토큰을 예측해 손실을 계산한다.
동일한 평가 텍스트: DeepSeek (ASCII · 8 Byte)

Tokenizer A → LLM A

DeepSeek
Tokenizer A · 2 tokensLLM A · 예측 손실 4 bits

Tokenizer B → LLM B

DeepSeek
Tokenizer B · 4 tokensLLM B · 예측 손실 6 bits
BPB = LLM의 전체 예측 손실 (bit) ÷ 원본 텍스트 크기 (Byte)
토큰당 평균 손실A: 2.0 · B: 1.5 bits/token→ B가 더 좋아 보임
BPB · 동일한 8 Byte 기준A: 0.50 · B: 0.75→ A의 예측 손실이 더 낮음
Tokenizer는 분할만 수행하고, 예측 손실은 각 언어 모델이 계산합니다. 모든 토큰 분할과 수치는 설명용 가상 예시입니다.
