§3–§3.2는 사람 선호를
모델 개선으로 바꾸는 과정입니다

Llama 2-Chat의 후학습은 사람이 만든 데이터 두 종류로 시작합니다. 사람이 직접 쓴 답(SFT)과 사람이 두 답 중 고른 결과(선호)입니다.

Meta는 직접 쓴 답을 2.7만 건에서 멈추고, 나머지 예산을 141만 건의 비교로 돌렸습니다. 그 비교로 reward model 두 개를 학습하고, Rejection Sampling과 PPO로 모델을 다섯 번 고쳤습니다.

3절은 Llama 2에서 Llama 2-Chat을 만드는 과정 전체입니다. SFT는 한 번만 하고, 그 뒤로 선호 데이터 수집, reward model 학습, 정책 갱신을 한 바퀴로 해서 여러 번 돕니다. 오늘은 이 중 SFT와 선호 데이터 수집까지 봅니다.

SFT 데이터는 공개 데이터로 시작했다가, 수백만 건짜리 제3자 데이터 대신 vendor가 만든 고품질 데이터로 바꿨습니다. 수천 건만으로도 결과가 좋아졌고, 180건을 직접 비교해 보니 모델이 쓴 답이 사람이 쓴 답과 비슷했습니다. 사람이 더 써 줘도 나아지기 어렵다고 보고 2만 7천 건에서 멈춘 뒤, 예산을 두 답 중 고르는 선호 데이터로 옮겼습니다. 다만 양과 출처와 품질이 동시에 바뀌어서 통제된 비교는 아닙니다.

SFT는 답 토큰에만 loss를 주고
2 epoch만 학습했습니다

prompt와 답을 이어 붙여 4,096 토큰을 채우고(packing), prompt 토큰의 loss는 0으로 둡니다. 질문 말투가 아니라 답하는 방식을 배우게 하려는 설정입니다.

학습률 2e-5(7B 사전학습 peak의 약 1/15) · cosine · weight decay 0.1 · batch 64 × 4,096 · 2 epoch입니다.

근거: Llama 2 · §3.1 Fine-Tuning Details
학습 방식은 사전학습과 같은 다음 토큰 예측인데, prompt 부분은 loss를 0으로 두고 답 부분에서만 loss를 계산합니다. 여러 샘플을 4,096 토큰으로 이어 붙여 학습했고, 학습률은 사전학습의 15분의 1 정도인 2e-5로 2 epoch만 돌렸습니다.

선호는 두 답 중 하나를 고르고
얼마나 나은지 표시해 모았습니다

annotator가 질문을 쓰면, 서로 다른 모델 변형이 temperature를 바꿔 답 두 개를 냅니다.

annotator는 기준(도움 또는 안전)에 따라 하나를 고르고, 얼마나 나은지 4단계 중 하나로 표시합니다. 이것이 비교 1건입니다.

이진 비교는 prompt당 정보 대신
prompt 다양성을 택한 선택입니다

저자들은 이진 비교를 고른 이유로 수집할 수 있는 prompt의 다양성을 듭니다.

K개 응답 순위는 한 prompt에서 여러 쌍을 얻지만, 같은 시간에 볼 수 있는 prompt 수는 줄어듭니다.

InstructGPT: K개 순위
prompt 하나에 4–9개 응답 순위
한 prompt에서 6–36쌍 (K개 중 2개 조합)
Llama 2: 이진 비교
prompt 하나에 응답 2개
한 prompt에서 1쌍 + 강도
트레이드오프 (해석)모델이 좋아져 두 응답이 비슷해질수록 이진 비교의 판정이 어려워집니다.
근거: Llama 2 · §3.2.1 · InstructGPT §3.5
왜 여러 개 순위를 매기지 않고 두 개만 비교했을까요. 저자들은 prompt 다양성을 이유로 듭니다. 순위 방식은 한 질문에서 많은 쌍을 얻지만, 그만큼 다양한 질문을 덜 보게 됩니다. 대신 이진 비교는 두 응답이 비슷해지면 고르기 어려워진다는 약점이 있습니다.

도움과 안전은 기준이 충돌해서
지침을 나눠 따로 모았습니다

도움됨은 요청을 얼마나 잘 들어주고 정보를 주는가, 안전은 응답이 안전 지침에 비추어 위험한가입니다.

"폭탄 만드는 법을 자세히"는 도움은 되지만 안전하지 않습니다. 그래서 지침을 나눠 따로 모았습니다. 안전 annotator는 적대적 prompt에 집중합니다.

안전 단계에서는 응답마다 안전 / 위험 label도 따로 받았습니다(둘 다 안전 47% · 둘 다 위험 35% · 고른 쪽만 안전 18% · 고른 쪽만 위험은 제외).

근거: Llama 2 · §3.2.1
선호는 두 기준으로 따로 모았습니다. 도움이 되는지와 안전한지입니다. 폭탄 제조법을 자세히 알려 주는 답은 도움은 되지만 안전하지 않습니다. 이렇게 두 기준이 부딪히니까 처음부터 지침을 나눴고, 이 분리가 나중에 RM 두 개로 이어집니다.

매주 최신 모델로 다시 모았고,
갈수록 두 응답이 비슷해졌습니다

모델이 좋아지면 출력이 바뀌고, 옛 출력만 본 RM은 새 출력을 잘 못 가립니다. 그래서 선호를 매주, 그 시점 최신 모델의 응답으로 다시 모았습니다(14 batch).

선호 데이터는 한 번에 모으지 않고 매주 최신 모델 답으로 다시 모았습니다. 모델이 바뀌면 출력도 바뀌는데, 예전 출력만 본 RM은 새 출력을 잘 평가하지 못하기 때문입니다. batch가 갈수록 세 가지가 변했습니다. 커졌고, 질문이 어려워졌고, 두 답이 점점 비슷해졌습니다. 마지막 변화 때문에 RM이 가려야 할 문제가 점점 어려워집니다.

Llama 3는 같은 선호 수집 틀에
편집 단계를 더하고 비슷한 쌍을 뺐습니다

논문 밖 내용입니다. 사람이 prompt를 쓰고 두 응답 중 하나를 고른 뒤 강도를 4단계로 표시하는 틀, 그리고 최신 모델로 다시 모은다는 원칙은 그대로입니다.

달라진 핵심은 두 가지입니다. 고른 답을 사람이 직접 고치는 편집 단계로 edited > chosen > rejected 순위를 만들고, 비슷한 쌍은 학습에서 뺐습니다.

마지막은 논문 밖 내용으로, 1년 뒤 Llama 3가 선호 데이터를 어떻게 모았는지입니다. 사람이 질문을 쓰고 두 답 중 하나를 고르고 강도를 표시하는 틀, 그리고 최신 모델로 계속 다시 모은다는 원칙은 같습니다. 달라진 건 두 가지입니다. 첫째, 고른 답을 사람이 직접 더 낫게 고치는 편집 단계를 넣어서, 고친 답, 고른 답, 버린 답 세 단계 순위를 만들었습니다. 둘 다 별로일 때 덜 나쁜 걸 고를 수밖에 없는 이진 비교의 한계를 보완한 겁니다. 둘째, 비슷한 쌍은 학습에서 뺐습니다. Llama 2에서 비슷한 쌍은 reward model도 거의 찍는 수준이었다는 결과와 맞닿아 있습니다.
