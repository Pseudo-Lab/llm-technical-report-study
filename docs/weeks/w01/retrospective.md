## 반성과 규칙

### 1. 결과만 나열하고 “왜 이걸 골랐나”가 없었다
- **피드백:** “다른 대안은 무엇이었는데 왜 이것을 했냐가 중요해요.”
- **고친 방식:** 정규화 · FFN · 위치 · 토크나이저 · 스케줄마다 대안 표를 두었다. 원문이 이유를 밝혔는지 밝히지 않았는지를 구분했다(예: Pre-norm은 “학습 안정성”, RoPE는 미기술).
- **규칙:** 설계 선택 한 장에는 대안, 고른 것, 원문 이유(없으면 “미기술”), 외부 근거를 둔다. 외부 근거에는 그 논문이 인용한 것인지 함께 적는다.

### 2. 숫자 · 인용을 원문에서 다시 확인하지 않았다
- **틀렸던 예:**
  - RMSNorm “7–64% 빠름” → RMSNorm 자체는 7–41%(Transformer 6.9%)이고, 64%는 근사판 수치다.
  - Narang 2021을 LLaMA의 근거처럼 썼다 → LLaMA는 이 논문을 인용하지 않았다.
  - “한”이 바이트로 쪼개진다는 예 → “한”은 어휘에 있다.
  - “공개 데이터 = 약한 모델” 분류 → The Pile은 데이터와 레시피를 둘 다 공개했다.
- **규칙:** 비율 · 속도 · 점수와 “누가 무엇을 인용했나”는 발표 전에 원문을 열어 확인한다. 실제로 돌려 볼 수 있는 것(토크나이저, 설정 파일)은 직접 돌린 결과를 쓴다. 분류를 세우면 반례(The Pile 같은 경우)를 먼저 찾는다.

### 3. 본편이 너무 길고 깊었다
- **피드백:** “Background로 스케일링 빼자 … 1페이지 핵심만”, “벤치마크쪽도 너무 긴데”.
- **고친 방식:**
  - 본편은 주제마다 핵심 한두 장으로 줄였다(스케일링 3장, 평가 8장).
  - 부록 Background는 “LLaMA 1이 제대로 짚지 않고 넘어간 것” 첫 장 → 주제별 로드맵 → 상세 순서로 짰다.
- **규칙:** 원문이 한 줄이나 출처 표기로 넘어간 배경 개념은 부록으로 보낸다. 부록 첫 장에는 주제 · 원문이 한 말 · 부록에서 볼 것 · 다음 주 담당 파트를 표로 두고, 본편의 해당 장 위에 “다음 주 깊게 다시 다룰 내용” 표시를 붙인다.

### 4. 글로 풀었고, 그림이 개념을 보여 주지 못했다
- **피드백:** “글로 날로먹지마”, “41~43 너무 글로 푸는 거 아냐?”, “그림 좀 별로인데 그냥 수식으로”.
- **고친 방식:**
  - 펼친 수식: x₁ = LN(x₀ + F₁) vs x₂ = x₀ + F₁ + F₂, 더하기의 네 항
  - 숫자 예시: [2, 4, 6]의 LayerNorm · RMSNorm 결과, 값 ⊙ 문 = [1.8, 0, 1.5], 회전 점수 0.54
  - 실제 결과: 토크나이저 출력, 처리 전 · 후 레코드
- **규칙:** 개념 장은 “그림 또는 펼친 식 + 작은 숫자 예시 + 4단계 이내 설명”으로 만든다. 그림이 더 어렵게 만들면 식과 예시로 바꾼다.

### 5. 처음 나오는 용어와 “왜”가 한 단계 부족했다
- **나온 질문:** perplexity가 뭐였지 · C = 6ND는 어디서 · Φ와 σ의 차이 · GELU와 GLU의 차이 · 왜 행렬이 3개 · 왜 두 개씩 쌍을 짓나 · 4개 항이 뭘 가리키나.
- **규칙:** 기호와 용어는 처음 나오는 장에서 한 줄로 정의한다. “왜”는 두 단계 아래까지 준비한다. 장마다 청중이 할 질문을 미리 하나 적어 보고, 그 답이 화면이나 대본에 있는지 확인한다.

### 6. 흐름을 꿰는 축이 없었다
- **고친 방식:** 스케일링은 “파라미터당 토큰” 하나로(1.7 → 20 → 21 · 149), 데이터는 “무엇을 넣고 · 얼마나 · 어떻게 걸렀나”로 꿰었다.
- **규칙:** 선행 연구 → 이 논문 → 이후를 비교할 때는 같은 축의 숫자 하나로 꿴다.

### 7. 예시는 “있는 경우 / 없는 경우”와 “처리 전 / 후”로
- **규칙:** 규칙을 설명할 때는 규칙대로 되는 예와 예외가 되는 예를 나란히 둔다. 데이터 처리에서는 처리 전 원문과 처리 후 실제 레코드를 나란히 두고, 지어낸 예는 “설명용”으로 표시한다.

### 8. 한 장에 메시지가 둘 이상이면 넘친다
- **규칙:** 넘치면 글자를 줄이기 전에 장을 나눈다(예: 정규화 위치 · 함수 → 2장, 활성화 곡선 · 게이트 → 2장). 레이아웃 검사는 데스크톱 · 태블릿 · 휴대폰에서 실패 0건이 될 때까지 돌린다.

### 9. 대본을 발표자와 같이 쓴다
- **고친 방식:** 장 제목을 키로 하는 `script.md`를 원본으로 두었다. 덱에서는 `N` 키로 대본을 띄우고, `script.html`에서 전체 대본을 본다.
- **규칙:** 대본은 화면과 함께 장마다 다듬는다. 원문 미기술 · 발표자 해석은 대본에서도 그렇게 말한다.

## 남은 일
- 확신도 ‘중간’이었던 GPT 리뷰 지적(warmup · batch 환산 가정 표시, TruthfulQA 지표 정의 등)은 아직 반영하지 않았다.
- 읽기 지도의 데이터 · 구조 개념 페이지는 이번 발표자료의 최종 내용으로 갱신하지 않았다.
- Post-training · Alignment 구간은 이번 발표에서 대본을 쓰지 않았다.
