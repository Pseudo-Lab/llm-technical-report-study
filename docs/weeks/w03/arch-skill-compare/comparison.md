## 1. 요약

1. **점수 합계는 거의 같고, 성격이 정반대다.** 13개 주제 × 5개 항목 판정 합계는 B 236점, T 234점이다. 주제별 승패는 B 10 : T 3이지만, B가 이긴 10개 중 4개는 합계 동점이었고 1개(pre-norm · RMSNorm)는 T의 합계가 더 높았다. 항목 평균으로 보면 근거는 B 4.92 대 T 2.46, 밀도는 B 2.23 대 T 4.54로 정반대다. (→ 5장)
2. **B의 강점은 정직성과 검증이다.** 75장 모두 출처 줄이 보이고(T는 0장) 대본이 있다(T는 0장). 숫자마다 근거 종류를 붙이고, 본문 주장을 표에서 다시 계산해 BBH 예외 · Theorem QA 9.8 대 10.8 같은 원문 불일치를 찾아낸다. 무엇을 유지했는지(we follow Qwen)와 원문 목록에 없는 작은 변화(작은 모델 tying, FFN 폭 5.29 d)는 B만 정리한다. (→ 4.1, 4.4 / B#39 · B#44 · B#48 · B#49)
3. **B의 약점은 길이 · 밀도 · 배치다.** 본편이 52장이고, 장당 화면 글 중앙값은 680자다(75장 기준. 본편만 세면 668.5자. T는 290자). 본편 대본의 한글 음절만 27,063개라 분당 300음절이면 약 90분이다(하한. 영어 단어 4,140개 · 숫자 3,030개는 뺀 값). 공백 제외 55,673자로 세면 약 160–200분이다(C10 투표). pre-norm이 왜 안정적인지와 QKV bias 네 항의 전개는 부록(B#59, B#63)에만 있다. 8/3은 이유는 본편 B#15에 있고 대수 한 줄만 부록으로 갔다. 원문 crop은 휴대폰에서는 확대 없이 읽을 수 없고, 데스크톱 · 프로젝터에서는 작다(C14, 논쟁 있음: 판정에 쓰는 값은 HTML로 다시 적혀 있다). (→ 4.1, 4.2, 4.3, 4.5 / B#15 · B#39 · B#59 · B#63)
4. **T의 강점은 가벼운 장과 기제 도식이다.** T는 장당 화면 글이 중앙값 290자로 가볍고, 표가 없는 장은 대개 1–2문장과 주 시각 1개로 짠다(표 전체 장 T#13 · T#22 · T#24–27은 예외). 경로 도식(T#2, T#15, T#16, T#20)과 KaTeX 유도 카드(T#4, T#9)로 '어떻게 동작하나'를 본편에서 보인다. Table 2–5를 HTML로 모두 다시 그리고 본문 주장을 색으로 표시했다. (→ 4.2, 4.3, 4.5 / T#2 · T#9 · T#24)
5. **T의 약점은 근거 표시다.** 출처 줄을 CSS로 숨겼다. config 값 · 추정 · 발표자가 만든 식에 표시가 없어 수치 감사에서 '표시 없는 계산 · 해석'이 14건 나왔다(28장, 장당 0.50건. B는 75장에 12건, 장당 0.16건). 본문 주장을 옮기며 판정이나 수정을 글로 밝히지 않았다. 예외가 있는데 단정한 줄은 T#13 ③(BBH 45.0 < 45.6)과 T#25 ②(GSM8K 80.7 < 82.7) 두 줄이고, T#27은 고친 사실을 표시하지 않았다. (→ 4.4, 6.2, 6.3 / T#13 · T#25 · T#27)
6. **가져올 것(P1):** P1-1 발표 시간 · 장 수 예산, P1-2 장당 밀도 예산과 근거 표지 위계, P1-3 배정 항목의 기제 · 유도는 본편에, P1-4 KaTeX 사전 렌더, P1-5 원문 crop 대신 HTML로 다시 짠 표 · 도식을 주 시각으로, P1-6 평가 절 개요 장, P1-7 전체화면 · 진행 표시 접기 · 대본 진입점. **지킬 것(핵심 5개):** 보이는 출처 줄, 대본, 근거 표지, 본문 주장 판정, 유지/변경 정리. 지킬 것 전체 13개는 9장에 있다. (→ 8장, 9장)

**해석할 때 주의할 점**

- **글꼴 차이가 측정을 흔든다.** B의 제목 줄 수와 넘침 검사 결과는 측정한 기기에 묶인다. Windows(Malgun Gothic)에서는 달라질 수 있다.
- **T의 깨진 링크 1건은 비교 환경 때문이다.** checker가 잡은 T#15의 `../w02/llama2-reading-map.html#c-mha-mqa-gqa`는 덱을 비교용 폴더(`arch-skill-compare/teammate/`)로 두 단계 옮기면서 깨졌다. 원래 자리(`docs/weeks/w03/`)에서는 실제 파일과 앵커로 이어진다(C04, C28 투표).
- **B의 입력 제한이 일부 약점을 만들었다.** B는 W01 읽기 지도를 열 수 없어서 AdamW · cosine을 'W01에서 다뤘다고 보고 — 확인 필요'로 처리했다(B#53). Su(2023b) 블로그도 입력에 없어 '이번 미열람'으로 남겼다(B#16).
- **측정 도구는 같다.** 두 덱 모두 같은 `deck_metrics.cjs` · `check_deck.cjs`로 쟀다. 다만 도구의 특성 몇 가지(숨은 대본도 표지 수에 들어감, 이미지 속 글자는 글자 크기에 안 잡힘)가 결과에 영향을 준다. 3장 표의 '주의' 칸에 적었다.

### 4.2 명확성 (용어 · 계산 단계 · 비교 짝 · 참조)

**B 강점**
- 식 → 값 대입 → 단위 → 비율 분해를 한 화면에 보이고, 같은 입력으로 두 방식을 나란히 둔다(C07). B#29는 G(x) = [2, 1, 0.5, −1]을 ①–⑤ 단계로 풀고 Mixtral 순서와 대조한다(합 0.834 대 1, y 6.991 대 8.386). B#18은 '2 × 32층 × 32 × 128 × 2 B = 524,288 B = 512 KiB', '524,288 ÷ 57,344 = 9.14배 = 8배 × 1.14배'를 적는다.
- 비교 조건을 맞춘다(C07, S9). B#30은 총 · 활성 폭을 고정한 대안(10,240 × 16개 중 2개, C(16,2) = 120)과 Qwen2(2,560 × 64개 중 8개, C(64,8) = 4,426,165,368)를 비교하고, Mixtral은 'hidden 4,096이라 조건이 달라' 뺐다고 적는다.
- 비교 짝을 처음부터 구분한다(C16). B#1 '↕ 비교 짝 · 가중치 계승 아님 (Qwen2의 직전 7B = Qwen1.5-7B)', B#8 §2.2.3 'relative to Qwen1.5 models'에 상자, B#25 Qwen-7B와 Qwen1.5-7B 구분.
- 용어를 먼저 정의한다(C27). B#3의 '처음 나오는 용어' 열(MHA · GQA · KV cache · config · shot), B#38 'shot = 문항 앞에 붙인 풀이 예시 수'.

**B 약점**
- 배정 항목의 유도 일부가 부록에만 있고, 본편과 링크로 이어지지 않는다(C06). B#16 본문은 QKV bias의 결론('거리만의 함수인 항이 하나 생긴다')만 말하고 '유도 → A-8'로 넘긴다. 실제 전개는 47장 뒤 B#63에 있고, 장 사이 링크도 없다. pre-norm · RMSNorm은 본편 전용 장이 없다. 본편에는 B#11 표 두 행('Post-LN → Pre-Norm', 'LayerNorm → RMSNorm'), B#13 도식의 위치(RMSNorm을 건너뛰는 잔차선), B#48 유지 표뿐이고, 왜 안정적인지는 부록 B#59에만 있다. (반박 반영: 8/3의 이유는 B#15 본문에 있고, 부록으로 간 것은 '8d² = 3dh' 대수 한 줄이다. pre-norm은 scope.md 배정 블록에 이름이 없다.)
- 장 사이 참조가 '2-8', '정의 1-3', '→ A-7' 같은 내부 코드이고 링크가 아니다(C25, 논쟁 있음). `href="#s…"`가 0개다. 머리 라벨은 'RQ1 … · 8 / 10'이라 RQk = (k+1)절로 바꿔 세야 한다. (반박 반영: 부록 장은 'A-5' 같은 배지를 화면에 보인다.)
- 같은 경계 경고를 여러 장에서 되풀이한다(C16). B#8 · B#18 · B#25 · B#41 · B#47.
- 정의 일부가 작은 캡션에 있다(C27). B#11 '외삽 = …'. B#61은 원전 표기 W · V · W₂와 gate · up · down의 대응을 적지 않았다.

**T 강점**
- 배정 항목의 유도를 본편에서 끝까지 보인다(C06). T#9 '① 8d² → ② 3dh → ③ 3dh = 8d² → ④ h = 8/3 d', T#6 post-norm과 pre-norm의 미분식, T#3 → T#4 → T#5 '어디에 넣었나 → 네 항 전개 → Su 실험'.

## 10. 한계

- **LLM이 판정했다.** 주제 판정 · 반박 투표 · 수치 감사 모두 LLM이 했다. 사람 청중의 이해도나 선호를 잰 것이 아니다.
- **위치 편향 가능성.** 판정은 주제마다 한 번만 돌렸다. 비교 Workflow의 판정 지시문은 주제마다 먼저 볼 덱을 번갈아 정했지만(홀수 번 주제는 B 먼저, 짝수 번 주제는 T 먼저), 같은 주제를 순서를 바꿔 다시 돌리지는 않았다. 동점 4개 중 Qwen Table 1 · 2 한 주제에서만 판정자가 결과를 정확히 전하는 쪽을 골랐다고 밝혔다. 나머지 셋(학습 설정, GQA, KV cache)은 동점을 가른 근거가 기록되지 않았다. 동점 넷은 B를 먼저 본 주제(5 · 7)와 T를 먼저 본 주제(6 · 8)가 둘씩인데 모두 B가 이겼다. 근거를 중시하는 판정 방식이 근거 중심인 B에 유리했을 수 있다.
- **같은 shell을 썼다.** 두 덱이 같은 shell에서 출발해 레이아웃 · 내비게이션 차이가 작아 보일 수 있다. 반대로 진행 점 · 머리줄 같은 shell 동작이 장 수 차이(75 대 28)와 섞여 배율 차이를 만들었다.
- **한 번만 실행했다.** B는 파이프라인을 한 번 돌린 결과다. 같은 스킬로 다시 돌리면 장 수 · 밀도가 달라질 수 있다. verify-criteria는 v1을 3개 섹션만 다시 만들어 편차를 보겠다고 정해 두었다(verify-criteria.md 26행).
- **글꼴 교란.** B는 글꼴을 싣지 않아 측정 Mac의 Apple SD Gothic Neo로 그려졌다. T는 Pretendard를 내장했다. 제목 줄 수 · 넘침 · 글자 폭 비교에 이 차이가 섞여 있다.
- **제작 조건이 다르다.** B는 입력이 제한된 AI 파이프라인의 '사람 검토 전 초안'이고 약 4.7시간이 걸렸다(RUN.md 4행). T는 제한 없는 사람의 '완성본'으로 보이며 제작 시간 기록이 없다. 대본 · 출처 숨김 같은 차이 일부는 산출물 종류의 차이일 수 있다(C13 논쟁 있음).
- **측정 도구의 특성.**
  - 근거 표지 수는 숨은 대본까지 세고, 일반 단어('계산')도 센다.
  - 16px 미만 비율은 이미지 속 글자를 세지 않아 B의 crop 부담을 낮게 잡는다.
  - SVG 글자 수는 HTML로 그린 차트를 놓친다.
  - checker의 넘침 검사는 카드 안 스크롤 영역을 넘침으로 보지 않아, 휴대폰에서 가려진 수식 · 표를 잡지 못한다.
- **T는 대본이 없어 발표 시간을 잴 수 없다.** 'T 28장 ≈ 30분'은 장당 1분이라는 가정이다.
- **보완 점검(S1–S11)은 반박 투표를 거치지 않았다.** S1이 밝힌 대로 화면 낭독기 실측은 하지 않았다.
