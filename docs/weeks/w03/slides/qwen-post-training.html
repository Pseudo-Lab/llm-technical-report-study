§3.1 / APPENDIX A.1.1

ChatML로 역할을 구분하고, Assistant 응답 본문에 Loss를 계산합니다.

기존 Human–Assistant 형식

human: Hello!

assistant: Hello!
일반 텍스트인 human / assistant가 역할 구분자로도 사용되어 모호할 수 있습니다.
ChatML은 전용 특수 토큰으로 메시지 경계를 명확하게 표시합니다.
ChatML 형식 + SFT Loss Masking
<|im_start|>system본문 LOSS = 0
You are a helpful assistant.
<|im_end|>
<|im_start|>user본문 LOSS = 0
Hello!
<|im_end|>
<|im_start|>assistant본문 LOSS 계산
Hello!
<|im_end|>
System / User는 문맥으로 읽되, Assistant 응답 본문을 학습 대상으로 삼습니다.

색상 표시는 메시지 본문에 대한 Loss Masking을 나타냅니다. 역할명 및 <|im_start|> / <|im_end|> 특수 토큰 각각의 Loss 처리 여부는 이 보고서에 명시되지 않았습니다.

Source: Qwen Technical Report (2023), §3.1.2, Appendix A.1.1QWEN · 5 / 53
§3.1 · LOSS MASKING

사용자 입력은 조건으로 사용하지만, 응답 토큰에 학습 신호를 줍니다.

SYSTEM
You are a helpful assistant.
USER
What is 2 + 3?
ASSISTANT
2 + 3 = 5.
LSFT = − Σt mt log pθ(xt | x<t)
mt = 0
System / User 토큰: Loss 제외
mt = 1
Assistant 응답: Loss 계산

설명용 일반적 SFT objective. 구체적인 delimiter token의 loss 처리까지 원문 발췌에 명시된 것은 아닙니다.

Source: Qwen Technical Report (2023), §3.1.2, Appendix A.1.1QWEN · 6 / 53
§3.2.1 · REWARD MODEL

RLHF는 먼저 “어떤 답변이 더 좋은가”를 판단하는 모델을 학습합니다.

① 사람의 선호 데이터

B. 어렵고 부정확한 설명

③ 응답마다 점수 하나
Reward Model응답 A의 점수 > 응답 B의 점수좋은 응답을 더 높게 평가
Qwen 논문의 “pooling”은?
입력한 Prompt + Response의 토큰 표현 중 특정 종료(end) 토큰을 기준으로, 응답 전체의 점수 하나를 추출하는 구조입니다.
핵심: Reward Model은 답변을 생성하는 모델이 아니라, 생성된 답변을 평가하는 모델입니다.

설명용 응답 예시입니다. Qwen은 동일 크기의 pretrained Qwen에 pooling layer를 추가했다고 기술하지만 pooling 연산의 구체적인 형태는 공개하지 않았습니다.

§3.2.2 · PPO 학습 절차

Qwen PPO의 실제 학습은 세 단계만 기억하면 됩니다.

1
Value Model부터 준비Policy를 고정하고 Value만 50 step 먼저 학습
2
Policy가 응답 생성질문마다 2개 응답을 샘플링
3
평가 결과로 PPO 업데이트Reward 점수를 높이되 Reference와 멀어지면 불이익
Qwen의 KL 계수0.04과도한 정책 변화 억제
추가로 사용한 장치Pretrained Gradient기존 능력 저하(Alignment Tax) 완화 목적

더 상세한 PPO 목적함수·learning rate·value loss clipping은 발표자 노트에서 설명합니다. Qwen은 Pretrained Gradient의 정확한 결합 계수를 공개하지 않았습니다.

§3.4 · TAKEAWAY

결론: Agent 데이터는 Qwen-Chat SFT에 통합됐고, 성능은 세 환경에서 확인했습니다.

학습에서 보여준 사실: 약 2K 고품질 Agent 예시를 Self-Instruct로 구축하여 일반 SFT와 혼합. 별도의 Agent 전용 학습 단계는 추가하지 않음.
