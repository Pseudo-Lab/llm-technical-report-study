# DeepSeek-V4: 1M 문맥을 위한 모델·시스템·후학습 읽기 경로

[W09 학습목표](../weeks/w09/README.md) · [배경 읽기 지도](README.md)

[DeepSeek-V4 v1](https://arxiv.org/abs/2606.19348v1)의 주요 구성요소를 본문 순서로 연결한다. CSA/HCA와 OPD를 이해하는 데 필요한 기반 모델, 데이터, 정밀도와 실행 시스템도 함께 읽는다. 수치와 구현 선택은 본문·Appendix B를 기준으로 하며, benchmark 이름이나 참고문헌에만 등장한 항목은 필수 배경에서 제외한다.

## V4 §3을 읽기 위한 시스템 선수 개념

### EP: expert를 나누는 일과 token을 보내는 일

MoE의 router가 token을 top-k expert로 고르면, **Expert Parallelism(EP)** 은 그 expert가 있는 GPU로 activation을 보내고(`dispatch`), expert FFN을 계산한 뒤 결과를 원래 token 위치에 합쳐 돌려보내는(`combine`) 분할 방식이다. V4 §3.1과 Fig. 5의 네 stage는 `Dispatch → Linear-1 → Linear-2 → Combine`이며, `SwiGLU + FP8 cast`는 Fig. 5에서 Linear-1과 Linear-2 사이의 activation 처리로 그려진다. 새 V4 방법은 expert를 wave로 쪼개어, 이번 wave의 GEMM, 다음 wave의 dispatch, 이전 wave의 combine을 겹치는 fused pipeline이다. 즉 top-k **routing rule**과 EP **실행 배치**는 다른 층위다.

V4가 직접 쓰는 판정은 `C/B ≤ V_comp/V_comm`이다. peak compute `C`, interconnect bandwidth `B`, 계산량 `V_comp`, 통신량 `V_comm`의 비율이 이 범위면 통신을 계산 뒤에 숨길 수 있다. 예를 들어 Pro의 token–expert pair는 6hd FLOPs와 3h bytes를 써 `C/B≤2d`가 된다. **점검:** network bandwidth를 두 배로 늘려도 이미 이 조건을 만족한다면 end-to-end latency가 반드시 두 배 빨라지는가? 아니다. compute가 새 병목이다. 이 항목은 V4 §3.1이 1차 근거이며, routing의 선행 원리는 위 DeepSeekMoE 경로만 읽는다.

### ZeRO/data-parallel Muon: element shard와 whole-matrix update의 충돌

V4 §3.4.1은 Muon이 full gradient matrix를 필요로 할 때 [ZeRO v1 §3](https://arxiv.org/abs/1910.02054v1)의 element-wise optimizer sharding과 충돌한다고 설명한다. ZeRO는 optimizer state·gradient·parameter를 rank에 분배해 memory 중복을 줄이는 방법이고, V4는 data-parallel group이 ZeRO limit보다 클 때 일부 group에서 Muon update를 중복 계산하는 trade-off도 명시한다. Muon의 Newton–Schulz는 한 논리 matrix 전체의 singular direction을 보므로, 단순 element shard만 보고 update하면 같은 연산이 아니다.

그래서 V4는 dense matrix를 ZeRO bucket에 matrix 경계가 남게 knapsack 배정하고, MoE expert의 SwiGLU up/down/gate matrix도 **논리적으로 독립인 matrix를 자르지 않게** flatten/pad한다. BF16 stochastic-round gradient sync와 FP32 local sum은 통신량과 누적 오차를 함께 다룬다. **점검:** 한 matrix를 element 수만 같게 반씩 나누면 왜 Newton–Schulz의 full-matrix update와 달라지는가? V4의 답은 matrix 단위를 보존한 bucket assignment다.

### CP·recomputation: sequence를 나눈 뒤 경계와 memory를 다시 맞춘다

**Context parallelism(CP)** 은 긴 sequence의 연속 token 구간을 rank별로 나누는 방식이다. CSA/HCA는 `m` 또는 `m'`개의 **연속** KV를 한 block으로 압축하므로 CP 경계에서 block이 잘릴 수 있고, packed sample마다 tail 길이도 다르다. V4 §3.4.3은 rank i의 마지막 `m` raw KV를 다음 rank에 보내 경계 block을 만들고, local compression 뒤 all-gather/select-and-pad로 global compressed entries를 재구성한다. **점검:** `m=4`이고 rank 경계 앞에 token 2개, 뒤에 token 2개가 있다면 왜 뒤 rank가 앞 rank의 두 entry를 받아야 하는가?

**Activation checkpointing/recomputation** 은 forward의 모든 intermediate activation을 저장하지 않고, backward 직전에 필요한 부분만 다시 계산해 memory를 시간으로 바꾸는 방법이다. V4 §3.4.2는 mHC에서 hidden state와 normalized input을 선택적으로 recompute하고, §3.4.4는 module 단위가 아닌 annotated tensor부터 필요한 최소 recomputation graph를 TorchFX로 찾는다. GPU memory copy 대신 freed storage pointer를 재사용한다. **점검:** activation을 전혀 저장하지 않으면 memory는 작지만 왜 compute가 커지는가? V4는 “무조건 recompute”가 아니라 compute-intensive operation은 보존하는 절충을 쓴다.

### kernel fusion·determinism·cache tier: 같은 결과와 덜 움직이는 bytes

**Kernel fusion** 은 여러 작은 operator의 intermediate를 GPU memory에 쓰고 다시 읽거나 Python에서 여러 번 launch하지 않고 하나의 compiled kernel/host launcher로 묶는 일이다. V4 §3.1의 EP pipeline과 §3.2 TileLang은 같은 이름의 한 기법이 아니라 각각 MoE communication-computation overlap과 fine-grained operator/host overhead을 푸는 선택이다. §3.3의 **batch invariance** 는 같은 token이 batch의 어느 자리에 있든 bitwise 같은 결과를 내는 성질이고, deterministic backward는 floating-point accumulation order를 고정해 loss spike를 재현·추적할 수 있게 한다. 둘을 “정확도가 더 높다”는 주장으로 바꾸지 않는다.

V4 §3.5의 cache는 homogeneous PagedAttention 하나가 아니다. CSA/HCA의 compressed KV는 classical KV cache에, SWA와 아직 `m`/`m'`이 차지 않은 raw tail은 fixed-size state cache에 둔다. disk prefix hit에서도 complete compressed block은 읽어 재사용할 수 있지만 incomplete tail은 raw state가 없으므로 recompute한다. SWA는 full caching / periodic checkpoint / zero caching 중 storage–recompute trade-off를 고른다. **점검:** disk cache가 hit했는데도 tail prefill이 남는 이유를 compressed block boundary로 설명한다.

## V4 §4–§5을 읽기 위한 data·precision·reward 선수 개념

### FIM·token splitting·packing·sample mask는 같은 preprocessing이 아니다

V4 §4.1은 V3 tokenizer의 special context token, token-splitting, Fill-in-Middle(FIM)을 **계승**하고 vocabulary 128K를 유지한다고만 공개한다. 정확한 원전 읽기 경로는 V4 → [DeepSeek-V3 v2 §4.1](https://arxiv.org/abs/2412.19437v2) → [DeepSeek-Coder-V2 v1 §3.1](https://arxiv.org/abs/2406.11931v1) → [Bavarian et al., FIM v1](https://arxiv.org/abs/2207.14255v1)이다. V3는 Coder-V2의 관찰을 근거로 FIM을 채택했다고 쓰며, 같은 절에서 Prefix–Suffix–Middle(PSM) 배열과 document-level pre-packing 적용을 명시한다. Bavarian et al.은 이 계보에서 Coder-V2가 직접 인용한 FIM 원전이다. FIM은 middle span을 예측하게 sequence 순서를 재배치해 code infilling을 학습하는 objective 변형이다. V3의 token splitting은 긴 document chunking이 아니라, punctuation과 line break를 합친 pretokenizer token을 일정 확률로 다시 나눠 terminal newline이 없는 multi-line prompt에서 생기는 token-boundary bias를 줄이는 처리다. V4가 직접 인용한 [Fewer Truncations Improve Language Modeling v1 §2–§3.1](https://arxiv.org/abs/2404.10830v1)에서는 긴 문서의 불가피한 절단과 concatenate-then-split의 추가 절단을 구별하고, chunk를 길이순으로 가장 잘 맞는 bin에 넣는 Best-fit Packing을 읽는다. V4의 source-aware packing은 이 packing 연구를 참고해 서로 다른 source의 document를 구성하는 선택이며, 원전 알고리즘과 동일 구현이라고 단정하지 않는다. source-aware packing은 짧은 document를 한 training sequence에 넣어 padding/truncation 낭비를 줄이는 배치 구성이다. V4의 sample-level attention mask는 **서로 다른 packed sample의 token이 attention하지 못하게** 경계를 준다.

작은 예로 doc A의 3 token과 doc B의 2 token을 한 5-token row에 pack했을 때, A의 query가 B key를 읽으면 A와 B가 하나의 문서였던 것처럼 training된다. sample mask는 그것을 막는다. 이는 causal mask(미래를 막음)와 다른 축이다. V4가 template/auto-generated web filtering, long-document/multilingual curation, agentic coding mid-training을 적은 것과 tokenizer merge 학습을 새로 제안한 것은 별개다.

### FP4 QAT는 inference에서 FP4로 cast하는 것만이 아니다

V4 §5.2.1의 **quantization-aware training(QAT)** 은 post-training forward에서 quantization 오류가 있는 weight/activation을 보게 해 teacher/reference/model이 deployment precision에 적응하도록 하는 절차다. V4는 MoE expert FP32 master weight를 FP4로 quantize한 뒤 FP8로 losslessly dequantize해 computation하고, backward gradient는 동일한 FP8 forward weight에 대해 master FP32로 전달한다(STE). indexer QK path도 FP4 cache/load/multiply하고 index score는 FP32→BF16으로 내려 top-k selector를 빠르게 한다.

MXFP4 표현의 직접 선행 원전은 [Microscaling Data Formats v1 §2–§3, Fig. 1·Table 1](https://arxiv.org/abs/2310.10537v1)이다. 하나의 block이 shared scale과 좁은 scalar element를 따로 저장하는 구조, MXFP4의 32-element block·E8M0 scale·E2M1 element를 먼저 읽고 V4가 선택한 scale 처리로 돌아간다.

그와 달리 inference/rollout에서는 backward가 없으므로 native FP4 weight를 직접 사용한다. **점검:** “FP4→FP8 is lossless”는 FP32 original weight가 그대로 남는다는 뜻인가? 아니다. V4가 검증한 sub-block scale 범위에서 **FP4 representation을 FP8로 표현하는 변환**이 lossless라는 뜻이다. 이 절은 report 자체가 1차 근거이며, V4가 QAT 일반 선례로 인용한 [Quantization and Training of Neural Networks for Efficient Integer-Arithmetic-Only Inference §2](https://arxiv.org/abs/1712.05877v1)는 선택 보충이다.

### GRM·ORM·OPD: reward를 만들고 policy를 맞추는 단계가 다르다

V4 §5.1.1에서 easy-to-verify task는 rule/test verifier를, hard-to-verify task는 rubric-guided data를 쓴다. **Outcome reward model(ORM)** 은 trajectory/answer를 scalar reward로 점수화해 RL policy update에 주는 별도 model이라는 개념이다. V4는 hard task에서 conventional scalar RM/ORM을 별도 annotation으로 훈련하는 대신 actor가 evaluative role도 수행하는 **Generative Reward Model(GRM)** 을 두고 GRM 자체도 RL 최적화한다고 설명한다. 이 specialist SFT→GRPO stage는 “teacher logits을 맞추는 OPD”가 아니다.

그 뒤 §5.1.2의 OPD는 student가 낸 prefix에서 domain teacher의 **분포 전체**를 reverse-KL로 맞추는 통합 stage다. 따라서 `verifier/GRM이 reward를 낸다 → GRPO가 specialist를 바꾼다 → student trajectory에서 full-vocabulary KL이 specialist를 하나로 옮긴다`가 순서다. V4는 ORM 원전을 새로 직접 인용하지 않으므로 ORM은 여기서 비교 정의로만 쓰고, OPD 배경은 V4가 병렬로 직접 인용한 MiniLLM과 [Thinking Machines Lab, On-Policy Distillation의 Implementation → Loss function: reverse KL → Pseudocode](https://thinkingmachines.ai/blog/on-policy-distillation/)를 읽는다. 후자는 student가 생성한 token에 teacher log probability를 붙이는 흐름을 설명한다. V4의 full-vocabulary KL은 이 글의 sampled-token advantage 방식과 구별할 변경점이다.

## W09에서 세 목표로 압축할 때의 선택

W09 목표는 `CSA`, `HCA`, `full-vocabulary OPD`를 중심에 둔다. 위 표의 mHC·MoE·MTP·Muon·data curriculum·infrastructure는 생략된 배경이 아니라 **각 목표를 오독하지 않기 위한 필요 개념**이다. 예컨대 CSA top-k가 보인다고 해서 V4가 all-MoE/aux-loss-free balance/MTP를 새로 제안했다고 말할 수 없고, full-vocabulary OPD가 보인다고 scalar GRM specialist training까지 OPD로 했다고 말할 수 없다.

## 보고서가 말하지 않은 것을 채우지 않는 경계

- V4는 tokenizer에 “special token 추가, vocabulary 128K 유지”와 V3 계승을 말한다. 새 BPE/BBPE merge 학습이나 token vocabulary의 구성 원리를 공개하지 않으므로 이를 V4의 신규 tokenizer 기법으로 만들지 않는다.
- CSA/HCA의 open-source inference implementation은 detail 확인용이다. 논문 본문에 없는 training behavior를 코드 기본값으로 단정하지 않는다.
- §4.3·§5.3–§5.4의 benchmark와 real-world score는 설계 전체의 결과다. CSA, mHC, Muon, data, OPD 중 하나의 단독 인과 효과로 읽지 않는다.
- V4는 [MOPD v1](https://arxiv.org/abs/2606.30406v1)을 직접 인용하지 않는다. V4의 OPD는 위 MiniLLM·Thinking Machines Lab의 병렬 직접 경로 및 본문 식 (29)을 출발점으로 읽는다.
