# W09 — DeepSeek-V3.2: 본문 구성요소와 선행 개념

[W09 학습목표](../weeks/w09/README.md) · [전체 읽기 지도](README.md) · [읽기 분담](workload.md)

## 이번 주 읽기 범위

[DeepSeek-V3.2 v1](https://arxiv.org/abs/2512.02556v1)은 세 문제를 한 보고서에서 다룬다. 긴 문맥 attention 비용은 DSA로, RL compute를 키울 때의 off-policy/MoE 불안정성은 GRPO recipe로, reasoning과 tool use의 결합은 context policy와 합성 환경으로 해결하려 한다. 한 기법이 다른 둘의 배경이라는 뜻은 아니다. 이 문서는 각 절이 실제로 요구하는 개념을 따로 연결한다.

공통 읽기는 [주차별 분담표](workload.md)에 적힌 대상 본문으로 시작한다. 담당 심화에서는 아래 구성요소 중 한 갈래와 필요한 선행 원전의 지정 절을 읽는다.

## 본문 구성요소와 선행 개념

<a id="dsa"></a>
### 1. DSA: 먼저 모든 과거 token을 싸게 점수화하고, 그 뒤 일부만 attention한다

[V3.2 §2.1–§2.1.1, Fig. 2, 식 (1)–(4)](https://arxiv.org/pdf/2512.02556v1)는 DeepSeek Sparse Attention(DSA)을 두 component로 설명한다.

1. **Lightning indexer**는 query token `h_t`와 과거 token `h_s`의 score `I_{t,s}`를 작은 head 수, ReLU, FP8로 계산한다. Fig. 2처럼 indexer의 query와 key에는 **partial RoPE**를 적용한다. ReLU는 이 논문에서 throughput을 위한 선택이다.
2. **Fine-grained selector**는 score top-`k`의 latent KV entry만 core attention에 넘긴다. main attention은 모든 과거 token이 아니라 선택된 set에만 attention한다.

따라서 core attention은 `O(L²)`에서 `O(Lk)`로 줄지만, indexer는 여전히 `O(L²)`이다. “DSA가 quadratic을 완전히 제거한다”라고 말하면 틀리다. 저자 주장은 작은 FP8 indexer와 optimized kernel을 포함한 end-to-end long-context cost 절감이다([§2.3, Fig. 3](https://arxiv.org/pdf/2512.02556v1)).

| 대상 본문 | 먼저 읽을 실제 연결 | 확인할 질문 |
| --- | --- | --- |
| V3.2 §2.1 “Instantiate DSA Under MLA” | [DeepSeek-V2 v5 §2.1.1–§2.1.4](https://arxiv.org/abs/2405.04434v5) → [MQA v1 §2.4](https://arxiv.org/abs/1911.02150v1) → V3.2 §2.1 | V3.2는 V3.1-Terminus checkpoint에서 계속 학습하기 위해 MLA 위에 DSA를 넣는다. kernel 효율을 위해 MLA의 **MQA mode**로 구현하여 한 latent KV entry를 query heads가 공유한다. MQA는 selector가 고른 top-`k`가 아니라, KV 공유 방식이다. |
| V3.2 Fig. 2와 Appendix A | V3.2 Appendix A “MHA and MQA Modes of MLA” | training/prefill의 MHA mode와 decoding의 MQA mode를 그림으로 분리한다. GQA를 이 보고서의 직접 전제로 추가하지 않는다. |
| V3.2 §2.1.1 dense warm-up | V3.2 §2.1.1 식 (3) | dense attention을 유지하고 indexer만 1,000 step 학습한다. 모든 attention head score를 합산·L1 normalize한 `p_{t,:}`와 `softmax(I_{t,:})`를 KL로 맞춘다. dense attention이 teacher distribution이고, indexer가 학생이다. |
| V3.2 §2.1.1 sparse training | V3.2 §2.1.1 식 (4) | selection 뒤에는 선택된 set `S_t` 안에서만 alignment한다. indexer 입력은 stop-gradient로 분리한다. indexer는 `L_I`만, main model은 language-model loss만 받는다. top-`k`가 미분하기 어렵다는 사실을 “같은 loss를 나눠 받는다”로 숨기지 않는다. |

작은 예로 과거 KV가 8개이고 indexer score 상위 3개가 `(s=2,5,7)`이면, DSA core attention은 그 3개만 읽는다. `s=1`의 dense attention weight가 컸다면 indexer alignment loss가 다음 update에서 이를 반영하도록 만든다. **선택 오류가 없는 것이 아니라**, dense warm-up과 continued training으로 그러한 오류를 줄이려는 것이다.

<a id="scaling-grpo"></a>
### 2. V3.2의 scalable GRPO: 같은 목적식에 붙인 네 가지 안정성 장치

W07에서 GRPO의 group advantage를 배웠다면, [V3.2 §3.1, 식 (5)–(9)](https://arxiv.org/pdf/2512.02556v1)은 “rollout을 많이 생성하고 여러 mini-batch update를 할 때 그 식을 어떻게 유지할까”를 묻는다. 일반 GRPO 원전은 [DeepSeekMath v3 §4.1.1–§4.1.3](https://arxiv.org/abs/2402.03300v3)이고, V3.2가 K3 estimator를 고친 배경은 저자가 직접 인용한 [Schulman, *Approximating KL Divergence*](http://joschu.net/blog/kl-approx.html)이다.

| V3.2의 장치 | 문제 | 원문에서 확인할 동작 |
| --- | --- | --- |
| unbiased KL estimate | `π_old`에서 sample했는데 current/reference만으로 K3 KL을 추정하면, 특히 `π_θ ≪ π_ref` token에서 큰 biased gradient가 생길 수 있다. | 식 (7)은 current/old importance ratio를 포함한다. 이것은 KL penalty를 항상 강하게 하라는 주장이 아니다. 저자는 math에서는 약하거나 없는 KL이 더 좋을 수 있다고 쓴다. |
| Off-Policy Sequence Masking | 큰 rollout batch를 여러 update에 재사용하고 inference/training framework가 다르면 sample이 current policy에서 멀어진다. | 식 (8)–(9)은 divergence가 임계값보다 큰 **negative-advantage sequence만** mask한다. 모든 off-policy data를 버리는 rule도, positive error를 mask하는 rule도 아니다. |
| Keep Routing | MoE의 inference/training numerical 차이와 policy update가 같은 input의 activated expert를 다르게 만들 수 있다. | rollout 때의 expert routing path를 저장해 training 때 강제한다. 새 MoE objective가 아니라 active parameter subspace가 갑자기 바뀌는 것을 막는 consistency policy다. |
| Keep Sampling Mask | top-p/top-k truncation 후에는 old/current action space가 다를 수 있어 importance sampling 전제가 깨진다. | rollout의 truncation mask를 current policy에도 적용한다. top-p를 “언어 일관성 reward”로 쓰는 것이 아니라, 같은 action support에서 update하도록 보존하는 것이다. |

[V3.2 §3](https://arxiv.org/pdf/2512.02556v1)는 specialist distillation 뒤 reasoning·agent·human-alignment를 한 mixed RL stage에 넣는다. reasoning/agent는 rule-based outcome reward·length penalty·language consistency reward, general task는 prompt별 rubric의 generative RM을 쓴다. multi-stage 학습의 catastrophic forgetting을 피하려는 선택과, 위 네 안정성 장치를 같은 것으로 섞지 않는다.

<a id="thinking-agent"></a>
### 3. Thinking tool use: context policy, cold start, environment synthesis

#### 3.1 대화 role에 따라 CoT를 버리는 조건을 바꾼다

[V3.2 §3.2.1, Fig. 4](https://arxiv.org/pdf/2512.02556v1)은 R1 식으로 두 번째 message가 오면 reasoning을 버리는 policy가 tool loop에서는 매번 재추론하게 만들어 token을 낭비한다고 말한다. V3.2는 **새 user message일 때만** 기존 reasoning을 제거하고, tool output만 이어지면 reasoning과 tool-call/result history를 남긴다. Roo Code/Terminus처럼 tool interaction을 user message로 흉내 내는 framework는 이 이득을 충분히 받지 못할 수 있어 non-thinking model을 권한다. 이것은 context window가 무한해진다는 주장이 아니라, 어떤 history를 유지할지의 policy다.

#### 3.2 Cold start는 reasoning data와 agent data의 interface를 한 trajectory로 맞춘다

[V3.2 §3.2.2 및 Appendix B Tables 6–8](https://arxiv.org/pdf/2512.02556v1)는 reasoning-only `<think>` example, non-thinking agent의 tool-description/format example, 그리고 thinking 중 여러 tool call을 허용하는 system prompt를 구분한다. 명시적 prompting으로 두 behavior를 이어 보지만 저자도 이 pattern이 아직 robust하지 않을 수 있다고 적는다. 이 data는 이후 agent RL의 initial trajectory를 만들기 위한 것이며, 합성 environment 자체와는 다른 단계다.

#### 3.3 “hard but easy to verify” 환경을 만들 때는 tool interface를 닫는다

[V3.2 §3.2.3, Table 1, §4.3, Fig. 5](https://arxiv.org/pdf/2512.02556v1)의 general agent path는 다음 순서다.

`category + sandbox → data를 sandbox DB에 저장 → task-specific tools 생성 → task/solution/verifier 생성 → solution 검증 → 난도 증가와 toolset 보강 → non-zero pass@100 filtering`

solution function은 tool function 호출이나 logical computation만 할 수 있고, 다른 function 호출이나 DB 직접 access는 못 한다. 그래서 “정답을 검사하기 쉬운 task”라는 말은 agent가 내부 DB를 bypass해 답을 복사할 수 없다는 interface 제약까지 포함한다. verifier가 solution을 통과시키지 못하면 solution 또는 verifier를 수정하며, 난도를 올리다 tool이 부족하면 toolset도 보강한다.

보고서는 real search/code/code-interpreter environment와 synthesized general environment를 구분한다(Table 1). 또한 §4.3은 50개 합성 task에서 frontier model도 낮은 pass@k를 보였다는 **난도**와, synthetic-only RL이 Tau2Bench/MCP-Mark/MCP-Universe에 transfer됐다는 **일반화**를 별개로 평가한다. verifier 통과·synthetic 난도·out-of-domain transfer는 같은 증거가 아니다.

<a id="test-time-context"></a>
### 4. Search agent의 test-time compute: serial context management와 parallel sampling

[V3.2 §4.4, Fig. 6](https://arxiv.org/pdf/2512.02556v1)은 context 사용량이 80%를 넘을 때 overflow trajectory를 Summary, Discard-75%, Discard-all로 처리한다. 비교 baseline은 여러 independent trajectory를 뽑아 fewest-step trajectory를 고르는 parallel scaling이다. 둘 다 test-time compute를 늘리지만 전자는 한 trajectory를 더 길게 이어 가고, 후자는 여러 trajectory를 병렬로 탐색한다. Fig. 6에서 Discard-all이 특정 BrowseComp 조건에서 효율/확장성 면에서 강했다는 관찰을, 모든 agent나 모든 context-management policy의 우위로 확장하지 않는다.

### 원전 사용 원칙

- DSA의 1차 근거는 V3.2 §2.1이다. MLA는 `V3.2 §2.1 → V2 §2.1`의 한 단계 연결이며, Qwen의 QSA나 다른 sparse attention과 동일 구현이 아니다.
- V3.2의 RL 안정화와 agent context/task pipeline은 이 보고서가 직접 설명한 새 recipe다. W07의 R1 GRPO, W08의 MiMo verifier-RL, W13의 long-horizon async RL과 용어가 비슷해도 서로의 구현을 대신하지 않는다.
- 지표를 읽을 때 model mode·agent framework·internal environment·context policy를 함께 기록한다. 특히 MCP benchmark internal environment와 BrowseComp context management 조건은 표의 점수와 분리할 수 없다.
