# Solar Open → Solar Open 2: 언어 데이터, hybrid state, 전이와 agent 학습

[W16 학습목표](../weeks/w16/README.md) · [배경 읽기 지도](README.md)

Solar Open 계열의 변화는 “한국어 data를 늘리고 linear attention을 넣었다”가 아니다. Solar Open은 tokenizer·synthetic data·curriculum·sparse MoE·off-policy RL을 묶고, Solar Open 2는 같은 backbone 일부를 옮긴 채 attention stack·state·expert pool·long-context curriculum·agent post-training을 바꾼다. 이 문서는 두 보고서 본문에서 실제로 필요한 개념을 단계별로 분해한다.

## 1. tokenizer: BPE vocabulary, pre-tokenization, chat interface는 다른 층이다

[Solar Open v1 §2.1·§2.1.1–§2.1.3·Table 1·Fig. 2–3](https://arxiv.org/abs/2601.07022v1)는 196,608 vocabulary의 byte-level BPE를 Korean/target domain oversampling corpus로 학습한다. digit을 독립 token으로 만들고 whitespace를 보존하는 regex는 각각 number/formula의 일관성과 indentation-sensitive code fidelity를 겨냥한다. [BPE v1 §3.2](https://arxiv.org/abs/1508.07909v1)는 pair merge의 원리만 설명한다. Solar Open의 Korean oversampling·digit split·whitespace rule은 별도 recipe다.

compression은 `UTF-8 bytes / produced tokens`이며 높을수록 같은 문자열을 적은 token으로 표현한다. 이는 Korean byte fallback/semantic segmentation, effective context, token당 inference cost와 연결되지만, 높은 bytes-per-token 자체가 reasoning accuracy를 증명하지는 않는다. `system/user/assistant/tool` role과 `<|think|>`를 분리하는 chat template(§2.1.2)은 tokenizer merge vocabulary가 아니라 model input/output protocol이다.

Solar Open 2 [§2.1](https://arxiv.org/abs/2607.20062v2)는 vocabulary를 196,608로 **그대로 유지**한다. 이는 embedding/output layer를 transfer할 수 있는 전제이며, “새 tokenizer를 만들어 1M context를 얻었다”는 설명은 틀리다.

**작은 점검.** 같은 Korean 문장에 byte-level BPE token 수가 줄어드는 효과, whitespace-preserving pre-tokenization의 code 효과, special role token의 conversational boundary 효과를 세 줄로 분리한다.

## 2. Solar Open 1의 sparse MoE와 bilingual curriculum

[Solar Open §2.2·Table 2](https://arxiv.org/abs/2601.07022v1)는 48 layer, 64 query/8 KV head GQA, 128 routed+1 shared expert, token당 Top-8, SiLU, RoPE를 둔 102B total/12B active sparse MoE를 공개한다. [GQA v3 §2.1–§2.2](https://arxiv.org/abs/2305.13245v3)와 [MoE v1 §2·§2.1·§4](https://arxiv.org/abs/1701.06538v1)을 읽어 KV head sharing과 expert routing·load balancing을 분리한다. shared expert는 route가 불확실하거나 일반 경로가 필요할 때를 보완하는 항상 활성 경로이고, Top-k는 token별 activated compute를 뜻한다.

**router 안정화의 국소 용례.** Solar Open §2.2는 expert-bias만 쓰면 early layer imbalance가 남았다고 보고, sequence-wise load-balancing loss를 함께 쓴다. 모든 layer가 MoE이므로 “처음 dense layer가 안정화한다”는 다른 family의 recipe를 가져오지 않는다. routing bias와 load-balancing loss는 *어느 expert로 보낼지*의 분포를 안정화하는 장치이며, Top-8은 *한 token이 실제로 실행할 expert 수*다.

[Solar Open §3.1–§3.2·Fig. 4](https://arxiv.org/abs/2601.07022v1)는 약 19.7T corpus에 4.5T synthetic data를 넣고, phase가 갈수록 quality threshold와 synthetic ratio를 높인다. general quality classifier, language-aware educational score, embedding topic clustering은 각각 불량 제거·학습적 품질·domain coverage를 다루므로 하나의 “quality score”가 아니다. late phase의 64% synthetic ratio도 전체 corpus의 synthetic ratio로 바꾸어 말하지 않는다.

이 data recipe는 tokenizer compression과 다른 지표다. `Korean 22% tokenizer-training mixture`와 `pretraining phase의 bilingual/synthetic ratio`는 서로 다른 corpus·목적을 가진 수치다.

**작은 점검.** (a) Korean byte-per-token, (b) Korean pretraining token 비율, (c) synthetic ratio를 각기 어느 table/figure에서 읽는지 적고 서로 대체 가능한 숫자가 아닌 이유를 말한다.

### HSDP·hybrid precision·MoE fast path은 data recipe가 아닌 system layer다

[Solar Open §3.3.1–§3.3.5·Table 3](https://arxiv.org/abs/2601.07022v1)에서 **FSDP**는 parameter/optimizer/gradient를 rank에 shard해 model memory를 분산하는 data-parallel 방식이다. 16→60 node에서 gradient All-Reduce가 inter-node traffic 때문에 둔화되자, **HSDP**는 global device pool을 10-node sharding group으로 쪼개 group 안에서는 FSDP, group 밖에서는 replica 사이 gradient 동기화를 한다. 즉 FSDP를 버린 것이 아니라 대부분의 shard communication을 작은 group에 가두고, 전역 consistency만 replica 간 collective로 유지한 계층화다.

**hybrid FP8/BF16**은 report가 full FP8 대신 선택한 정밀도 배치다(§3.3.3 footnote). FP32 sigmoid가 필요한 router score를 계산한 뒤 원 dtype을 회복시키는 일은 numerical safety와 이후 matmul의 FP32 slow path 방지를 함께 다룬다. 이 문제는 “FP8이면 자동으로 빠르다”가 아니라 tensor마다 안정성과 throughput의 허용 정밀도가 다름을 보여 준다.

**MoE fast path**도 별개다. expert parallel을 쓰지 않은 이 configuration에서는 grouped-GEMM의 padding/reorder가 일만 늘리므로 bypass했다(§3.3.3). load-balancing loss도 one-hot 대신 histogram으로 계산했다. 둘은 router의 learning objective나 Top-8 expert 의미를 바꾸지 않고, 같은 routing 결과를 더 적은 framework overhead로 실행하는 kernel 선택이다.

## 3. Solar Open SFT: 난도 추정에서 다섯 데이터 경로까지

[Solar Open §5.1–§5.5 및 Appendix A.3](https://arxiv.org/abs/2601.07022v1)는 SFT를 단일 instruction mixture가 아닌 다섯 data path로 설명한다. **difficulty-aware curation**은 reasoning complexity estimator로 existing data의 난도를 계층화해 sampling하는 path이고, **complex query generator**는 seed context에서 query를 만들고 estimator로 평가해 더 어려운 query 쪽으로 generator를 cyclically retrain하는 path이다. classifier는 GLM/Qwen의 reasoning 유무와 Solar Pro 2를 포함한 **다섯 model configuration의 self-consistency 패턴**을 이용한다. 약 140K query-response tuple에서 query 간 pairwise 비교를 만들고 LLM이 난도를 label하여 classifier를 학습한다(§5.1). 생성과 난도 판정은 역할이 다르므로 “어려운 synthetic query를 생성했다” 한 문장으로 끝내지 않는다.

**agent simulation**은 API specification/dependency를 확장한 tool set에서 success criterion이 있는 task를 만들고, task-oriented multi-tool trajectory와 user-oriented multi-turn requirement refinement를 따로 합성한다(§5.3). 여기서 tool call의 argument, prior tool output, error recovery를 포함한 *trajectory supervision*이 일반 QA data와 다른 이유를 확인한다.

**Korean knowledge integration**은 embedding match로 관련 문서를 연결해 comparative·causal·multi-hop·theme-inference QA를 만들고, SFT/RL 모두에 넣는다(§5.4). 더 많은 Korean token을 넣는 것과 여러 source를 연결해야 답할 수 있는 relation supervision은 다른 개입이다.

**safety framework**은 38 risk category마다 harmful intent의 refusal-with-redirection과 self-harm 등 sensitive case의 bounded safe completion을 구분한다(§5.5). adversarial-but-safe query를 넣어 over-refusal을 줄이는 data는 unsafe query를 더 잘 거절하게 하는 data와 목표가 다르다. 이 구분은 safety reward나 classifier 이름으로만 대신하지 말고 Appendix A.3 example까지 읽는다.

**작은 점검.** 어떤 sample이 (a) difficulty estimator의 score 대상, (b) generator의 output, (c) agent trajectory, (d) Korean multi-hop pair, (e) safety-policy response인지 구분하고, 그 sample에 필요한 input context를 한 줄씩 적는다.

## 4. SnapPO: generation, reward, training을 cache로 분리하는 RL system

[Solar Open §6–§6.1.1](https://arxiv.org/abs/2601.07022v1)는 SnapPO를 cyclic off-policy framework로 둔다. generation 결과, reward computation, training을 분리해 cache하고 behavior-policy log probability를 저장한다. reward를 다시 계산해도 rollout을 다시 생성할 필요가 없도록 하는 것이 핵심이다. [GSPO v1 §1–§4.1](https://arxiv.org/abs/2507.18071v1)은 Solar Open이 직접 채택한 sequence likelihood ratio/sequence-level clipping의 배경이다.

이것은 “RL이 offline이다”라는 한 문장으로 끝나지 않는다. stale behavior policy에서 나온 response의 ratio를 현재 policy와 대조하는 문제, domain마다 reward를 바꾸어 합성할 수 있는 문제, rollout straggler를 training step의 동기화에서 떼어내는 문제가 구분된다. Solar Open §6.2의 reasoning optimization과 §6.3의 iterative DPO도 reward/objective가 다른 phase다.

**작은 점검.** response pool에서 (i) 새 token generation, (ii) reward recomputation, (iii) policy gradient update 중 무엇이 SnapPO cache에서 재사용 가능한지 표시한다. GSPO의 sequence ratio를 token-level PPO ratio라고 바꾸어 쓰지 않는다.

## 5. Solar Open 2: softmax global recall + KDA fixed-size state

[Solar Open 2 §2.2·Fig. 3·Table 1](https://arxiv.org/abs/2607.20062v2)는 48 layer에 `[softmax ×1, linear ×3]×12`의 S-L-L-L pattern을 둔다. softmax layer는 GQA와 sigmoid output gate, linear layer는 KDA를 쓴다. softmax attention은 exact global recall을, linear layer는 fixed-size recurrent state로 sequence length에 대해 constant KV cache/linear compute를 목표로 한다. 하나가 다른 하나의 implementation detail이 아니다.

[Kimi Linear v2 §2.2·§3](https://arxiv.org/abs/2510.26692v2)와 [Gated Delta Networks v3 §2.1–§2.2·§3.1–§3.3](https://arxiv.org/abs/2412.06464v3)을 통해 delta-rule state update를 읽은 뒤 Solar Open 2로 돌아온다. linear state는 과거 token의 모든 K/V를 정확히 재생하는 cache가 아니라, 순차 update된 고정 크기 memory다. 그 한계 때문에 이 보고서는 25% softmax layer를 남긴다.

### NoPE와 negative eigenvalue는 별개의 확장

NoPE는 softmax Q/K에 explicit position signal을 넣지 않고, sequence order를 linear state update 순서에 맡긴다. [PE Length Generalization v2 §4–§5](https://arxiv.org/abs/2305.19466v2)을 읽어 NoPE가 “순서 정보가 없다”가 아님을 확인한다. Solar Open 2는 RoPE extrapolation과 position learning bottleneck을 피하려는 범위에서 이 선택을 설명한다.

KDA의 `allow_neg_eigval=True`는 write strength를 `β=2σ(·)∈(0,2)`로 넓혀 transition eigenvalue range를 `[-1,1]`로 만든다. [Unlocking State-Tracking v5 §3.1·§4.1–§4.2](https://arxiv.org/abs/2411.12537v5)에서 negative eigenvalue가 parity/modular counting 같은 state tracking에 필요한 이유를 확인한다. 양의 [0,1] range가 decay/persist만 허용한다면 음수 eigenvalue는 sign flip/erase correction을 가능하게 한다. NoPE는 positional representation의 선택, negative eigenvalue는 recurrent transition의 표현력 선택이다.

**작은 점검.** `s_t=-s_{t-1}`가 가능한 상태와 `s_t=0.5s_{t-1}`만 가능한 상태를 비교한다. 어느 쪽이 alternating parity를 보존할 수 있는지와, 이것이 softmax layer의 exact retrieval를 대체하지 않는 이유를 적는다.

## 6. selective weight transfer: 어디까지 옮겼으며 어디서 새로 시작했는가

[Solar Open 2 §3.1·Table 2·Fig. 6](https://arxiv.org/abs/2607.20062v2)는 Solar Open 1→2에서 5.69B(2.3%)만 transfer하고, 나머지는 random initialize한다. 기준은 “이전 checkpoint에 있음”이 아니라 **representation/shape/computation이 같아 1:1 대응하는가**다.

| Solar Open 2 module | 처리 | 이유 |
| --- | --- | --- |
| token embedding/output, normalization, 12 softmax GQA의 q/k/v/o, shared expert | transfer | vocabulary·shape·GQA geometry가 유지됨 |
| linear layer의 q/o | GQA q/o에서 remap | shape가 맞는 부분만 대응 |
| linear k/v, decay/write gate, short convolution, sigmoid output gate | random | 이전 model에 대응 computation이 없음 |
| 320 routed expert와 router | random | 128→320은 1:1 mapping이 없고 복제는 expert similarity를 키울 위험 |

[Sparse Upcycling v2 §3–§3.1](https://arxiv.org/abs/2212.05055v2)은 dense checkpoint를 expert로 복제하는 방법, [Priming v1 §2.2·§3.2.2–§3.2.4](https://arxiv.org/abs/2605.08301v1)은 attention→hybrid 전이의 alignment를 다룬다. Solar Open 2의 방식은 둘을 그대로 재현한 것이 아닌 partial warm start이며, **distillation도 하지 않았다**고 본문이 명시한다. Fig. 6의 proxy는 initialization만 바꾼 controlled comparison이므로 data/architecture 전체 우위를 증명하는 그림으로 과장하지 않는다.

## 7. 1M pretraining과 agent post-training은 구조 전이의 후속 단계다

[Solar Open 2 §3.2–§3.3·Fig. 5·Fig. 8](https://arxiv.org/abs/2607.20062v2)는 10T general pretraining→1T high-threshold intensive pretraining→0.9T length expansion과 checkpoint merge를 쓴다. Stage 4에서 performance drop을 보고하고 네 intermediate checkpoint merge로 보정한다. NoPE/hybrid architecture가 있으므로 length curriculum이 불필요했다는 뜻은 아니다.

[Solar Open 2 §4.1–§4.2](https://arxiv.org/abs/2607.20062v2)는 agent SFT scenarios, fully asynchronous RL, 12-specialist MOPD를 추가한다. MOPD는 prompt 하나를 한 teacher에 route하고 student 자체 rollout의 full-vocabulary reverse KL을 쓴다. 이때 environment reward를 다시 더하지 않고, `[L×V]` logits 전체를 보내는 대신 pre-lm-head hidden state를 tile로 보내 student가 logits를 재구성한다. 12 teacher pool의 CPU snapshot swap은 한 GPU slot에서 teacher를 바꾸는 serving/system 비용 절감 장치다. 이는 Solar Open 1의 SnapPO와 동일 recipe가 아니다.

**asynchrony의 국소 용례.** Solar Open 2 §4.2.1은 rollout token마다 생성 policy version과 rollout-time log probability를 붙인다. fresh-token ratio가 기준에 못 미치면 trajectory를 버리고, 기준을 넘으면 stale prefix token만 loss에서 mask한다. token-level double-sided importance ratio도 범위를 벗어나면 제외한다. 이는 “off-policy trajectory 하나를 전부 쓰거나 버린다”는 단순 rule보다 긴 agent rollout을 회수하려는 설계이며, SnapPO의 cached stage separation과는 겹치는 문제도 있지만 동일한 admission rule은 아니다.

**작은 점검.** Solar Open 1의 SnapPO와 Solar Open 2의 fully asynchronous RL/MOPD를 `rollout policy metadata`, `reward 사용 여부`, `teacher signal`, `cache/recompute` 네 칸으로 비교한다.

## 연결 주차와 범위

- **W16:** tokenizer·data/curriculum·KDA/NoPE·selective transfer가 핵심 경로다. SnapPO/MOPD는 구조/데이터 목표 뒤의 후학습을 읽기 위한 보충 경로다.
- **W08/W12/W15:** agent environment·asynchronous RL·MOPD와 용어가 겹쳐도, W16은 Solar Open 계열의 system/transfer 결정만 다룬다.

## 원전 사용 원칙

- Solar Open 1/2의 수치·module mapping·curriculum·system은 [Solar Open v1](https://arxiv.org/abs/2601.07022v1)와 [Solar Open 2 v2](https://arxiv.org/abs/2607.20062v2)의 본문/appendix를 1차 근거로 삼는다.
- BPE, GQA, MoE, GSPO, KDA/GDN, NoPE, state tracking, upcycling/priming은 본문이 필요로 하거나 직접 인용하는 배경 원전이다. 선행 원전의 일반 결과를 Solar Open 결과라고 하지 않는다.
