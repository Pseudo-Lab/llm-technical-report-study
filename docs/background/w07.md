# W07 — DeepSeek-R1: 본문 구성요소와 선행 개념

[W07 학습목표](../weeks/w07/README.md) · [전체 읽기 지도](README.md) · [읽기 분담](workload.md)

## 이번 주 읽기 범위

이 문서는 [DeepSeek-R1 v2](https://arxiv.org/abs/2501.12948v2)의 본문과 기술 부록을 따라간다. `R1-Zero의 pure RL`만이 논문의 전부는 아니다. 같은 보고서는 **검증 가능한 보상**, **사람이 읽을 수 있게 바꾼 cold start와 두 번의 SFT/RL**, **긴 rollout을 실제로 돌리는 시스템**, **작은 모델로의 증류**를 서로 다른 문제로 둔다. 아래 순서는 그 경계를 잃지 않기 위한 읽기 경로다.

공통 읽기는 [주차별 분담표](workload.md)에 적힌 대상 본문으로 시작한다. 담당 심화에서는 아래 구성요소 중 한 갈래와 필요한 선행 원전의 지정 절을 읽는다.

## 본문 구성요소와 선행 개념

<a id="verifiable-rl"></a>
### 1. SFT 없는 R1-Zero: 무엇을 보상할 수 있어야 하는가

[R1 §2.1–§2.3, 식 (1)–(4)](https://arxiv.org/pdf/2501.12948v2)는 V3-Base에서 SFT를 먼저 하지 않고 GRPO로 rollout을 갱신한다. 여기서 `pure`는 데이터가 전혀 없다는 뜻이 아니라, **사람이 쓴 reasoning demonstration으로 policy를 먼저 모사하지 않는다**는 뜻이다. 문제와 정답 또는 실행 가능한 판정기는 여전히 필요하다.

| 대상 본문에서 확인할 것 | 필요한 배경과 범위 | 왜 필요한가 · 작은 점검 |
| --- | --- | --- |
| R1 §2.1 식 (1)–(3)의 group-relative advantage | [DeepSeekMath v3 §4.1.1–§4.1.3](https://arxiv.org/abs/2402.03300v3) | 같은 질문의 `G`개 답에서 `A_i=(r_i-mean(r))/std(r)`를 만든다. 별도 value critic을 학습하는 PPO와 달리 group reward가 baseline 역할을 한다. 세 답의 보상이 `(1,1,0)`이면 정답 둘의 advantage가 같고 오답은 음수가 되는지 계산한다. **GRPO는 R1의 신규 제안이 아니라 채택한 알고리즘**이다. |
| R1 §2.2 식 (4)의 accuracy + format reward | R1 §2.2; Supplementary B.3.1의 math/code/STEM/logic 자료 | 수학은 정답 match, 코드는 compiler/test case처럼 외부 판정기로 정확도를 준다. `<think>…</think><answer>…</answer>`은 추론 내용을 채점하는 보상이 아니라 출력 경계를 강제하는 format reward다. proof처럼 정확도를 안정적으로 판정하기 어려운 자료를 왜 제외했는지 B.3.1에서 확인한다. |
| R1 §2.2가 reasoning에 neural ORM/PRM을 쓰지 않은 이유 | R1 §2.2와 §6 “Reward Hacking”; Supplementary B.5 | 저자 주장은 큰 규모 RL에서 neural reward model이 policy에 의해 exploit될 수 있고, 재학습 비용도 크다는 것이다. 이는 “모든 neural RM이 불가능하다”는 일반 명제가 아니다. R1의 general prompt에는 뒤에서 model-based reward를 별도로 쓴다. |
| R1 §2.3, Fig. 1의 길어진 CoT·reflection 관찰 | R1 §2.3; Supplementary C.1–C.2 | 긴 출력·`wait` 같은 반성 표현의 증가를 관찰했지만, 특정 reward 항 하나가 reflection을 **인과적으로** 만들었다는 ablation은 제시하지 않는다. 관찰 결과와 mechanism 주장을 구분한다. |

R1-Zero의 template는 reasoning과 final answer의 위치만 제한한다. 따라서 “사람과 같은 CoT를 가르쳤다”가 아니라 **정답/형식으로만 feedback을 주었을 때 exploration 중 어떤 reasoning pattern이 나타났는가**가 첫 질문이다. 이 설계는 reliable verifier가 있는 math·code·logic에서만 바로 성립한다.

<a id="staged-r1"></a>
### 2. R1의 다단계 recipe: 읽기 쉬움, 일반 대화, 안전은 별도 신호다

[R1 §3, Fig. 2, 식 (5)–(10)](https://arxiv.org/pdf/2501.12948v2)는 R1-Zero를 그대로 제품형 모델로 쓰지 않았다. `cold-start SFT → reasoning RL → rejection-sampling SFT → mixed RL`이라는 흐름에서 각 단계가 고치는 대상을 따로 표시한다.

| 단계 | 원문 근거 | 새로 들어가는 신호와 해결하려는 문제 |
| --- | --- | --- |
| cold-start SFT | [§3, Supplementary B.3.2](https://arxiv.org/pdf/2501.12948v2) | annotator가 Zero trace를 1인칭·문제 이해→추론→반성/검증·질문 언어 유지 형태로 다듬고, LLM rewrite 뒤 사람 검수를 한다. 이는 reasoning capability를 새로 증명하려는 단계가 아니라 language mixing과 읽기 어려운 trace를 제품 관점에서 완화하는 시작점이다. |
| 첫 RL | [§3.2.1, 식 (5)–(7)](https://arxiv.org/pdf/2501.12948v2) | reasoning prompt에는 rule reward를 쓰되 language-consistency reward를 마지막 reward에 더한다. 정확도 신호와 “사용자 언어로 읽히는 CoT” 신호를 혼동하지 않는다. |
| rejection-sampling SFT | [§3, Supplementary B.3.3](https://arxiv.org/pdf/2501.12948v2) | 첫 RL checkpoint에서 reasoning data를 sample·filter하고, V3 SFT의 non-reasoning 자료 및 일부 code-engineering 자료와 묶어 800K SFT 자료를 만든다. sample을 보상으로 **선별하여 imitation data로 바꾸는 것**과 on-policy RL update는 다르다. |
| 두 번째 mixed RL | [§3.2.2, 식 (8)–(10)](https://arxiv.org/pdf/2501.12948v2) | reasoning에는 다시 rule reward, general prompt에는 helpfulness/safety RM + format reward를 사용한다. 일반 instruction/preference는 마지막 400 steps에만 넣으며, 저자는 model-based reward를 더 오래 쓰면 reward hacking이 나타날 수 있다고 쓴다. |

#### Reward model의 두 가지 학습 문제

[R1 §3.1](https://arxiv.org/pdf/2501.12948v2)은 reward model을 하나의 “선호 점수”로 뭉뚱그리지 않는다. helpfulness RM은 chosen/rejected **pairwise** ranking(66K pair, 응답 길이를 맞춤)이고, safety RM은 safe/unsafe **pointwise** 분류(106K data)다. 동일 query가 어느 dataset에 속하느냐에 따라 general reward를 고른다. 작은 점검으로, 길이가 긴 답이 자동으로 chosen이 되지 않도록 길이를 맞춘 이유와, safe/unsafe에 왜 pairwise 비교가 필수는 아닌지를 구분해 본다.

<a id="rl-system"></a>
### 3. 긴 reasoning RL을 가능하게 한 시스템 분해

보고서의 기술 기여를 알고리즘 식만으로 읽으면 긴 rollout의 비용을 놓친다. [Supplementary B.1, Fig. 5](https://arxiv.org/pdf/2501.12948v2)는 아래 네 module을 분리한다. 이것은 새 RL objective가 아니라 **생성·판정·학습의 자원 충돌을 줄이는 실행 설계**다.

| module | R1에서 하는 일 | 구분할 점 |
| --- | --- | --- |
| Rollout | 여러 vLLM worker가 actor로 응답을 sample한다. V3 MoE에는 node 간 expert parallelism·hot expert 복제, MTP self-speculative decoding을 쓴다. | MTP는 policy loss가 아니라 longest rollout completion을 줄이려는 decoding 보조다. MTP 기본 학습은 [W06](../weeks/w06/README.md)를 먼저 본다. |
| Inference | reward model과 reference model forward를 수행한다. | model-based reward/KL 정보가 필요할 때의 GPU module이며 rule checker와 다르다. |
| Rule-based reward | code executor, answer matcher, format checker를 unified interface로 실행한다. | GPU model은 없지만 느릴 수 있어 rollout/inference와 비동기로 겹친다. “규칙 기반이므로 공짜”가 아니다. |
| Training | actor와 필요 시 critic을 update하고, global length sort → process 분배 → Best-Fit pack으로 padding을 줄인다. DualPipe pipeline parallelism도 쓴다. | GRPO는 critic을 생략할 수 있지만 framework는 PPO/DPO도 수용한다. 알고리즘의 필요조건과 framework의 일반성을 분리한다. |

각 module이 끝나면(규칙 보상 module 제외) model instance를 VRAM에서 system memory/disk로 offload한다. 질문 하나의 `generate → check → update` 순서는 그대로지만, 어느 비용을 서로 overlap하는지가 scalability를 결정한다.

<a id="distillation"></a>
### 4. Teacher trace를 SFT로 옮기는 것과 작은 모델의 직접 RL 비교

[R1 §5–§6 및 Supplementary F–F.1](https://arxiv.org/pdf/2501.12948v2)은 R1 rollout을 sample해 Qwen/Llama base model에 SFT하는 distillation을 공개한다. 여기서 학생은 teacher와 상호작용하며 reward를 받는 것이 아니라, **고정된 teacher-generated reasoning trace를 모사**한다. 저자들의 조건부 결론은 다음과 같다.

- 작은 base model에서 같은 규모의 RL을 직접 돌리는 것보다 R1 distillation이 더 좋은 성능을 냈다. 이는 teacher가 이미 탐색해 낸 long-CoT 분포를 전달하기 때문이다.
- 이것이 “SFT가 언제나 RL보다 낫다”는 뜻은 아니다. 충분히 큰 base checkpoint·검증 가능한 reward·RL compute가 있으면 direct RL은 새로운 탐색을 할 수 있다.
- reliable verifier가 약한 복잡한 task에서는 pure RL을 확대하기 어렵고, tool use·structured output은 당시 R1의 약점으로 남는다([§6](https://arxiv.org/pdf/2501.12948v2)).

**마지막 점검.** 학생이 맞힌 답을 teacher의 trace로 SFT한 경우와 학생이 스스로 낸 답을 verifier로 채점해 GRPO한 경우를, (1) 행동을 만든 policy, (2) 학습에 쓰는 target, (3) 실패를 고치는 signal의 세 칸에 적어 비교한다.

### 원전 사용 원칙

- R1의 primary source는 [v2 고정 본문·부록](https://arxiv.org/abs/2501.12948v2)이다. 숫자·단계·시스템 설명은 이 보고서에서 확인한다.
- GRPO 수식의 원 제안은 R1 본문이 직접 인용한 [DeepSeekMath v3 §4.1.1–§4.1.3](https://arxiv.org/abs/2402.03300v3)이다. PPO는 비교 대상이며 R1의 기법으로 바꾸어 쓰지 않는다.
- MiMo/Flash의 verifier·dynamic sampling은 비슷한 단어가 있어도 다른 구체적 recipe다. W08에서 별도로 읽는다.
