# W05 — DeepSeek-V2: 본문 구성요소와 선행 개념

[W05 학습목표](../weeks/w05/README.md) · [전체 읽기 지도](README.md) · [읽기 분담](workload.md)

## 이번 주 읽기 범위

DeepSeek-V2는 MLA와 DeepSeekMoE만 제시하는 논문이 아니다. [§2–§5와 Appendix B–E](https://arxiv.org/abs/2405.04434v5)는 KV cache, expert routing, data/tokenizer, parallel training, long-context extension, SFT/RL을 하나의 model release에서 함께 다룬다. 이 문서는 그 연결을 먼저 잡고 W05의 세 목표로 돌아가는 읽기 경로다. 원전은 본문 직접 인용을 우선하고, 본문이 이름만 든 BPE/RMSNorm 일반 원전은 **선택 보충**으로 표시한다.

공통 읽기는 [주차별 분담표](workload.md)에 적힌 대상 본문으로 시작한다. 담당 심화에서는 아래 구성요소 중 한 갈래와 필요한 선행 원전의 지정 절을 읽는다.

**연결 자료:** [W01 block·RoPE·AdamW](w01.md) · [W02 GQA·선호 정렬](w02.md)

## 본문 구성요소와 선행 개념

### 1. attention: 저장 형태와 위치 처리를 분리한다

| DeepSeek-V2 본문에서 확인할 것 | 왜 먼저 알아야 하나 | 본문이 직접 인용한 원전과 범위 | V2에서의 유지·제안과 작은 확인 |
| --- | --- | --- | --- |
| [§2.1.1, Eq. (1)–(9)](https://arxiv.org/abs/2405.04434v5)는 MHA의 per-head K/V와 decoding KV cache를 출발점으로 둔다. | MLA의 이득은 attention score 자체를 sparse하게 만드는 것이 아니라 **과거 token마다 cache할 표현**을 바꾸는 데서 시작한다. | [Transformer v7 §3.2.1–§3.2.2](https://arxiv.org/abs/1706.03762v7), [MQA v1 §2.4·§3](https://arxiv.org/abs/1911.02150v1), [GQA v3 §2.1–§2.2](https://arxiv.org/abs/2305.13245v3). | MHA는 head마다 K/V, MQA는 한 K/V, GQA는 group 공유다. 작은 점검: decoding step `t`에서 cache가 model layer마다 길이 `t`에 비례하는 이유를 적고, query는 cache하지 않는다는 점을 표시한다. |
| [§2.1.2, Eq. (10)–(13)](https://arxiv.org/abs/2405.04434v5)는 K/V를 `c^KV`로 down-project한 뒤 K/V로 up-project하며, inference에는 latent `c^KV`만 cache한다고 설명한다. | low-rank factorization을 알지 못하면 “latent cache”를 K와 V를 단순 평균낸 것으로 오해하기 쉽다. | 이 low-rank joint compression의 정확한 구조는 V2의 **자체 제안**이다. 별도 선행 원전을 들지 않으므로 V2 §2.1.2와 Appendix C Eq. (35)–(46)를 직접 읽는다. | V2의 새 방법이다. 작은 점검: `c^KV` 하나를 저장하고 `W^UK c^KV`, `W^UV c^KV`를 재구성하는 경로를 그린 뒤, MQA가 head 수를 줄이는 방식과 다르다고 설명한다. |
| [§2.1.3, Eq. (14)–(18)](https://arxiv.org/abs/2405.04434v5)는 RoPE를 latent K 전체에 적용하면 projection absorption이 깨진다고 설명하고, shared positional key `k^R`와 head별 `q^R`로 decouple한다. | KV compression과 RoPE는 독립 기능이지만 naively 결합되지 않는다. 왜 “position을 따로 든 key”가 필요한지 여기서 나온다. | [RoFormer v5 §3.2·§3.4.2](https://arxiv.org/abs/2104.09864v5). | V2는 RoPE **사용을 유지**하면서 latent cache에 맞게 position path를 **분리**한다. 작은 점검: `W^UK`가 query projection 쪽에 absorb될 수 있는 경우와 RoPE matrix가 position마다 달라 absorb되지 않는 경우를 한 문장으로 대비한다. |
| [§2.1.4, Table 1과 Appendix D](https://arxiv.org/abs/2405.04434v5)는 cache size를 MHA/GQA/MQA/MLA로 비교하고, Appendix D.2에서 MHA 대비 MLA의 cache와 성능을 대조한다. | “압축”은 parameter count, activation memory, KV cache 중 무엇을 줄였는지 명시해야 검증 가능한 주장이다. | 비교식·ablation은 V2 report의 자체 근거다. Appendix D.1은 MHA/GQA/MQA, D.2는 MLA/MHA를 대조한다. | V2의 headline은 cache 감소와 hard benchmark 성능을 함께 보는 것이다. 작은 점검: Table 1에서 cache formula의 `l`(sequence length)와 `n_h`(head count)가 어느 선택에서 사라지거나 남는지 표시한다. |

### 2. MoE는 전문가 식만이 아니라 device 제약이다

| DeepSeek-V2 본문에서 확인할 것 | 왜 먼저 알아야 하나 | 본문이 직접 인용한 원전과 범위 | V2에서의 유지·제안과 작은 확인 |
| --- | --- | --- | --- |
| [§2.2.1, Eq. (20)–(23), Fig. 4](https://arxiv.org/abs/2405.04434v5)는 shared expert와 fine-grained routed expert를 함께 둔다. | routed expert는 token별 top-k, shared expert는 모든 token이 거치는 공통 경로다. 이 둘을 하나의 “expert 수”로 합치면 specialization·redundancy 주장이 흐려진다. | [DeepSeekMoE v1 §3.1–§3.3, Fig. 2](https://arxiv.org/abs/2401.06066v1), 비교 기준 [GShard v1 §2–§3](https://arxiv.org/abs/2006.16668v1). | V2는 DeepSeekMoE를 **채택**한다. 작은 점검: top-k routed output과 shared output이 모두 더해지는 Eq. (20)에서 router가 고르는 대상과 항상 계산되는 대상을 색으로 나눈다. |
| [§2.2.2, Eq. (24)–(26)](https://arxiv.org/abs/2405.04434v5)는 token이 보낼 device를 먼저 `M`개로 제한하고, 그 device 안에서 expert를 고른다. | top-k expert routing만 배워서는 expert가 여러 device에 퍼질 때 all-to-all traffic이 어디서 생기는지 설명할 수 없다. | expert parallel의 conditional computation 배경은 [GShard v1 §3–§4](https://arxiv.org/abs/2006.16668v1). V2의 device score와 top-`M` device rule은 **자체 제안**이므로 V2 §2.2.2가 1차 자료다. | V2는 token의 보내는 device 수를 bound한다. 작은 점검: expert top-k가 6이어도 `M=3` device limit이면 6 expert가 세 device에 어떻게 분포할 수 있는지 그린다. |
| [§2.2.3, Eq. (27)–(31)](https://arxiv.org/abs/2405.04434v5)는 expert/device/communication balance loss를 별도로 둔다. | load balance는 expert count 균등화만이 아니다. device가 받은 token과 device 사이의 communication까지 균형을 보려는 목적이 다르다. | auxiliary loss의 기본 맥락은 [Switch Transformer v1 §2.2](https://arxiv.org/abs/2101.03961v1)와 [GShard v1 §3](https://arxiv.org/abs/2006.16668v1)를 읽는다. V2의 세 loss 식은 자체 설계다. | V2는 세 balance factor를 함께 둔다. 작은 점검: device limit이 sender를 제한해도 receiver가 몰릴 수 있는 이유와 `L_CommBal`이 겨냥하는 대상을 구분한다. |
| [§2.2.4](https://arxiv.org/abs/2405.04434v5)는 capacity factor 1.0에서 device별 low-affinity token을 drop하되, 약 10% sequence는 drop하지 않는 training strategy를 설명한다. | loss는 load를 유도할 뿐 strict capacity guarantee가 아니다. token drop은 학습 효율을 위한 별도 fallback이다. | V2는 [V-MoE](https://arxiv.org/abs/2106.05974v1)를 직접 인용한다. 읽을 범위는 V-MoE v1 §2–§3의 capacity/routing 설명이며, V2의 device-level rule은 자체 방식이다. | V2는 training 중 drop하고 evaluation에는 drop하지 않는다([§3.1.2](https://arxiv.org/abs/2405.04434v5)). 작은 점검: dropped token이 낮은 affinity라는 사실과 semantic importance가 낮다는 보장이 다른 이유를 적는다. |

### 3. pre-training: tokenization·안정화·분산 실행을 함께 읽는다

| DeepSeek-V2 본문에서 확인할 것 | 왜 먼저 알아야 하나 | 본문이 직접 인용한 원전과 범위 | V2에서의 유지·변경과 작은 확인 |
| --- | --- | --- | --- |
| [§3.1.1](https://arxiv.org/abs/2405.04434v5)는 cleaning/filtering, contentious-content filtering, DeepSeek 67B와 같은 100K BBPE tokenizer, 8.1T token을 적는다. | corpus cleaning, bias filtering, tokenizer는 서로 다른 단계다. token 비율은 tokenizer가 바뀌면 그대로 비교할 수 없다. | V2는 BPE algorithm 원전을 직접 인용하지 않는다. [BPE v1 §3.2](https://arxiv.org/abs/1508.07909v1)는 본문이 이름만 쓴 BBPE를 이해하기 위한 **선택 보충**이다. V2는 source/quality classifier·contentious criterion을 추가로 공개하지 않는다. | V2는 tokenizer를 **계승**한다. 작은 점검: 8.1T가 raw document count가 아니라 이 tokenizer로 센 token 수임을 명시한다. |
| [§3.1.2](https://arxiv.org/abs/2405.04434v5)는 random initialization, compression/expert bottleneck 뒤 RMSNorm·scale factor, AdamW, warmup-and-step-decay, gradient clipping, batch-size schedule을 공개한다. | architecture의 narrow latent/expert width는 activation scale도 바꾼다. optimizer schedule을 MLA 식의 일부로 오해하지 않기 위해 별도 읽는다. | [AdamW v3 §2](https://arxiv.org/abs/1711.05101v3)는 본문 직접 인용이다. [RMSNorm v1 §3–§4](https://arxiv.org/abs/1910.07467v1)는 V2가 이름만 쓴 RMSNorm의 **선택 보충**이며 직접 인용은 아니다. V2의 scale factor·batch schedule은 자체 hyperparameter다. | V2는 AdamW를 **사용**하고 bottleneck 안정화 장치를 추가한다. 작은 점검: `β1, β2, weight decay`는 optimizer 설정, compression dimension은 architecture 설정, batch schedule은 training throughput 설정으로 분류한다. |
| [§3.1.3](https://arxiv.org/abs/2405.04434v5)는 16-way zero-bubble pipeline parallelism, 8-way expert parallelism, ZeRO-1 data parallelism, activation recomputation, shared-expert compute와 all-to-all overlap을 적는다. | parameter sharding, layer pipeline, expert placement는 같은 “distributed training”이지만 저장·통신·idle bubble을 각기 해결한다. | ZeRO는 [ZeRO v3 §1–§3](https://arxiv.org/abs/1910.02054v3), expert parallel은 [GShard v1 §3–§4](https://arxiv.org/abs/2006.16668v1), attention kernel은 [FlashAttention-2 v1 §1–§3](https://arxiv.org/abs/2307.08691v1)를 읽는다. internal HAI-LLM/zero-bubble schedule의 세부는 report가 공개하지 않는다. | V2는 tensor parallel 없이 학습했다고 보고한다. 작은 점검: shared expert compute를 all-to-all와 겹친다고 해서 routed expert의 all-to-all 자체가 사라지는 것은 아님을 설명한다. |
| [§3.1.4](https://arxiv.org/abs/2405.04434v5)는 YaRN을 decoupled shared positional key `k^R`에만 적용하고, 4K→128K extension을 별도 32K training으로 수행한다. | long-context는 model의 maximum config 하나가 아니라 positional transform·어느 tensor에 적용하는가·continual training을 모두 포함한다. | [YaRN v3 §2–§4](https://arxiv.org/abs/2309.00071v3), RoPE는 [RoFormer v5 §3.2](https://arxiv.org/abs/2104.09864v5). | V2는 YaRN을 **수정 적용**해 attention entropy scale을 조절한다. 작은 점검: “YaRN applied to all K/V”가 아니라 `k^R`만이라는 본문 조건을 Appendix C MLA 식과 대조한다. |

### 4. chat model: SFT·reward·online RL을 따로 본다

| DeepSeek-V2 본문에서 확인할 것 | 왜 먼저 알아야 하나 | 본문이 직접 인용한 원전과 범위 | V2에서의 유지·변경과 작은 확인 |
| --- | --- | --- | --- |
| [§4.1](https://arxiv.org/abs/2405.04434v5)은 1.5M SFT instance(도움성/안전성)와 quality 개선, IFEval·open-ended 평가를 구분한다. | SFT dataset 크기, helpfulness/safety mixture, evaluation benchmark는 같은 data pool이 아니다. | IFEval의 instruction constraint 평가는 [IFEval v1 §2.1–§2.2](https://arxiv.org/abs/2311.07911v1). V2는 SFT source와 filtering algorithm을 추가로 공개하지 않는다. | V2의 이후 [§4.4](https://arxiv.org/abs/2405.04434v5)는 적은 SFT data에서 IFEval 하락을 관찰한다. 작은 점검: SFT 1.5M이라는 학습 수치와 IFEval score를 인과적으로 같은 것으로 읽지 않는다. |
| [§4.2, Eq. (32)–(34)](https://arxiv.org/abs/2405.04434v5)는 critic을 생략하고 group score로 baseline을 추정하는 GRPO를 쓴다. | PPO-style clipping, reward model score, group-relative advantage, reference KL은 다른 항이다. critic를 안 쓴다는 것이 reward model도 안 쓴다는 뜻은 아니다. | [DeepSeekMath v3 §4.1, Eq. (6)–(8)](https://arxiv.org/abs/2402.03300v3). | V2는 GRPO를 **채택**한다. 작은 점검: one query에서 group output과 각 response의 `r_i`로 mean/std advantage가 생기는 순서를 적는다. |
| [§4.2](https://arxiv.org/abs/2405.04434v5)는 reasoning alignment 뒤 human-preference alignment를 두고, reasoning RM과 helpful/safety/rule RM을 분리한다(Eq. (35)–(36)). | code/math의 compiler/ground truth와 open-ended helpfulness/safety는 검증 가능성이 다르므로 한 scalar reward의 출처를 밝혀야 한다. | preference/RM 기초는 반복하지 않고 [W02의 ranking·PPO 경로](w02.md#preference-ranking)를 재사용한다. V2의 two-stage weighting과 data proportion은 자체 설정이다. | V2는 다중 reward를 **결합**한다. 작은 점검: compiler feedback, human preference, safety response 중 어느 것이 rule/RM/두 방식의 조합인지 표시한다. |
| [§4.2–§4.4](https://arxiv.org/abs/2405.04434v5)는 training/inference parallel strategy가 다른 hybrid engine, vLLM rollout, CPU↔GPU offload schedule과 online-RL 우위를 보고한다. | RL의 policy update와 rollout serving이 같은 parallel layout일 필요는 없다. system throughput이 sample freshness·online/offline choice에 연결된다. | PagedAttention serving 원전은 [vLLM v1 §3](https://arxiv.org/abs/2309.06180v1). hybrid engine/offload schedule의 구현 세부는 V2가 공개하지 않는다. | V2는 online approach가 해당 preference setting에서 offline보다 낫다고 **관찰**했지만 일반 법칙으로 증명하지는 않는다. 작은 점검: policy update GPU memory와 rollout batch throughput이 충돌하는 이유를 한 문장으로 쓴다. |

### 5. 분산·수치 recipe를 이름별로 찾아 읽기

이 절은 §3.1.2–§3.1.3에서 한 문단에 함께 나오는 설정을 “대형 학습 recipe”로 뭉개지 않기 위한 보조 지도다. 아래의 항목은 서로 대체 관계가 아니다.

#### 5.1 AdamW, clipping, batch-size schedule

같은 §3.1.2의 숫자를 세 열로 나눈다: LR schedule은 update 크기, clipping은 한 update의 gradient norm, batch schedule은 한 update에 들어오는 token 수다. AdamW의 원전 범위와 V2 값은 위 §3 표에 있다.

#### 5.2 bottleneck RMSNorm과 scale factor

`MLA cache 감소`와 `narrow representation scale 안정화`를 두 화살표로 그린다. 후자는 global pre-norm을 다시 말하는 것이 아니라 compression/expert-width bottleneck 뒤에 둔 V2의 장치다.

#### 5.3 PP, EP, DP와 recomputation

PP는 layer stage, EP는 MoE expert placement, DP/ZeRO-1은 replica/optimizer state, recomputation은 forward activation 재계산이다. 모두 memory와 communication에 관여하지만 같은 tensor를 같은 방식으로 줄이지 않는다.

#### 5.4 shared-expert overlap과 FlashAttention-2

overlap은 통신을 없애는 것이 아니라 기다리는 동안 독립 compute를 실행하는 schedule이다. routed expert output이 오기 전에 가능한 shared expert compute와 output을 기다리는 combine을 구분한다.

#### 5.5 FP8 parameter serving과 KV-cache quantization

[V2 §3.2.3](https://arxiv.org/abs/2405.04434v5)은 serving parameter를 FP8로 변환하고, MLA가 남긴 KV cache의 각 element를 평균 6 bit까지 quantize한다고 쓴다. MLA는 **token마다 저장할 element 수**, quantization은 **element당 bit 수**를 줄인다. KV quantization의 직접 인용 원전은 [KVQuant v1 §1–§3](https://arxiv.org/abs/2401.18079v1)과 [Atom v1 §1–§3](https://arxiv.org/abs/2310.19102v1)이다. parameter FP8의 format/calibration 세부는 V2가 공개하지 않으므로 §3.2.3만 근거로 둔다. **작은 점검:** actual serving memory를 `element count × bits per element`로 써 본다.

### 읽기 완료 점검

- [ ] MLA의 cache 압축, decoupled RoPE, MQA/GQA의 KV 공유가 각각 무엇을 저장·공유·분리하는지 구별했다.
- [ ] shared/routed expert, device-limited routing, 세 balance loss, token dropping을 식과 device 흐름으로 연결했다.
- [ ] BBPE/data filtering, optimizer/bottleneck scaling, parallelism, YaRN extension, SFT/RL system을 한 architecture label 아래 뭉개지 않았다.
- [ ] MLA의 cached representation 크기와 FP8/KV quantization의 representation bit 수를 별도 축으로 설명했다.
