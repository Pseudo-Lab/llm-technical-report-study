# LFM2: 기기 제약에서 구조·학습 목표까지

[W14 학습목표](../weeks/w14/README.md) · [배경 읽기 지도](README.md)

LFM2를 “짧은 convolution 모델” 또는 “Top-K KD 모델”로만 읽으면 보고서의 설계 단위가 사라진다. 저자들이 실제로 묶은 것은 **기기에서 측정한 구조 탐색**, **local/global token mixing**, **작은 모델의 pre-/post-training**이다. 아래 경로는 LFM2 본문이 직접 말하거나 직접 인용하는 원전만 잇는다. 원전이 없는 세부 recipe는 LFM2 본문에서만 확인한다.

## 1. Proxy 점수에서 hardware-in-the-loop Pareto 탐색으로

[LFM2 §2.1](https://arxiv.org/abs/2511.23404v1)는 후보마다 동일한 runtime·quantization·prompt·tokenizer 설정으로 device에서 측정한다. quality는 50개 이상 내부 과제, latency는 TTFT·p50/p95 decode·prefill throughput, memory는 4K/32K의 peak RSS이며, 한 예산을 넘는 후보는 버린 뒤 quality–latency–memory Pareto frontier의 hypervolume improvement로 남긴다. 이때 **Pareto 우위**란 세 축 중 적어도 하나가 좋고 나머지가 모두 나쁘지 않은 경우다. benchmark 정확도 하나와 같은 뜻이 아니다.

저자들이 직접 비교하는 [STAR v1 §4–§4.1·§5.3–§5.4](https://arxiv.org/abs/2411.17800v1)는 perplexity·parameter/cache proxy와 evolutionary search를 쓴다. LFM2의 주장은 “search heuristic이 새롭다”가 아니라 proxy가 downstream score와 release runtime의 latency/RSS로 잘 전이하지 않았으므로 **목적 함수를 실기기로 바꾸었다**는 것이다.

**작은 점검.** A가 quality/latency/RSS=(80, 10ms, 1GB), B가=(81, 12ms, 0.9GB)이면 어느 하나도 다른 하나를 지배하지 않는다. 이 사례만으로 A나 B가 “더 좋은 architecture”라고 결론 내리지 말고, 제품의 예산을 먼저 써 본다.

## 2. minimal hybrid: gated short convolution, GQA, SwiGLU

[LFM2 §2.2·Fig. 2·Table 1](https://arxiv.org/abs/2511.23404v1)는 대부분의 layer에 gated short convolution, 소수 layer에 GQA, position-wise MLP에 SwiGLU를 둔다. 모든 layer의 pre-norm RMSNorm, attention의 RoPE/QK-Norm은 구성값이지만 이 보고서의 새 주장은 아니다.

### Gated short convolution은 무엇을 계산하는가

입력 `h∈R^{L×d}`에 대해 LFM2는 `Linear(h)`를 `B,C,h̃` 세 채널로 나누고,

`y=B⊙h̃`, `z=Conv_k(y)`, `o=Linear_out(C⊙z)`

를 쓴다. 여기서 `Conv_k`는 channel마다 sequence 축의 폭 `k`만 섞는 depthwise 1D convolution이다. `B`는 convolution **전**, `C`는 **후**에 입력 의존 gate를 건다. 따라서 kernel 3이면 해당 위치가 local 이웃만 직접 섞는다는 뜻이며, gate가 있다고 해서 long-range retrieval을 하는 것은 아니다.

[Hyena v3 §2.1·§3.1–§3.4](https://arxiv.org/abs/2302.10866v3)는 short convolution을 long implicit convolution/long filter가 든 hybrid의 한 부분으로 설명한다. LFM2 §2.1–§2.2는 그 전체 operator를 그대로 채택한 것이 아니라, short-conv 부분만 남기고 장거리 retrieval은 드문 GQA에 맡긴 결과를 보고한다. `Hyena = LFM2`라고 읽지 않는다.

### GQA와 MLP가 맡은 나머지 역할

[GQA v3 §2.1–§2.2](https://arxiv.org/abs/2305.13245v3)에서 query head 여러 개가 하나의 K/V group을 공유하는 방식을 먼저 확인한다. GQA는 multi-head query를 유지하면서 KV traffic/cache를 줄인다. LFM2의 “소수 GQA”는 local convolution이 못하는 global retrieval을 보완하는 층 배치이지, short convolution이 attention을 수학적으로 근사한다는 주장이 아니다.

[GLU Variants v1 §2–§3.1](https://arxiv.org/abs/2002.05202v1)에서 `Swish(xW)⊙xV`형 gate를, [RMSNorm v1 §3–§4](https://arxiv.org/abs/1910.07467v1)과 [RoFormer v5 §3.2](https://arxiv.org/abs/2104.09864v5)에서 각각 norm과 rotary position을 확인한다. 이는 LFM2가 새로 발명했다고 적은 구성요소가 아니라, Table 1의 backbone을 읽기 위한 선수 지식이다.

**QK-Norm의 국소 용례.** LFM2 §2.2는 attention block에 QK-Norm을 둔다고만 기록한다. Q와 K의 크기가 지나치게 커지면 dot product logit도 커져 softmax가 너무 뾰족해질 수 있으므로, score 전에 Q/K를 정규화하는 안정화 장치로 이해한다. short convolution의 gate나 RMSNorm의 block 입력 정규화와는 적용 위치가 다르다. LFM2는 이 기법의 새 식·ablation을 제공하지 않으므로, 이 주차에서 QK-Norm의 성능 원인을 LFM2의 핵심 주장으로 만들지 않는다.

**작은 점검.** `Conv_3`가 1,000번째 token에서 직접 보는 과거 token의 범위와, 그 token이 GQA layer에서 causal attention으로 볼 수 있는 범위를 나란히 그린다. KV cache를 줄이는 직접 원인이 “모든 convolution”인지 “GQA의 KV group 수”인지 분리한다.

## 3. Sparse MoE가 추가될 때: total parameter와 active parameter

[LFM2 §2.3·Table 1](https://arxiv.org/abs/2511.23404v1)은 8B-A1B에서 첫 두 layer는 dense로 두고, 이후 dense MLP를 32개 SwiGLU expert의 sparse MoE로 바꾼다. token마다 normalized-sigmoid router가 Top-4 expert를 선택한다. 그러므로 8.3B는 저장되는 total parameter, 약 1.5B는 token 하나에서 활성화되는 parameter다. “MoE가 메모리를 없앤다”가 아니라 per-token compute가 먼저 문제인 device regime에서 active compute를 줄인다는 범위의 주장이다.

모든 expert가 같은 token을 받으면 specialization이 무너진다. [DeepSeekMoE v1 §3.1–§3.2·Fig. 2](https://arxiv.org/abs/2401.06066v1)에서 routed/shared expert와 fine-grained expert의 역할을 확인하고, LFM2 §2.3의 adaptive routing bias를 돌아온다. LFM2는 expert 수·Top-k·처음 두 dense layer를 공개하지만, 본문만으로 router가 어떤 의미론적 domain으로 나뉜다고 추정해서는 안 된다.

**작은 점검.** total 32 expert 중 Top-4만 실행하면 어느 수가 FLOPs에, 어느 수가 checkpoint storage에 먼저 영향을 주는지 표시한다. 같은 Top-4라도 모든 token이 같은 4 expert에 몰리면 왜 계산량은 그대로인데 모델 용량의 이점은 사라지는지 설명한다.

## 4. tokenizer와 pre-training: 길이·형식·teacher signal을 혼동하지 않기

[LFM2 §2.2](https://arxiv.org/abs/2511.23404v1)는 65,536 vocabulary의 byte-level BPE를 pre-training mixture로 학습하고, JSON/code-like 자료와 FIM·tool-call·ChatML special token을 둔다. [BPE v1 §3.2](https://arxiv.org/abs/1508.07909v1)는 **문자/기호열**에서 빈번한 pair를 반복 병합해 subword vocabulary를 만드는 알고리즘이다. LFM2가 그 입력 단위를 UTF-8 byte로 바꾼 것은 별도 adaptation이다. byte 단위가 OOV 없이 문자 집합을 공유하는 이유는 간접 배경인 [BBPE v2 §1·§3](https://arxiv.org/abs/1909.03341v2)에서 확인하고, LFM2의 특수 token/interface 설계는 여전히 §2.2 자체에서 읽는다.

[LFM2 §3.1–§3.2](https://arxiv.org/abs/2511.23404v1)는 dense model의 10T token·4K pre-training 뒤, 자연 장문을 포함한 고품질 1T token·32K mid-training을 공개한다. context window 증가와 data quality 증가는 같은 knob가 아니다. code의 절반에는 [FIM v1 §3·§3.1–§3.2](https://arxiv.org/abs/2207.14255v1) objective를 쓰므로, prefix/suffix에서 가운데를 예측하는 훈련과 일반 left-to-right next-token prediction도 구분한다.

### 저장하지 않은 teacher tail을 다루는 Top-K KD

LFM2는 LFM1-7B teacher의 매 위치 Top-32 logit만 저장한다. [Hinton et al. v1 §2](https://arxiv.org/abs/1503.02531v1)의 soft target/temperature를 출발점으로 하고, LFM2 §3.3·식 (1)–(2)에서 teacher Top-K set `T`에 대한 mass `P(T|x_c)`의 Bernoulli KL과 `T` 안 conditional KL을 분리한다. temperature는 conditional 항에만 적용한다. 저장하지 않은 tail을 포함한 full KL을 계산했다고 말하면 안 된다; `τ=1`에서만 이 목적은 full forward KL의 lower bound이며, `τ>1`은 tempered surrogate다(Appendix A).

**작은 점검.** vocabulary 6개에서 teacher Top-2만 저장한 경우를 그린다. student가 Top-2에 주는 총 mass가 같아도 두 token 사이의 비율이 다를 수 있음을 보이고, mass 항과 conditional 항을 따로 써 본다.

**선택 읽기.** LFM2의 VL(§5)·Audio(§6)·ColBERT retrieval(§7)은 text-core 세 목표의 선수 지식에는 포함하지 않는다. retrieval 확장이 필요할 때만 [§7.1–§7.2·식 (6)–(8)](https://arxiv.org/abs/2511.23404v1)과 [ColBERT v1 §3](https://arxiv.org/abs/2004.12832v1)의 late-interaction MaxSim·score distillation을 별도 읽는다.

## 5. SFT·direct alignment·model merging은 서로 다른 후학습 단계

[LFM2 §4.1–§4.3](https://arxiv.org/abs/2511.23404v1)는 (1) chat template와 downstream skill을 위한 SFT, (2) SFT checkpoint의 on-policy sample과 offline preference를 쓰는 direct preference alignment, (3) candidate model을 평가·결합하는 merging을 분리한다. SFT의 curriculum은 여러 model의 empirical success probability로 easy→hard 순서를 예측하는 방식(§4.2.1)이다. preference pair의 chosen/rejected response와 SFT에서 imitation하는 chosen response도 같은 data 역할이 아니다.

LFM2 §4.3의 length-normalized objective는 [DPO v1 §3](https://arxiv.org/abs/2305.18290v1)의 reference-relative log probability를 출발점으로 하되, 보고서의 식 (3)–(5)에서 response length로 relative/absolute term을 나눈 일반형을 사용한다. DPO를 PPO라고 바꾸어 부르거나, model merging을 parameter average라고 단정하지 않는다. 병합 recipe의 구체적 candidate와 selection은 LFM2 §4.4에서 확인한다.

**작은 점검.** 같은 prompt에서 SFT checkpoint가 낸 5개 response를 LLM jury가 순위화해 chosen/rejected를 만든 뒤, SFT에는 chosen만 들어갈 수 있고 direct alignment에는 pair가 들어갈 수 있음을 표시한다. 그리고 §4.4의 model soup·task arithmetic·TIES/DARE/DELLA 후보는 *추가 training 없이* parameter-space에서 결합하는 후보군이지, reward model이 아니라는 점을 확인한다.

## 연결 주차와 범위

- **W14:** 이 문서의 §1–§4가 architecture search, hybrid block, Top-K KD의 직접 선수 지식이다. VL·Audio는 text-core 범위에서 제외했고 ColBERT는 선택 경로다.
- **W16:** tokenizer와 sparse MoE의 비교는 필요할 때만 Solar Open의 별도 tokenizer/MoE 설계와 대조한다. 두 보고서가 동일한 data recipe를 썼다는 뜻은 아니다.

## 원전 사용 원칙

- 위 text-core 수식·구성값·제안 범위는 [LFM2 v1](https://arxiv.org/abs/2511.23404v1) §2–§4와 Appendix A의 직접 근거다. §5–§7 응용 model은 선택 읽기 외에는 이 주차의 범위에 포함하지 않는다.
- Hyena, GQA, GLU, RMSNorm, RoPE, BPE, FIM, Hinton, DPO는 LFM2 본문이 필요로 하거나 직접 인용하는 이전 기법이다. 각 원전의 일반 성질을 LFM2의 실험 결과로 읽지 않는다.
