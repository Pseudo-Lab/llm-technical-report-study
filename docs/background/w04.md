## 이번 주 읽기 범위

이 문서는 Qwen2.5 v2와 Qwen3 v1의 **본문 인용과 직접 설명**을 먼저 따라, Qwen2.5가 확장한 tokenizer/data/post-training recipe와 Qwen3가 실제로 계승·변경했다고 쓴 부분을 나눈다. 본문에 이름만 나오고 원전을 인용하지 않은 일반 개념은 ‘선택 보충’으로만 표시한다.

공통 읽기는 [주차별 분담표](workload.md)에 적힌 대상 본문으로 시작한다. 담당 심화에서는 아래 구성요소 중 한 갈래와 필요한 선행 원전의 지정 절을 읽는다.

**연결 자료:** [Qwen1.5 → Qwen2 배경](w03.md)

## 본문 구성요소와 선행 개념

<a id="qwen25-handoff"></a>
### 0. Qwen2.5의 확장을 Qwen3의 직접 채택으로 과장하지 않는다

Qwen2.5는 Qwen2 dense decoder를 유지하면서 BBPE control token, long-context training, task-specific SFT data와 offline/online RL을 넓혔다. Qwen3는 Qwen2.5를 여러 곳에서 data/model lineage로 인용하지만, 그 모든 filtering threshold나 synthesis algorithm을 다시 공개하지 않는다. 아래 표는 W03에서 이미 읽은 Qwen2 기반과 Qwen2.5의 고유 확장을, Qwen3가 직접 말한 계승 범위에만 연결한다.

### 1. 먼저 계승과 변경을 분리한다

Qwen3 [§2, Table 1–2](https://arxiv.org/abs/2505.09388v1)는 dense와 MoE를 함께 공개하지만, 모든 구성요소가 Qwen3의 새 제안은 아니다. [W03의 Qwen1.5→Qwen2 구조 비교](w03.md#qwen-architecture)와 위 [Qwen2.5 handoff](#qwen25-handoff)에서 GQA·RoPE·RMSNorm·BBPE 계보를, [W01 LLaMA block recipe](w01.md#llama1-recipe)에서 SwiGLU/pre-RMSNorm의 기본 위치를 먼저 확인한 뒤 아래의 **Qwen3 변경**을 읽는다.

### 2. 36T token이라는 숫자 앞의 데이터·단계

Qwen3 [§3.1–§3.2](https://arxiv.org/abs/2505.09388v1)는 데이터 원천, annotation, mixture, sequence-length curriculum을 함께 바꾼다. “synthetic data를 더 넣었다”만으로는 어떤 품질 신호와 어떤 단계에서 바뀌는지 알 수 없다.

| Qwen3 본문에서 확인할 것 | 왜 먼저 알아야 하나 | 본문이 직접 인용한 원전과 범위 | Qwen3에서의 유지·변경과 작은 확인 |
| --- | --- | --- | --- |
| [§3.1](https://arxiv.org/abs/2505.09388v1)은 PDF-like document를 Qwen2.5-VL로 OCR하고 Qwen2.5로 정제하며, Qwen2.5/Math/Coder로 textbook·QA·instruction·code를 합성한다고 설명한다. | OCR → refinement → task-format synthesis는 같은 “synthetic”이라는 단어 아래에서도 오류 원인과 검증 기준이 다른 세 단계다. | Qwen3 §3.1이 이 모델 사용과 pipeline을 1차 근거로 제시한다. filter threshold·세부 알고리즘은 추가로 공개하지 않는다. 위 [Qwen2.5 data/synthesis handoff](#qwen25-handoff)는 instruction·math·code의 원전 경로를 보완한다. | Qwen3의 고유 주장은 trillions 규모의 OCR/refinement와 여러 format 합성의 **사용**이다. 작은 점검: OCR 오인식, refinement 환각, 합성 instruction 오류를 하나씩 적고 같은 quality score로 처리할 수 없는 이유를 말한다. |
| [§3.1](https://arxiv.org/abs/2505.09388v1)은 30T+ token에 교육 가치·field·domain·safety를 annotate하고, source/domain 단위가 아니라 **instance-level** mixture를 proxy-model ablation으로 최적화한다고 쓴다. | data mixture는 “어느 corpus를 넣나”와 “label이 붙은 sample 비율을 어떻게 고르나”가 다른 문제다. | 비교 대상으로 직접 인용한 [DoReMi v1 §2–§3](https://arxiv.org/abs/2305.10429v1)는 domain reweighting을 설명한다. Qwen3은 annotation schema·proxy ablation 식·label taxonomy를 추가로 공개하지 않는다. | Qwen3은 source/domain-level 최적화와 달리 fine-grained label을 쓴다고 **주장**한다. 작은 점검: 같은 web source의 두 문서가 education label에서 다를 수 있는 예를 만들고, source-level weight가 이를 표현하지 못하는 이유를 쓴다. |
| [§3.2](https://arxiv.org/abs/2505.09388v1)는 S1 general 4K → S2 reasoning 4K(고품질 5T, STEM/code/reasoning/synthetic 비중↑, LR decay 가속) → long-context 32K로 나눈다. | 길이 curriculum, data mixture, LR schedule은 모두 “stage”라는 말 아래 묶이지만 서로 다른 control knob다. | Qwen3은 Qwen2.5 scaling-law practice를 언급하지만 stage-specific proxy-model prediction 식은 공개하지 않는다. 이 report의 §3.2를 설정의 1차 근거로 읽는다. | 4K S2가 reasoning data 비율을 바꾸는 단계이고, final stage가 sequence length를 32K로 바꾸는 단계임을 분리한다. 작은 점검: S2의 4K sample을 long-context sample이라고 부르면 왜 틀리는지 말한다. |
| [§3.2와 Appendix A.1.1](https://arxiv.org/abs/2505.09388v1)는 RoPE base 10,000→1,000,000의 ABF, YaRN, DCA, 32K long corpus와 inference 4× extension을 함께 둔다. | base-frequency 수정, long-context continual pretraining, inference-time DCA는 모두 문맥을 길게 하지만 작동 위치가 다르다. | ABF는 [Effective Long-Context Scaling v1 §4.1, Fig. 4–5](https://arxiv.org/abs/2309.16039v1), YaRN은 [YaRN v3 §2–§4](https://arxiv.org/abs/2309.00071v3), DCA는 [DCA v2 §2–§3.3, Fig. 2](https://arxiv.org/abs/2402.17463v2)를 읽는다. | Qwen3은 ABF와 long-context pretraining을 **적용**하고, YaRN·DCA로 inference capacity를 확장한다. 작은 점검: “32K로 학습”, “128K까지 처리”, “RoPE angle/base 변경”을 각각 하나의 상자에 넣어 같은 숫자로 합치지 않는다. |

### 3. post-training은 thinking fusion만이 아니다

Qwen3 [§4.1–§4.6](https://arxiv.org/abs/2505.09388v1)는 long-CoT cold start, reasoning RL, thinking mode fusion, general RL, strong-to-weak distillation을 **순서가 있는 별도 단계**로 둔다. W04의 세 Action Item은 fusion·budget·distillation을 깊게 다루고, 아래 표는 그 앞뒤의 선행 조건을 연결한다.

| Qwen3 본문에서 확인할 것 | 왜 먼저 알아야 하나 | 본문이 직접 인용한 원전과 범위 | Qwen3에서의 유지·변경과 작은 확인 |
| --- | --- | --- | --- |
| [§4.1](https://arxiv.org/abs/2505.09388v1)은 verifier/reference answer/code test가 있는 problem을 long-CoT cold start에 쓰고, query와 response를 별도로 filtering한다. | answer correctness, reasoning quality, validation contamination은 한 filter가 아니다. cold start가 reasoning RL 전에 왜 작게 유지되는지도 여기서 나온다. | long-CoT query/response filtering의 N, Pass@N, human review rule은 Qwen3의 자체 절차다. report §4.1을 직접 읽고 외부 표준 알고리즘처럼 일반화하지 않는다. | Qwen3은 Qwen2.5-72B-Instruct로 쉬운 query를 빼고 QwQ-32B response를 여러 개 만든다. 작은 점검: final answer는 맞지만 생각·summary가 모순된 trace를 response filter가 왜 버리는지 설명한다. |
| [§4.2](https://arxiv.org/abs/2505.09388v1)는 3,995 query–verifier pair와 GRPO, large batch·many rollouts·off-policy sample efficiency·entropy control을 적는다. | verifier가 reward를 만들고, rollout group이 advantage를 만들며, entropy는 exploration을 조절한다. 이를 SFT label과 같다고 보면 RL 단계가 사라진다. | [DeepSeekMath v3 §4.1, Eq. (6)–(8)](https://arxiv.org/abs/2402.03300v3)는 critic 없이 group reward로 baseline을 만드는 GRPO를 제시한다. Qwen3의 verifier-pair 수, entropy schedule은 자체 설정이다. | Qwen3은 GRPO를 **채택**한다. 작은 점검: “정답 verifier 하나”와 “한 query에서 생성한 여러 rollout의 상대 advantage”가 각각 어느 곳에 들어가는지 화살표로 잇는다. |
| [§4.3](https://arxiv.org/abs/2505.09388v1)는 reasoning-RL model에 continual SFT를 해 thinking/non-thinking을 fusion하고, empty `<think>` block과 마지막 flag 우선 규칙을 사용한다. | mode fusion의 template은 UI 장식이 아니라 train/inference의 control token contract다. | template은 Qwen3의 자체 설계이며, 위 Qwen2.5의 BBPE/control-token 범위는 token interface의 배경일 뿐 같은 template의 직접 원전은 아니다. | thinking data는 Stage-2 model의 rejection sampling, non-thinking data는 curated task/checklist라는 점을 구분한다. 작은 점검: multi-turn에 `/think`, `/no think`가 모두 있으면 왜 마지막 flag가 mode를 결정하는지 Table 9에 대조한다. |
| [§4.4](https://arxiv.org/abs/2505.09388v1)는 instruction/format/preference/agent/RAG 등 20+ task에 rule-based, model-based, hybrid reward를 나눈다. | “RL reward” 하나로 부르면 checker가 가능한 task와 open-ended preference task의 신뢰도 차이를 놓친다. | instruction-following rule reward는 Qwen3이 직접 인용한 [Lambert et al. v1 §2–§3](https://arxiv.org/abs/2402.04792v1)를 읽는다. Qwen3의 20+ task taxonomy와 hybrid combination의 정확한 weight는 본문에 공개되지 않았다. | agent rollout은 실제 environment execution feedback과 multi-turn interaction을 허용한다. 작은 점검: format checker가 가능한 output과 free-form helpfulness를 각각 rule/model/hybrid 중 어디에 둘지 쓰고 이유를 말한다. |
| [§4.5·§4.7 Table 21](https://arxiv.org/abs/2505.09388v1)는 `/think`·`/no think` response의 off-policy distillation 뒤 학생 생성 prefix에서 teacher logit을 맞추는 on-policy distillation을 둔다. | teacher response를 모방하는 supervised phase와 student가 실제 갈 prefix에서 distribution을 맞추는 phase는 다르다. | Qwen3은 on-policy KL/distillation의 별도 선행 원전을 특정하지 않는다. §4.5의 two-phase 정의와 §4.7의 같은-checkpoint RL 비교가 이 report의 1차 근거다. | Qwen3의 강한 주장은 작은 model이 네 단계 전체를 독립 수행하지 않고 두 mode를 함께 distill할 수 있다는 것이다. 작은 점검: teacher forcing prefix와 student-generated prefix가 다르면 어느 쪽에서 exposure mismatch가 생기는지 적는다. |

### 4. 이 주차에서 확인할 경계

- Table 1–2의 **parameter/active parameter/context length**는 서로 다른 비용 축이다. MoE의 total parameter가 크다고 token당 FFN compute가 모두 그만큼 늘었다는 뜻은 아니다.
- [§4.7, Table 22](https://arxiv.org/abs/2505.09388v1)는 fusion과 general RL의 단계를 비교하지만, data·reward·model effect를 완전히 분리한 인과 실험은 아니다. 각 단계의 수치를 하나의 기법만의 효과로 단정하지 않는다.
- [Appendix A.1.1](https://arxiv.org/abs/2505.09388v1)는 long-context 평가에서 thinking budget을 8,192로 둔다. 이는 input context capacity와 output reasoning budget이 별개의 제어값임을 보여 주는 설정이며, 모든 과제의 최적 budget을 증명하지 않는다.

### 5. Qwen3 본문에서 같이 나오는 용어를 분해하기

#### 5.1 QK-Norm은 pre-RMSNorm과 다른 안정화 위치다

실제 위치만 그리면 된다: `x → pre-RMSNorm → Q,K projection → QK-Norm → QK^T`. 앞 norm은 sublayer 입력 `x`, 뒤 norm은 projected `Q,K`를 다룬다. 원전 범위와 Qwen3의 채택 여부는 위 §1 표에 있다.

#### 5.2 shared expert 제거와 global-batch LBL은 별개다

`shared expert 제거`는 FFN 경로 구성, `global-batch LBL`은 routed-expert 선택 빈도를 합산하는 범위다. 같은 MoE 설정으로 부르더라도 한 변경이 다른 변경을 자동으로 만들지 않는다.

#### 5.3 OCR, refinement, synthesis, annotation은 다른 품질 신호다

예를 들어 PDF 표의 숫자가 틀리면 OCR 오류, 내용은 맞지만 문장이 깨지면 refinement 문제, 새 QA의 정답이 틀리면 synthesis 문제, 같은 문서의 교육 가치가 다른 것은 annotation 문제다. 따라서 이 넷을 하나의 “data quality” score로 읽지 않는다.

#### 5.4 S1/S2/long-context stage에서 바뀌는 knob

stage별 한 줄 메모는 `S1: 4K/general`, `S2: 4K/reasoning mixture+LR`, `final: 32K/long corpus`다. 따라서 data mixture, LR, sequence length는 독립 열로 기록하고, inference-time DCA를 final pre-training 단계로 잘못 넣지 않는다.

#### 5.5 cold start, verifier, GRPO, general-RL reward

두 흐름을 나란히 쓴다: math는 `verifier → rollout reward → group advantage → policy update`, open-ended writing은 `model judge → reward → policy update`다. verifier는 GRPO algorithm도, general reward taxonomy도 아니다.
