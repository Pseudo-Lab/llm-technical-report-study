# Qwen3.8-Next: recurrent memory·sparse retrieval·residual·optimizer를 함께 읽기

[W10 학습목표](../weeks/w10/README.md) · [배경 읽기 지도](README.md)

[Qwen3.8-Next v1](https://arxiv.org/abs/2608.30320v1)은 GDN, QSA, Gated Residual(GR), n-gram embedding, Muon을 각각 독립 부품으로 나열하지 않는다. 이들은 attention FLOPs, long-range memory, residual traffic, sparse parameter capacity, large-batch stability를 함께 바꾸는 recipe다. 아래는 본문 §2–§3과 §4–§5를 **직접 읽어** 정리한 경로다. 직접 인용·비교된 원전과, 본문이 이름만 사용한 개념의 선택 보충 원전을 구분했다.

## 모델 안에서 무엇이 어디에 놓이는가

Fig. 1과 §2를 먼저 본다. token mixer는 layer-wise GDN과 periodic global attention을 섞고, continued pre-training(CPT)에서 global attention 일부를 QSA로 바꾼다. MoE는 FFN이고, GR은 그 sublayer 전후의 widened residual state이며, n-gram은 Layer 2에서 residual에 주입되는 sparse embedding memory다. 따라서 “n-gram이 KV cache를 대체한다”나 “GDN이 QSA를 선택한다”는 설명은 틀리다.

### GR은 AttnRes나 VWN을 채택한 이름이 아니다

Qwen §2.2의 비교 대상인 **Attention Residual (AttnRes)**은 이전 sublayer output에 attention해 읽을 경로를 정한다. Full AttnRes는 이전 모든 sublayer를, Block AttnRes는 `S`개 sublayer output을 먼저 합친 block representation을 대상으로 삼으므로 block 요약은 더 적은 후보와 맞바꾼 근사다. Table 6의 비교는 이 두 설계와 GR의 **대상 보고서 내 ablation**이며, Qwen3.8이 AttnRes를 채택했다는 뜻은 아니다.

VWN도 같은 widened-residual 계열이지만 token embedding을 여러 좁은 segment로 나누어 finer-grained read/write를 노린다. HC/mHC는 branch-scalar read/write와 `H_res` mixing에, GR은 channel-wise read gate와 `H_res` 제거에 capacity를 쓴다. 따라서 셋을 모두 “residual branch를 여러 개 둔다”로만 합치면 어떤 memory traffic과 어떤 read granularity를 바꿨는지 사라진다.

### Batch-size warmup은 Qwen이 다시 검증한 training recipe다

Qwen §3.2에서 batch-size warmup은 초기에는 critical batch size가 작아 작은 batch로 시작하고, training이 진행되며 이를 키우는 관행이다. 작은 초기 batch와 그에 맞춘 learning rate는 초기 안정화에 쓰이지만, Qwen은 Muon의 large-batch data efficiency와 sparse MoE에서 expert별 token diversity가 필요한 조건을 근거로 이를 다시 시험했고 production recipe에서는 제거했다. 이것은 warmup 일반론의 폐기가 아니라 **이 architecture·optimizer·MoE 조건에서의 채택 판단**이다.

## GDN 계산을 GPU에서 실행하는 FlashQLA

[Qwen §2.1.1 “Kernel Efficiency”](https://arxiv.org/abs/2608.30320v1)는 **FlashQLA**를 TileLang 기반 fused linear-attention kernel library로 소개하고 [공식 구현](https://github.com/QwenLM/FlashQLA)을 연결한다. 선수 개념인 **kernel fusion**은 여러 GPU 연산을 묶어 중간 결과의 메모리 왕복과 실행 호출을 줄이는 방식이다. GDN은 계산 규칙이고 FlashQLA는 그 계산을 효율적으로 실행하는 구현이므로 두 층위를 나누어 읽는다.

본문의 속도 비교는 NVIDIA GPU의 여러 설정에서 FLA Triton 대비 forward 2–3배, backward 약 2배라는 kernel benchmark다. 전체 모델 학습이나 모든 GPU에서 같은 배속을 보장하는 값은 아니다. 보고서는 kernel 내부의 세부 변환식을 제시하지 않으므로 **필수 범위는 이 문단**, 구현 확장은 공식 저장소의 선택 읽기로 둔다. **점검:** 같은 GDN 식을 사용하는 두 구현의 FLOPs가 유사해도 memory traffic이나 launch 횟수 때문에 시간이 달라질 수 있는가?

## §2에 반복해서 나오는 norm·gate·MoE·FP8의 범위

### q/k L2 norm, zero-centered RMSNorm, GatedNorm은 같은 정규화가 아니다

Qwen §2.1.1의 q/k L2 norm은 query와 key 각각을 unit-length에 맞춰 recurrent update의 rank-one transition이 activation 크기에 따라 과도하게 커지지 않게 한다. 이는 `q·k`의 방향 비교를 안정시키는 **attention/GDN 입력** 정규화다. 같은 절의 RMSNorm은 vector의 RMS로 output scale을 조절하는 **layer/residual** 정규화이며, Qwen은 zero-centered variant를 써 RMSNorm weight growth를 제약한다고만 명시한다. 그 variant의 정확한 parameterization은 이 보고서가 새로 정의하지 않으므로 §2.1.1이 가리키는 Qwen3-Next 선례를 확인하기 전에는 일반 RMSNorm 식으로 환원하지 않는다.

GR의 GatedNorm(§2.2 식 (29))은 RMSNorm 뒤에 low-rank `SiLU`–sigmoid gate를 곱해 channel별 read magnitude를 다시 조절한다. 즉 `L2 q/k`는 GDN state write의 입력 크기, RMSNorm은 residual/출력 scale, GatedNorm은 residual branch에서 무엇을 얼마나 읽을지를 다룬다. **점검:** GatedNorm이 있다는 사실만으로 q/k norm이나 RoPE가 불필요해지는가? 각각 적용 위치와 해결하는 failure mode가 다르므로 아니다.

### MoE와 load balance는 W10에서 ‘공개된 범위’까지만 읽는다

Qwen은 Fig. 1·Table 1·§2.2–§3에서 model을 `25B-A3B MoE` 등으로 부르고 MoE expert와 n-gram table 사이 parameter allocation을 ablate한다. 하지만 이 보고서는 router score 식, top-k, shared/routed expert 구성, auxiliary loss 또는 load-balancing update를 **설명하지 않는다**. 따라서 W10에서 MoE는 “FFN의 sparse capacity와 active-parameter budget”이라는 architecture context까지가 본문 근거다. routing·balance를 DeepSeek-V3/V4의 식으로 채워 Qwen3.8의 설정인 양 설명하지 않는다. 그 개념은 보고서 자체가 공개한 경우에만 별도 주차 배경이 된다.

### FP8 residual state는 full FP8 training 주장과 다르다

Qwen §2.2의 FP8은 widened GR state를 BF16 대신 저장해 moved bytes를 절반으로 줄이는 **inference-memory traffic** 선택이다. gate가 write magnitude를 bound하므로 residual value range가 low precision에 맞는다는 것이 저자들의 이유이고, quality 저하가 거의 없다는 실험 결과로 채택했다. 이는 §3.1 Muon의 Newton–Schulz iteration이나 model 전체 weight/activation이 FP8이라는 주장과 다르다. **점검:** 같은 hidden state라도 “저장 format”, “GEMM compute format”, “optimizer master weight” 중 무엇을 FP8로 말하는지 문장마다 표시한다.

## 식을 따라가는 네 가지 작은 예

### QSA: 16 → 4 → 2 blocks → 8 tokens (+ 최신 tail)

Qwen §2.1.2의 block indexer를 과거 key 16개, micro-block 크기 `r=4`로 **교육용으로만** 축약해 본다. 16 key는 순서를 보존한 4 complete block key가 된다. query가 4 block을 score해 top-2를 고르면, 선택된 block의 원래 token index 8개를 core attention 후보로 다시 펼친다. 아직 완결되지 않은 최신 block은 average-pool block key로만 판단하면 최신 local information을 잃을 수 있으므로 indexer top-k와 별개로 candidate에 남는다. 이 `16 → 4 → 2 → 8 + tail`은 **후보를 줄이는 index procedure**이며, V2의 MLA에서 줄이는 latent KV **저장 표현**과 같은 연산이 아니다. 실제 Qwen 설정의 top-k는 512이므로, 교육용 top-2를 모델 hyperparameter로 읽지 않는다.

### GDN: 잊기와 correction은 다른 gate다

한 head의 state를 Qwen의 구현 convention대로 `S_t∈R^(d_k×d_v)`라고 둔다. 따라서 read는 `y_t=S_t^⊤q_t`이며, 이는 원전과 전치된 convention임을 본문이 명시한다. 교육용 1차원 축약에서 기존 `S=2`, `k=1`, 목표 `v=5`, decay `α=.5`, write gate `β=.5`라면 decay 뒤 state와 현재 key가 읽는 값은 `1`이다. 새 value와의 error는 `5−1=4`이고, state에는 `1+.5×4×1=3`이 남는다. 원문의 multi-head·short convolution·L2 q/k·output gate 전체를 대체하는 식은 아니지만, `α`가 기존 연합의 보존량이고 `β`가 이미 읽힌 값을 뺀 correction의 기록량임을 보여 준다. 식 (1)–(11)으로 돌아가 이 두 역할을 분리해 확인한다.

### GR: 4개 branch를 모두 같은 방식으로 섞지 않는다

branch가 4개, hidden width가 `d`라면 Qwen의 GR read gate는 branch×channel인 `4×d`이고 write gate는 branch마다 하나인 `4` scalar다. 따라서 어느 channel을 어느 branch에서 읽을지는 세밀하게 바꾸지만, 새 residual을 어느 branch에 얼마나 쓸지는 branch 단위로 정한다. `H_res` mixing을 남긴 HC/mHC와 이 선택을 구분한다. 이 dimension 차이는 “GR이 branch를 늘렸다”보다 왜 memory traffic과 path selectivity가 달라지는지를 설명한다.

### n-gram table은 tokenizer도 KV cache도 아니다

Qwen이 scale 기준으로 쓰는 base tokenizer vocabulary `V=250K`와 n-gram table `50V`는 같은 종류의 vocabulary count가 아니다. 전자는 input token vocabulary의 크기, 후자는 local token sequence hash가 주소화하는 sparse parameter table이다. 본문은 tokenizer의 merge 방식은 공개하지 않는다. Layer 2 배치는 layer 1을 계산하는 동안 host에서 table vector를 prefetch하려는 시스템 선택이다. 따라서 table을 50배로 늘린 Table 9를 “BBPE token이 50배 늘었다”거나 “attention cache가 50배 늘었다”로 읽지 않는다.

## 이번 보고서에서 다루지 않는 항목

Qwen3.8-Next는 architecture/evaluation/efficiency/optimization 보고서다. 본문은 Qwen3.5 base tokenizer vocabulary 250K를 n-gram table scale의 기준으로 언급하지만, 새 tokenizer·BBPE·data construction·synthetic instruction·SFT/RL/DPO pipeline을 설명하지 않는다. 따라서 이 주차의 필수 배경으로 Qwen2.5의 BBPE나 Qwen2의 data synthesis를 반복해서 넣지 않는다. 그것들은 [W02 Qwen 가이드](qwen.md)의 범위다.

또한 QSA는 V3.2의 DSA를 인용하지만 MLA를 직접 채택했다는 문장이 없다. MLA는 위의 `Qwen→V3.2→V2` 비교 경로에서만 읽는다. V4의 MOPD 역시 이 논문의 직접 인용이 아니므로 W10의 OPD 배경으로 넣지 않는다.

## W10의 세 목표와 이 가이드의 관계

세 목표는 (1) GDN/global attention/QSA, (2) GR/n-gram, (3) Muon/parallelism에 초점을 둔다. 이 가이드는 그 세 줄 아래의 RoPE·MQA·normalization·FP8·MoE capacity·scaling law·stress test를 분해해 둔 것이다. 즉 목표 수를 늘리지 않고도 “이 component가 왜 필요한가, 어느 논문 원전에서 무엇을 읽어야 하는가, Qwen이 실제로 채택·변경한 부분은 어디인가”를 답할 수 있게 한다.
