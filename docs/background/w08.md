# W08 — MiMo → MiMo-V2-Flash: 본문 구성요소와 선행 개념

[W08 학습목표](../weeks/w08/README.md) · [전체 읽기 지도](README.md) · [읽기 분담](workload.md)

## 이번 주 읽기 범위

[MiMo v2](https://arxiv.org/abs/2505.07608v2)는 **reasoning pattern을 보존하는 pre-training data**, **code test 난도를 보상으로 바꾸는 RL**, **긴 rollout의 idle time을 줄이는 engine**을 보고한다. [MiMo-V2-Flash v2](https://arxiv.org/abs/2601.02780v2)는 그 위에서 hybrid attention·deployment용 MTP·다교사 통합과 MoE RL infrastructure를 바꾼다. 다음은 “무엇을 계승했고 무엇이 새 설계인가”를 분리한 읽기 지도다.

공통 읽기는 [주차별 분담표](workload.md)에 적힌 대상 본문으로 시작한다. 담당 심화에서는 아래 구성요소 중 한 갈래와 필요한 선행 원전의 지정 절을 읽는다.

## 본문 구성요소와 선행 개념

<a id="mimo-pretraining"></a>
### 1. MiMo의 reasoning-friendly pre-training: 원문을 덜 버리고, 혼합 비율을 바꾼다

[MiMo §2.1–§2.3](https://arxiv.org/pdf/2505.07608v2)는 단순히 math/code 비중을 늘렸다는 이야기가 아니다. 일반 web extractor가 수식·code block·forum 구조를 잃는 문제에서 시작해, extraction → global deduplication → quality tagging → stage-wise mixture를 연결한다.

| 대상 본문 | 동작과 이유 | 확인 질문 |
| --- | --- | --- |
| §2.1 “Better Reasoning Data Extraction” | math/code/forum에 맞춘 HTML extractor와 STEM·code를 더 보존하는 PDF parser를 사용한다. 이후 filter의 입력에 남는 structure 자체가 달라진다. | “filter가 좋으면 parser는 상관없다”가 왜 이 보고서의 주장과 다른가? 수식이 텍스트에서 사라진 문서는 quality tagger도 되살릴 수 없다. |
| §2.1 “Fast Global Deduplication”·“Multi-Dimensional Data Filtering” | URL+MinHash로 모든 web dump를 deduplicate한 뒤, content-aware 하지 않은 dedup 결과는 domain/다차원 quality score로 다시 분포를 조정한다. rule-based filter가 math/code가 많은 고품질 page를 버린다는 관찰 때문에 small LLM tagger를 fine-tune한다. | duplicate 제거와 quality ranking은 다른 연산이다. 같은 내용의 두 page를 하나로 만드는 것과, 남은 page의 reasoning density를 높게 주는 것을 분리해 설명할 수 있는가? |
| §2.1 “Synthetic Reasoning Data” | STEM source에 깊은 분석을 시키고, math/code problem을 풀게 하며, creative writing query도 넣는다. 저자는 non-reasoning synthetic data와 달리 synthetic reasoning response는 아주 많은 epoch로 학습해도 overfit 위험이 낮았다고 보고한다. | 이 문장은 저자들의 preliminary observation이다. 모든 합성 CoT가 무제한 재사용 가능하다는 일반 법칙으로 바꾸지 않는다. |
| §2.1 “Three-Stage Data Mixture” | stage 1은 광고·news 같은 과대표집/낮은 density를 줄이고 전문 자료를 올린다. stage 2는 math+code를 약 70%까지 올린다. stage 3은 math/code/creative-writing query의 합성 response 약 10%와 8K→32K context extension을 함께 넣는다. | “32K 학습”과 “synthetic response 10%”는 같은 stage에서 함께 바뀐다. 특정 성능 변화를 한 요인만의 효과라고 단정할 수 있는가? |

**먼저 읽을 원전 — MinHash.** MiMo §2.1이 직접 인용한 [Broder (1997), §2–§3](https://www.cs.princeton.edu/courses/archive/spring13/cos598C/broder97resemblance.pdf)에서 문서를 연속 token 묶음인 **shingle의 집합**으로 바꾸고, 두 집합의 교집합/합집합 비율(resemblance)을 작은 random sketch로 추정하는 원리를 읽는다. 이는 주소가 같은 문서를 찾는 URL deduplication과 달리, 주소가 달라도 내용이 거의 같은 문서를 찾는 배경이다. 예를 들어 shingle 집합 `A={a,b,c}`, `B={a,b,d}`의 resemblance는 `2/4`다. 같은 주제를 다룬다는 의미적 유사성과 문구의 중복을 구별한다. MiMo는 MinHash를 **채택**했으며 shingle 크기·threshold나 tagger label schema를 공개하지 않았으므로 그 값은 채우지 않는다.

<a id="mimo-base-mtp"></a>
### 2. MiMo-7B의 decoder와 MTP: 학습 보조와 decoding draft를 같은 것으로 부르지 않기

[MiMo §2.2–§2.3, Fig. 2](https://arxiv.org/pdf/2505.07608v2)의 base model은 decoder-only Transformer에 GQA, pre-RMSNorm, SwiGLU, RoPE를 쓴다. 이 네 구성은 MiMo의 독점적 새 제안이 아니라 Llama/Qwen 계열에서 계승한 block recipe다([W01의 구성요소](w01.md), [W03의 GQA 비교](w03.md)). MiMo가 이 절에서 구체화한 선택은 **single MTP layer의 학습과 여러 MTP layer의 추론 전환**이다.

| 시점 | MiMo가 한 일 | 왜 Flash와 구분해야 하나 |
| --- | --- | --- |
| pre-training | main model과 tied output head를 둔 **하나의** MTP layer를 추가 objective로 학습한다. 여러 MTP layer는 추가 품질 이득이 없었다고 쓴다. MTP loss weight도 0.3에서 0.1로 낮춘다(§2.3). | next-token loss를 더 먼 token에도 주는 학습 보조와, 바로 multi-token을 accept하는 speculative decoding은 다른 단계다. MTP 원전은 보고서가 직접 인용한 [Gloeckle et al. v1 §2, 식 (1)–(2)·Fig. 1–2; §3.2](https://arxiv.org/abs/2404.19737v1)에서 읽는다. |
| inference 준비 | 학습된 single MTP layer를 두 개 복제한 뒤, main model+첫 MTP layer는 freeze하고 새 두 layer만 fine-tune한다. | “학습 중 1개”라는 비용 선택이 “추론 중 여러 draft head”를 금지하는 것은 아니다. Fig. 2의 좌·우를 따로 그린다. |
| decoding | draft한 token을 main model이 verify하여 accept한다. AIME24에서 첫 layer acceptance 약 90%, 세 번째도 75% 이상이라는 수치는 그 benchmark 조건의 관찰이다. | acceptance가 높을수록 항상 고정 배속이라는 뜻은 아니다. 입력/출력 길이, entropy, batch/kernel이 latency에 관여한다. Flash §5에서 이 제약을 더 직접 분석한다. |

<a id="mimo-verifier-rl"></a>
### 3. MiMo의 verifier-RL: reward 모양·문제 난도·rollout scheduling을 함께 읽는다

[MiMo §3.1–§3.4, Fig. 5–6](https://arxiv.org/pdf/2505.07608v2)는 GRPO 식만 재사용하지 않는다. RL sample이 실제 gradient를 주도록 prompt pool과 reward를 바꾸고, 그 결과 생긴 scheduling 문제를 Seamless Rollout Engine으로 다룬다.

| 대상 본문 | 필요한 개념과 실제 절차 | 작은 예시·한계 |
| --- | --- | --- |
| §3.1 SFT preprocessing | eval과 16-gram overlap인 query 제거 → language mixing/incomplete response 제거 → query당 response 최대 8개로 제한해 약 500K SFT set을 만든다. | dedup/decontamination은 correctness reward와 별개의 누수 방지 단계다. 이후 6M SFT scale 관찰은 §3.6에서 별도로 확인한다. |
| §3.2 RL data curation | math에서는 proof/multiple-choice를 빼고, 16 rollout에서 pass rate 90% 초과의 쉬운 문제를 제거한다. code에서는 test 없는 문제·gold solution도 tests를 못 통과하는 문제를 제거한다. | “정답이 있다”만으로 verifier-RL data가 되는 것은 아니다. 너무 쉬움·오답·test 부실 모두 group advantage를 무력하게 할 수 있다. |
| §3.3.1 test-difficulty driven reward | 여러 model rollout의 test-case pass rate로 test를 난도 group으로 묶는다. strict는 쉬운 group까지 모두 통과해야 다음 난도 보상, soft는 통과한 test에 group score를 나눈다. | 단일 full-pass reward에서는 어려운 문제의 reward가 늘 0일 수 있다. test A/B의 pass rate가 다를 때, “부분 정답”을 주는 것이 false success를 허용하는 것은 아닌지 strict/soft 두 설계를 비교한다. |
| §3.3·§3.3.2 dynamic sampling/easy re-sampling | pass rate 0 또는 1 prompt를 rollout에서 걸러 effective gradient를 확보한다. policy가 좋아지면 1인 문제만 많아져 batch를 채우기 비싸므로, 완전히 제거하지 않고 easy pool에서 약 10%를 다시 sample해 update 안정성을 노린다. | easy problem은 gradient가 없으니 버린다는 직관이 policy collapse 위험과 충돌한다. 이 10%는 공개된 실험 설정이며 보편적 최적값이 아니다. |
| §3.4–§3.4.1 Seamless Rollout Engine | completion을 기다려 barrier를 만들지 않고, 끝난 rollout의 reward를 계산하며 필요한 만큼 다음 rollout을 계속 시작한다. asynchronous reward·early termination을 조합해 training 2.29×/validation 1.96× 속도를 보고한다. | 이것은 asynchronous **policy update**를 도입한 것이 아니라 reward/rollout scheduling을 겹친 설계다. 길이가 다른 sample의 straggler와 policy staleness를 같은 문제로 부르지 않는다. |

[MiMo §3.6](https://arxiv.org/pdf/2505.07608v2)는 base에서 바로 RL한 모델은 exploration growth가 크지만, 충분히 큰 SFT를 거친 모델이 더 높은 ceiling을 보였다고 보고한다. language-mixing penalty는 역방향 언어 판별·code/math 내 영어 때문에 reward hack을 만들 수 있었다. 따라서 “format/language penalty를 더하면 해결”이라고 일반화하지 않는 것이 이 보고서의 중요한 반례다.

### 4. Flash가 바꾼 세 층: attention, draft, policy integration

#### 4.1 Hybrid SWA/GA와 learnable sink

[Flash §2.1–§2.2, Fig. 2, 식 (1)–(4)](https://arxiv.org/pdf/2601.02780v2)는 standard Transformer+MoE 위에 8개 hybrid block을 둔다. 각 설계의 작동을 나누어 읽는다.

| 구성요소 | 실제 동작 | 왜 필요한가 · 범위 |
| --- | --- | --- |
| SWA block | 현재 query가 고정 local window의 KV만 직접 읽는다. Flash는 5개 SWA를 연속 배치한다. | long sequence에서 attention KV access와 연산을 줄인다. local/global의 일반 background는 Flash가 직접 인용한 [Longformer v2 §3–§3.1](https://arxiv.org/abs/2004.05150v2)에서 읽되, Flash의 causal block을 Longformer encoder와 같은 구현으로 부르지 않는다. |
| GA block | SWA 다섯 개 뒤에 global-attention block 하나를 둬 멀리 있는 token 연결을 회복한다. 첫 Transformer block만 GA+dense FFN인 예외도 Fig. 2에서 표시한다. | SWA를 모든 layer에만 쓰면 장거리 token을 직접 비교할 기회가 줄어든다. `5:1`, 8 hybrid block, window 128은 이 보고서의 specific configuration이다. |
| learnable sink logit | softmax 분모에 head별 scalar `s_sink`을 넣는다(식 (1)–(4)). | 어떤 real token에도 attention mass를 주지 않는 선택지를 제공한다. 이는 initial token의 KV를 cache하는 “sink token”과 다르다. Flash가 구현 출처로 밝힌 [gpt-oss model card v1 §2.2](https://arxiv.org/abs/2508.10925v1)를 읽는다. |
| window-size ablation | Tables 2–4에서 128/다른 window와 global block 배치를 비교한다. | 128이 모든 모델·corpus에서 우월하다는 원리가 아니라 32B·data·training setting 아래의 실험적 선택이다. |

#### 4.2 Flash의 lightweight MTP는 rollout throughput을 겨냥한다

[Flash §2.3.1–§2.3.2, §5.1–§5.2](https://arxiv.org/pdf/2601.02780v2)의 MTP module은 main model과 동일한 구조를 복제하지 않는다. draft block의 attention은 SWA, FFN은 dense로 두어 **KV I/O가 큰 attention**과 **작은-batch rollout의 낮은 arithmetic intensity**를 동시에 겨냥한다. pre-training에는 single head, post-training에는 이를 `K` head로 복제해 joint training한다. draft가 낸 여러 token을 main model이 verify해 accept하며, acceptance length가 실제 decode throughput의 매개다. Fig. 7의 next-token entropy와 acceptance length 관계는 상관 관찰이고, Table 10의 speedup은 16K input/1K output·batch·accept-length 조건을 함께 읽어야 한다.

#### 4.3 MOPD와 MoE RL execution은 별개의 새 조합이다

[Flash §4.1·§4.4, 식 (5)–(9)](https://arxiv.org/pdf/2601.02780v2)는 stage 1 SFT → stage 2 domain-specialist RL/SFT → stage 3 MOPD로 specialized teacher를 하나의 student에 합친다. MOPD loss와 execution system은 나눠 읽는다.

| 구성요소 | 실제 동작 | 왜 필요한가 · 범위 |
| --- | --- | --- |
| domain routing | prompt `x`에 대응하는 domain specialist teacher를 선택한다. | “모든 teacher 평균”이 아니다. 교사별 specialist capability를 한 student로 보존/통합하려는 선택이다. |
| reverse-KL token advantage | student가 **자기 rollout에서 낸 token**에 teacher/student log-prob ratio를 계산해 advantage로 쓴다(식 (5)–(8)). | teacher trace만 SFT하는 것보다 student가 실제로 하는 실수 위치에서 신호를 준다. on-policy student-trajectory의 배경은 Flash가 직접 인용한 [On-Policy Distillation v3 §2–§3](https://arxiv.org/abs/2306.13649v3)이다. |
| ORM 결합 | MOPD advantage에 outcome-reward/GRPO advantage를 `α`로 결합한다(식 (9)). | teacher distribution을 닮는 신호와 task outcome signal은 같은 보상이 아니다. Fig. 6에서 ORM-only, MOPD-only, 결합을 별도 곡선으로 비교한다. |
| Rollout Routing Replay (R3) | rollout 때 고른 MoE expert route를 training에도 replay한다. | Flash §4.6.1이 설명한 inference/training 사이의 수치 정밀도 문제로 expert routing이 달라지는 불안정을 줄인다. R3는 distillation objective가 아니라 route consistency policy다. |
| request-level prefix cache | 같은 request의 앞 turn KV cache와 routed expert를 재사용하되 inter-request output cache 공유/재-prefill은 피한다. | multi-turn rollout의 비용을 줄이면서 sampling consistency를 보존하려는 선택이다. 일반 radix cache와 혼동하지 않는다. |
| Data Scheduler·Toolbox | sequence 단위로 return된 sample을 scheduling하고 partial rollout의 staleness를 truncated importance sampling으로 제한한다. Toolbox/Tool Manager는 QPS/quota, pre-warm, timeout recovery를 담당한다. | 이들은 MOPD loss가 아니라 heterogeneous tool/reward duration 때문에 생기는 GPU idle·resource contention을 다루는 시스템 정책이다. |

### 6. Flash의 데이터·SFT·RL: 어느 단계에서 무엇을 바꾸는가

#### 데이터 mixture와 context schedule

[Flash §3–§3.2](https://arxiv.org/pdf/2601.02780v2)는 MiMo의 데이터 처리 pipeline을 계승하면서 repository code·PR·issue·commit history 등 긴 의존관계가 있는 자료를 늘린다. **data mixture**는 학습에 보여 줄 자료의 비율, **context length**는 한 번에 함께 볼 수 있는 token 범위, **learning-rate schedule**은 update 크기를 바꾼다. 세 개가 같은 curriculum 표에 있어도 역할은 다르다.

| 단계 | 자료·문맥의 변경 | 이해할 차이 |
| --- | --- | --- |
| 0–22T | 일반 corpus, 32K context | 폭넓은 언어 능력을 세우는 초기 pre-training |
| 22–26T | code upsampling, 약 5% synthetic reasoning | 창 길이를 바꾸기 전에 학습 분포를 바꾸는 mid-training |
| 26–27T | 256K context, long-range data upsampling | 긴 example을 실제로 보여 주면서 GA의 RoPE base도 조정하는 context extension |

MiMo의 약 10% 합성 reasoning과 Flash의 약 5%는 서로 다른 모델·stage의 recipe다. **점검:** RoPE base만 변경하고 긴 code dependency를 보여 주지 않아도 이 보고서와 같은 context-extension 학습인가? 자료 구성과 위치 표현 변경을 함께 확인한다. RoPE 기초는 [W01](w01.md), Flash가 정한 schedule은 해당 본문이 원전이다.

#### MoE SFT 안정성: `num-zeros`, expert bias, AdamW epsilon

[Flash §4.2](https://arxiv.org/pdf/2601.02780v2)는 자체 specialist checkpoint가 생성한 thinking/non-thinking 응답으로 SFT하고, **gradient가 0인 parameter 수(`num-zeros`)**를 관찰한다. 저자들은 이 값의 증가를 expert load balance 악화, 감소를 과적합의 신호로 해석한다. 이는 해당 학습에서의 관찰이며 모든 MoE에 적용되는 판정식은 아니다.

선수 개념은 [W06의 expert-bias load balancing](w06.md)과 [W01의 AdamW](w01.md)다. routing bias는 expert가 선택되는 빈도에, AdamW의 `ε`는 adaptive update 분모의 수치 안정성에 작용한다. Flash는 두 hyperparameter가 `num-zeros` 안정성에 영향을 준다고 보고하며 SFT에서 각각 `1e-4`, `1e-8`을 쓴다. **점검:** 같은 loss라도 거의 사용되지 않는 expert가 늘어나는 상황을 loss 하나로 판별할 수 있는가? parameter별 gradient와 routing 이용률을 구분해 본다.

#### single-turn reward와 상호작용 환경의 supervision

[Flash §4.3.1–§4.3.2](https://arxiv.org/pdf/2601.02780v2)의 non-agentic RL은 완성된 한 응답을 programmatic tool+LLM judge로 검증하거나, helpfulness/safety를 rubric과 reference answer로 평가한다. agentic RL은 `action → tool execution → observation → 다음 action`이 이어지는 환경을 구성한다. 정확도 reward의 기본은 [MiMo verifier-RL](#mimo-verifier-rl)에서 재사용하고, 여기서는 **무엇이 실행 환경이고 무엇이 판정 근거인가**를 읽는다.

| 환경 | 본문이 설명한 구성·보상 | 확인 질문 |
| --- | --- | --- |
| Code | 실제 GitHub issue와 repository snapshot으로 container를 만들고 `bash/str_replace/finish` 도구 및 unit test를 제공한다. | 코드 응답 문자열과 환경에서 실행한 patch의 성공은 어떻게 다른가? |
| Terminal | Stack Overflow/Exchange 문제를 query·Dockerfile·test case로 바꾸고 설치 성공·난도·판정 신뢰성을 검사한다. | 환경 설치 실패를 모델 풀이 실패로 점수화해도 되는가? |
| Web development | 실제 웹 결과에서 query를 역구성하고, 실행 영상을 visual verifier로 평가한다. | 이 경로의 시각 판정은 모델 본체를 multimodal로 바꾸는 것과 같은가? 이는 텍스트 coding policy를 위한 환경·보상 구성이다. |
| Search·general tools | seed entity의 fact graph를 확장해 검증 가능한 검색 문제를 만들고, tool-call graph에 명시적 입출력 의존과 암묵적 state 의존을 둔다. | 앞 tool의 반환값을 복사하는 일과 숨은 시스템 상태를 추론하는 일을 각각 예로 든다. |

이 환경 구성과 `num-zeros` 사용은 Flash 자체 절차다. 본문이 별도 알고리즘 원전을 지정하지 않은 부분에 임의의 합성 데이터 논문을 붙이지 않는다.

### 원전 사용 원칙

- MiMo/Flash에서 보고된 dataset size·비율·speedup·acceptance·architecture 수치는 각 고정 보고서 본문에서 확인한다. 공개되지 않은 parser/tagger 또는 scheduler의 구현 세부를 추정하지 않는다.
- W06는 MTP의 일반 objective, W07은 GRPO의 기본식, W09은 agent task synthesis를 맡는다. W08에서는 그 기초 위에서 MiMo/Flash가 바꾼 data, verifier, decoding, systems를 묻는다.
- Flash의 MOPD가 W15의 MOPD 또는 다른 multi-teacher report를 자동으로 뒷받침하지 않는다. 각 보고서의 teacher routing·reward·signal 단위를 다시 확인한다.
