# W13 — GLM-5: 본문 구성요소와 선행 개념

[W13 학습목표](../weeks/w13/README.md) · [전체 읽기 지도](README.md) · [읽기 분담](workload.md)

## 이번 주 읽기 범위

이 문서는 [GLM-5 v2](https://arxiv.org/abs/2602.15763v2)의 architecture·data·post-training·agent environment 중 본문이 설명하는 선행 개념을 연결한다. W13의 중심은 TITO/비동기 RL이지만, 그것이 어떤 base model·rollout 시스템·검증 환경 위에서 작동하는지도 함께 읽는다. `채택/변경/제안`의 경계는 각 항목에 표시한다.

공통 읽기는 [주차별 분담표](workload.md)에 적힌 대상 본문으로 시작한다. 담당 심화에서는 아래 구성요소 중 한 갈래와 필요한 선행 원전의 지정 절을 읽는다.

## 본문 구성요소와 선행 개념

### 1. base model과 long-context adaptation

#### MoE scale

- **본문 출발점:** [§2.1, Table 1](https://arxiv.org/abs/2602.15763v2). GLM-5는 256 expert/80 layer/744B total·40B activated로 바꾼다.
- **작동과 필요:** token당 일부 expert만 활성화하는 MoE에서 total parameter는 capacity, active parameter는 token당 compute의 가까운 지표다. layer 수를 줄이는 선택은 expert-parallel communication overhead를 줄이는 데 목적이 있다.
- **원전 경로:** MoE shared/routed expert의 기본은 [DeepSeek-V2 v5 §2.2](https://arxiv.org/abs/2405.04434v5), GLM-5 scale 변경은 §2.1 자체가 원전이다.
- **경계:** 256 expert/80 layer는 **구성 선택**이다. Table 10의 architecture 수와 generic MoE theory를 혼동하지 않는다.
- **확인 질문:** total 744B가 active 40B와 다른 이유와, layer를 줄이는 이유가 각각 compute의 어느 부분을 겨냥하는가?

#### MLA와 GQA의 KV-cache 압축 단위

- **본문 출발점:** [§2.1, Table 1](https://arxiv.org/abs/2602.15763v2). GLM-5는 576-dimensional MLA cache와 GQA-8를 비교한다.
- **작동과 필요:** GQA는 여러 query head가 KV head를 공유하여 head 축의 cache를 줄인다. MLA는 K/V를 latent representation으로 압축한 뒤 필요할 때 reconstruct하는 방식으로 channel representation을 줄인다. Table 1의 비교는 같은 cache budget이 attention quality·decode latency에 주는 trade-off를 보는 ablation이다.
- **원전 경로:** MLA는 [DeepSeek-V2 v5 §2.1](https://arxiv.org/abs/2405.04434v5), GQA 기본은 [W12 구성요소 가이드](w12.md)의 GQA 절에서 먼저 읽는다. GLM-5의 576-dimensional 비교 조건은 §2.1 자체가 원전이다.
- **경계:** Table 1은 pre-training ablation이며, MLA가 모든 cache budget에서 GQA보다 낫거나 나쁘다는 보편 순위가 아니다.
- **확인 질문:** latent KV dimension을 줄이는 MLA와 KV head 수를 줄이는 GQA는 cache를 각각 어떤 representation에서 압축하는가?

#### Muon Split과 MLA-256

- **본문 출발점:** [§2.1, Table 1](https://arxiv.org/abs/2602.15763v2). 576-dimensional MLA cache의 quality gap을 Muon Split으로 보정하고, MLA-256으로 head dimension과 head 수를 바꾼다.
- **작동과 필요:** Muon Split은 Q/K/V up-projection을 head별 작은 matrix로 나누어 orthogonalization하므로 head마다 update scale을 가질 수 있다. MLA-256은 head dimension을 256으로 하고 head 수를 1/3로 줄여 decode dot-product 수를 낮추려는 architecture/optimizer 결합 변경이다.
- **원전 경로:** Muon 기본은 [W12 구성요소 가이드](w12.md)의 Muon 절에서 읽는다. head별 split과 MLA-256은 GLM-5 §2.1의 **변경 원전**이다.
- **경계:** MLA/Muon은 **채택**이고, head별 Muon orthogonalization·MLA-256은 **GLM-5 변경**이다. Table 1은 pre-training ablation이다.
- **확인 질문:** Q/K/V up-projection을 head별 matrix로 나누면 standard Muon 적용과 어떤 update coupling이 달라지는가?

#### MTP parameter sharing

- **본문 출발점:** [§2.1, Table 2](https://arxiv.org/abs/2602.15763v2). train 시 3 MTP layer의 parameter를 공유한다.
- **작동과 필요:** MTP layer를 여럿 두면 n-token draft를 학습할 수 있지만 parameter/KV memory가 step 수에 비례한다. weight sharing은 이 memory를 억제하면서 4-step speculation의 accept length를 늘리려 한다.
- **원전 경로:** MTP는 [MTP §2–§3](https://arxiv.org/abs/2404.19737v1), speculative decoding은 [§2–§3](https://arxiv.org/abs/2211.17192v2)다.
- **경계:** MTP는 **채택**, 3 layer parameter sharing은 GLM-5의 **변경**이다.
- **확인 질문:** MTP parameter sharing은 inference에서 4 speculative step을 실제로 어떻게 학습한 것과 다른가?

#### DSA continued pre-training

- **본문 출발점:** [§2.1.1, Table 3, Figure 6](https://arxiv.org/abs/2602.15763v2). mid-training 끝 dense model에서 indexer warm-up→20B sparse adaptation으로 DSA로 전환한다.
- **작동과 필요:** DSA indexer가 top-k token을 골라 dense `O(L²)` attention 비용을 낮춘다. dense checkpoint에서 시작하면 pretraining을 처음부터 반복하지 않고 selection module과 base model을 적응시킬 수 있다.
- **원전 경로:** 보고서가 직접 인용한 [DeepSeek-V3.2 v1 §2.1–§2.1.1](https://arxiv.org/abs/2512.02556v1)를 읽는다.
- **경계:** DSA는 **채택**, GLM-5의 smaller-budget warm-up/adaptation은 **변경**이다. “90% attention entry”는 report의 predecessor 해석이지 보편 정리가 아니다.
- **확인 질문:** indexer만 warm-up할 때와 joint adaptation할 때, 어느 parameter가 frozen/updated 되는가?

#### SWA/GDN은 core replacement가 아닌 ablation

- **본문 출발점:** [§2.1.2, Tables 4–6](https://arxiv.org/abs/2602.15763v2). GLM-9B에서 fixed SWA interleave, searched SWA pattern, GDN, SimpleGDN을 비교한다.
- **작동과 필요:** SWA는 일부 layer를 local window로 제한하고, GDN은 attention을 gated linear recurrence로 바꾼다. search-based pattern은 모든 layer를 교대하지 않고 long-context benchmark에 필요한 full-attention layer 위치를 고른다. SimpleGDN은 기존 Q/K/V projection을 recurrence에 재사용해 새 parameter를 줄인다.
- **원전 경로:** GDN은 직접 인용한 [Gated Delta Networks](https://arxiv.org/abs/2412.06464), DSA와 continual adaptation은 위 절의 DeepSeek-V3.2이다. GLM-5의 beam-search pattern·SimpleGDN은 §2.1.2가 원전이다.
- **경계:** 이는 GLM-5 deploy architecture가 아니라 **ablation/비교**다. 보고서의 결론은 이 실험 조건에서 DSA가 더 적은 quality gap을 보였다는 것이며, 모든 attention 종류의 보편적 순위가 아니다.
- **확인 질문:** fixed 1:1 interleave보다 layer-position search가 나은 이유를, full-attention layer가 담당할 수 있는 long-range dependency로 설명할 수 있는가?

### 2. data·context·training systems

#### web/code/math selection

- **본문 출발점:** [§2.2](https://arxiv.org/abs/2602.15763v2). DCLM sentence-embedding classifier와 world-knowledge classifier, code metadata/language classifier, chunk-and-aggregate document scoring을 쓴다.
- **작동과 필요:** web quality와 world knowledge를 같은 classifier로 보지 않고, medium/low-quality 문서 안의 long-tail knowledge를 별도 선택한다. code metadata alignment와 language identification은 quality score가 잘못된 파일 종류에 적용되는 문제를 줄인다.
- **원전 경로:** GLM-4.5에서 이어진 quality sampling/FIM/SemDedup은 [W12 데이터 가이드](w12.md)를 재사용한다. GLM-5의 world-knowledge classifier·chunk-and-aggregate scoring은 별도 원전으로 위임하지 않은 **자체 본문 설계**다.
- **경계:** classifier의 세부 training data/threshold는 공개되지 않는다. 이 항목은 **운용 선택**이며, corpus quality가 benchmark gain의 유일 원인이라는 ablation은 없다.
- **확인 질문:** quality classifier와 world-knowledge classifier를 나누면, “교육적으로 좋은 문서”와 “희소 사실을 담은 문서”의 trade-off를 어떻게 다룰 수 있는가?

#### 32K→128K→200K mid-training

- **본문 출발점:** [§2.3](https://arxiv.org/abs/2602.15763v2). context를 32K(1T)→128K(500B)→200K(50B)로 늘리고, repo issue–PR·related file, natural long document, synthetic long-range dependency, MRCR-like recall data를 단계별로 넣는다.
- **작동과 필요:** repo-level code sequence는 issue, diff, related file의 멀리 떨어진 dependency를 같은 attention window에 둔다. interleaved packing은 유사 text 묶음에서 멀리 떨어진 association을 강제하려는 구성이다. 200K stage의 MRCR-like data는 multi-turn recall을 보완한다.
- **원전 경로:** report reference의 NextLong/EntropyLong은 제목·저자·연도만 적혀 있고 공개 식별자/URL을 제공하지 않아, 외부 원전으로 단정하지 않는다. 이 보고서에서 채택한 data mixture와 stage 순서는 **GLM-5 §2.3 자체**로 읽는다.
- **경계:** 200K stage가 128K performance도 높였다는 것은 해당 report의 관찰이다. interleaved packing·MRCR variant의 exact construction은 공개되지 않는다.
- **확인 질문:** 문서를 단순히 길게 붙이는 것과 similar text를 interleaved packing하는 것은 lost-in-the-middle에 어떤 다른 신호를 주는가?

#### memory: ZeRO shard·activation offload·chunked projection

- **본문 출발점:** [§2.4.1](https://arxiv.org/abs/2602.15763v2). flexible MTP placement, pipeline ZeRO-2 gradient sharding, Muon shard communication, activation offload, sequence-chunked output projection을 설명한다.
- **작동과 필요:** 200K sequence에서는 activation·output logits·MTP module이 stage별 memory peak를 만든다. gradient shard/double buffer는 persistent gradient memory를, activation offload는 GPU-resident forward state를, chunked projection은 output-layer peak를 줄인다.
- **원전 경로:** 직접 인용한 [ZeRO §3](https://arxiv.org/abs/1910.02054v3)를 읽는다. double buffering, MTP placement, chunked projection의 조합은 GLM-5 §2.4.1 자체가 원전이다.
- **경계:** ZeRO는 **채택**, 세 memory optimization의 concrete placement는 **인프라 설계**다. 산술 FLOP 개선 수치는 본문에 없다.
- **확인 질문:** parameter sharding과 activation offloading은 각각 optimizer state/gradient와 forward activation 중 무엇을 줄이며, 왜 서로 대체가 아닌가?

#### parallelism과 INT4 QAT

- **본문 출발점:** [§2.4.2–§2.4.3](https://arxiv.org/abs/2602.15763v2). deferred weight-gradient로 pipeline bubble을 줄이고, INT4 QAT와 training/inference bitwise-identical kernel을 쓴다.
- **작동과 필요:** critical path가 아닌 gradient computation을 뒤로 미뤄 communication과 겹치게 하면 pipeline idle time을 낮춘다. QAT는 low-bit quantization error를 training 중에 노출해, inference 때만 INT4로 바꾸는 distribution gap을 줄인다.
- **원전 경로:** direct citation인 [Zero Bubble Pipeline Parallelism](https://arxiv.org/abs/2401.10241v1)을 읽는다. GLM-5의 INT4 kernel과 bitwise-identical claim은 §2.4.3 자체가 원전이다.
- **경계:** deferred gradient는 **채택/응용**, exact scheduling과 QAT kernel은 **GLM-5 구현**이다. INT4가 모든 task에서 무손실이라는 결과는 제시하지 않는다.
- **확인 질문:** QAT에서 training과 inference kernel이 bitwise-identical해야 한다는 요구는 어느 종류의 deployment mismatch를 줄이는가?

### 3. inference deployment: precision, fused operator, scheduling

#### component-wise W8A8/W4A8 quantization

- **본문 출발점:** [§5](https://arxiv.org/abs/2602.15763v2). GLM-5 deployment는 attention/MLP를 W8A8(INT8), MoE expert를 W4A8(INT4)로 두고 outlier suppression과 scaling calibration을 쓴다.
- **작동과 필요:** `W4A8`은 weight를 4-bit, activation을 8-bit로 표현한다. expert weight는 MoE total parameter의 큰 부분이라 더 낮은 bit로 memory를 아끼고, attention/MLP에는 더 높은 precision을 남겨 component별 quantization-error budget을 배분한다. outlier suppression은 작은 bit range에서 큰 activation/weight 값이 scale을 지배하는 문제를 줄인다.
- **원전 경로:** report가 직접 인용한 [QuaRot §3–§4](https://arxiv.org/abs/2404.00456)를 읽어 rotation 기반 outlier 완화와 end-to-end low-bit inference의 범위를 확인한다. GLM-5의 attention/MLP↔expert precision allocation과 calibration 조합은 §5 **자체 원전**이다.
- **경계:** QuaRot의 all-component 4-bit recipe와 GLM-5의 component-wise W8A8/W4A8 deployment를 같은 방법으로 쓰지 않는다. 단일 Atlas node와 장문 비용 50% 수치는 platform/workload 결과이지 일반 보장이 아니다.
- **확인 질문:** MoE expert만 W4A8로 낮추고 attention/MLP를 W8A8로 남기면, memory saving과 accumulated quantization error는 각각 어느 component에서 주로 달라지는가?

#### sparse attention·MLA operator fusion

- **본문 출발점:** [§5](https://arxiv.org/abs/2602.15763v2). Lightning Indexer는 score/ReLU/TopK를, Sparse Flash Attention은 KV top-k selection과 sparse attention을, MLAPO는 MLA 전처리 13개 operator를 fused kernel로 만든다.
- **작동과 필요:** 작은 operator를 개별 launch하면 intermediate tensor를 memory에 쓰고 다시 읽는 비용과 launch overhead가 누적된다. fusion은 producer 결과를 같은 kernel에서 consumer로 넘기며 DSA top-k 및 MLA pre-processing의 memory traffic을 줄이고, vector/cube unit이 겹쳐 일할 여지를 만든다.
- **원전 경로:** 세 fused kernel의 operation boundary와 target hardware scheduling은 GLM-5 §5 **자체 원전**이다. DSA/MLA algorithm 자체는 이 가이드의 DSA·MLA 절과 각 cited original paper에서 먼저 읽는다.
- **경계:** kernel 이름과 Ascend unit mapping은 platform-specific implementation이다. “fusion이 언제나 빠르다”가 아니라 해당 sparse pattern·operator graph에서 intermediate-memory 병목을 줄인다는 주장으로 읽는다.
- **확인 질문:** `score → ReLU → TopK`를 세 kernel로 실행할 때와 하나로 fuse할 때, global-memory round trip과 kernel launch 수는 어떻게 달라지는가?

#### decode scheduling·prefix cache·attention-DP/EP·MTP serving

- **본문 출발점:** [§5](https://arxiv.org/abs/2602.15763v2). vLLM/SGLang adaptation에서 D2H sampling과 다음 decode preparation을 overlap하고, RadixCache/prefix cache, attention data parallelism+MoE expert parallelism, split AllReduce, MTP inference를 쓴다.
- **작동과 필요:** asynchronous decode scheduling은 CPU-side sampling copy가 끝날 때까지 device decode가 빈 채로 기다리는 bubble을 줄인다. radix/prefix cache는 같은 system prompt 또는 prefix의 KV entries를 재사용하고, attention-DP는 attention workload를 rank에 나누며 EP는 selected expert 계산을 나눈다. MTP는 여러 next-token proposal을 target verification으로 묶어 generation step 수를 줄인다.
- **원전 경로:** MTP/speculative verification은 [MTP §2–§3](https://arxiv.org/abs/2404.19737v1)와 [Speculative Decoding §2–§3](https://arxiv.org/abs/2211.17192v2), KV cache 기본은 [W05 attention/cache](../weeks/w05/README.md)를 먼저 읽는다. cache/parallel scheduling 조합은 GLM-5 §5 **자체 원전**이다.
- **경계:** D2H overlap, FlashComm split AllReduce, RAM extension, DP/EP rank mapping은 exact engine/platform integration이다. report의 comparative cluster-cost claim을 일반 vLLM/SGLang performance claim으로 확대하지 않는다.
- **확인 질문:** 두 request가 긴 system prompt를 공유할 때 prefix cache는 prefill의 무엇을 재사용하고, MTP는 decode의 무엇을 줄이는가?

### 4. post-training과 agentic engineering

#### interleaved·preserved·turn-level thinking

- **본문 출발점:** [§3.1, Figure 7](https://arxiv.org/abs/2602.15763v2). SFT chat template이 interleaved/preserved/turn-level thinking을 지원한다.
- **작동과 필요:** interleaved thinking은 tool call 전에도 reasoning을 넣고, preserved thinking은 multi-turn coding agent에서 이전 thought block을 보존하며, turn-level은 per-turn reasoning budget을 바꾼다.
- **원전 경로:** 이 template/mode는 GLM-5 **자체 원전**이다. GLM-4.5의 hybrid thinking foundation은 [W12 구성요소 가이드](w12.md)로 이어진다.
- **경계:** 논문은 user-facing API option을 명세하지 않는다. Figure 7은 mode의 training representation이지 product behaviour guarantee가 아니다.
- **확인 질문:** preserved thinking이 tool observation과 달리 보존하려는 정보는 무엇이며, context를 무한히 보존하지 않는 이유는 무엇인가?

#### reward mixture와 on-policy cross-stage distillation

- **본문 출발점:** [§3.2–§3.5, 식 (1)–(2)](https://arxiv.org/abs/2602.15763v2). reasoning RL은 domain verifier를, general RL은 rule/ORM/GRM을, 마지막 stage는 on-policy cross-stage distillation을 쓴다.
- **작동과 필요:** reward mixture는 정확히 규칙화할 수 있는 조건, outcome quality, 열린 평가를 분리한다. cross-stage distillation에서는 앞선 단계의 최종 checkpoint를 teacher로 두고, 해당 teacher의 RL training set에서 prompt를 섞어 뽑는다. **현재 student가 생성한 on-policy trajectory**의 prefix에서 teacher와 student의 token log-probability를 비교하고, 식 (2)의 `stop-gradient(log π_teacher − log π_student)`를 식 (1)의 advantage 자리에 넣어 이전 능력의 퇴행을 줄인다.
- **원전 경로:** GRPO는 [W07 DeepSeekMath](../weeks/w07/README.md), on-policy distillation의 보충 출처는 본문이 인용한 [Thinking Machines Lab 글](https://thinkingmachines.ai/blog/on-policy-distillation/)이다. GLM-5의 hybrid reward/식 (1)–(2)은 **자체 원전**이다.
- **경계:** teacher의 완성 응답을 정답 trace로 저장하는 offline SFT와 생성 주체·학습 신호가 다르다. teacher는 앞선 단계의 최종 checkpoint라고 명시하지만, prompt 혼합 비율의 구체적인 값은 공개하지 않는다.
- **확인 질문:** rule reward와 ORM/GRM을 한 reward pipeline에 섞어도, 각각을 별도로 audit해야 하는 이유는 무엇인가?

#### DSA reasoning RL의 deterministic indexer와 freeze

- **본문 출발점:** [§3.2](https://arxiv.org/abs/2602.15763v2). RL에서 DSA top-k indexer의 deterministic selection을 구현하고 indexer parameter를 freeze한다고 설명한다.
- **작동과 필요:** 같은 hidden state가 run마다 다른 top-k token을 고르면 rollout policy와 learner policy의 attention graph가 달라져 importance ratio의 전제가 흔들린다. deterministic indexer는 action probability를 재계산할 때 selection path를 재현하게 하고, freeze는 RL reward가 indexer instability 자체를 최적화하는 것을 막는다.
- **원전 경로:** DSA architecture는 [DeepSeek-V3.2 v1 §2.1–§2.1.1](https://arxiv.org/abs/2512.02556v1), RL의 deterministic top-k/freeze 선택은 GLM-5 §3.2 **자체 원전**이다.
- **경계:** `torch.topk` 선택과 indexer freeze는 이 report의 RL stability choice다. deterministic sparse selection이 모든 accelerator/kernel에서 같은 성능을 준다는 주장은 아니다.
- **확인 질문:** rollout과 learner가 같은 text를 보더라도 top-k index가 달라지면, 왜 token log-probability ratio를 공정하게 비교할 수 없게 되는가?

#### slime의 rollout interface·tail latency·fault tolerance

- **본문 출발점:** [§3.6.1–§3.6.3](https://arxiv.org/abs/2602.15763v2). slime의 기존 기능을 활용해 다양한 rollout을 연결하고, 느린 trajectory의 완료 시간과 서버 장애를 관리한다.
- **작동과 필요:** HTTP server/router와 custom rollout interface는 tool call·환경 응답·verifier 분기를 학습 backend에서 분리한다. no-queue serving은 충분한 분산 KV-cache를 확보해 대기 시간을 줄이며, MLA의 attention-DP는 rank 사이의 KV 복사를 피한다. **FP8 rollout과 MTP**는 token 생성 시간을 줄이고, **prefill–decode 분리**는 긴 history의 prefill이 다른 trajectory의 decode를 막는 문제를 줄인다. heartbeat가 끊기거나 상태가 나빠진 서버는 종료·router 등록 해제 후 retry를 정상 서버로 보낸다.
- **원전 경로:** API·배치 완료 시점·prefill/decode 간섭·heartbeat의 연결은 GLM-5 §3.6 자체에서 읽는다. KV-cache/parallelism은 이 가이드의 deployment 절, FP8은 [W06 수치 표현](w06.md), MTP는 위 MTP 절을 재사용한다. 공개 구현은 [THUDM/slime](https://github.com/THUDM/slime)이다.
- **경계:** 보고서는 이 기능들을 새로 제안했다고 하지 않고 **slime의 기능을 활용**했다고 명시한다. no-queue는 충분한 cache와 serving 자원을 확보하려는 구성 목표이며, 임의의 부하에서도 대기 시간이 0이라는 보장이 아니다.
- **확인 질문:** 짧은 trajectory 7개와 긴 trajectory 1개를 기다리는 batch에서 평균 tokens/s만 높이면 충분한가? FP8/MTP, prefill–decode 분리, heartbeat는 각각 느린 생성·자원 간섭·장애 중 무엇을 해결하는가?

#### asynchronous rollout–learner 분리

- **본문 출발점:** [§3.6, §4.1.1](https://arxiv.org/abs/2602.15763v2). slime server/rollout abstraction 위에서 inference rollout과 learner를 분리하고, K update마다 weight를 sync하며 optimizer를 reset한다.
- **작동과 필요:** multi-turn agent rollout은 길이가 달라 sync barrier에서 GPU idle time을 만든다. inference가 계속 trajectory를 만들고 learner가 threshold마다 update하면 throughput은 커지지만 rollout policy가 current learner보다 오래될 수 있다.
- **원전 경로:** slime 공개 구현은 [THUDM/slime](https://github.com/THUDM/slime)에서 확인할 수 있다. policy lag, weight sync, reset은 GLM-5 **자체 원전**이다.
- **경계:** GLM-4.5의 비동기 agent RL을 이어 rollout–learner 분리와 controller를 구체화한 **확장**이다. K·threshold·reset이 일반 최적값이라는 주장은 아니다.
- **확인 질문:** rollout이 learner보다 빨라질 때 policy lag가 생기는 순간을 policy version 번호로 그릴 수 있는가?

#### TITO와 DDIS

- **본문 출발점:** [§4.1.2, 식 (3)–(5)](https://arxiv.org/abs/2602.15763v2). TITO gateway가 token ID/metadata/rollout log-probability를 보존하고, direct double-sided importance sampling으로 ratio와 양쪽 clip mask를 정의한다.
- **작동과 필요:** learner에서 text를 재tokenize하면 action index와 advantage index가 어긋날 수 있다. TITO는 이를 막는다. `exp(log πθ−log πrollout)` ratio는 stale behaviour policy에서 나온 action을 current policy로 update할 때 off-policy bias를 제한하며, 양쪽 clipping은 overly-large와 overly-small ratio를 모두 막는다.
- **원전 경로:** GRPO group-relative baseline은 [DeepSeekMath v3 §4.1](https://arxiv.org/abs/2402.03300v3), TITO/DDIS는 GLM-5 **자체 원전**이다.
- **경계:** DDIS는 standard PPO의 asymmetric clipping을 그대로 복사한 것이 아니다. sampling temperature나 stale threshold의 보편적인 안전 범위도 제시하지 않는다.
- **확인 질문:** rollout text가 같아도 learner tokenizer가 다르면, token-level loss mask가 왜 틀어질 수 있는가?

#### failed group과 DP-aware KV locality

- **본문 출발점:** [§4.1.2](https://arxiv.org/abs/2602.15763v2). failed rollout을 버린 뒤 valid sample이 half group을 넘으면 복제해 채우고, 아니면 group 전체를 버린다. consistent hash로 rollout ID를 같은 DP rank에 둔다.
- **작동과 필요:** environment crash를 reward 0으로 쓰면 policy failure가 아닌 system failure를 학습한다. multi-turn prefix는 같은 rank로 보내야 KV cache prefill을 반복하지 않는다.
- **원전 경로:** 이 failure rule과 routing은 GLM-5 **자체 원전**이다. DP·KV-cache 기본은 [W05 attention/cache](../weeks/w05/README.md)를 재사용한다.
- **경계:** copied sample은 new exploration sample이 아니다. half-group threshold와 dynamic hash rebalancing은 infrastructure heuristic이다.
- **확인 질문:** 같은 trajectory의 valid sample을 복제해 group을 채우는 경우와 group 전체를 버리는 경우를 왜 `half group` 기준으로 나눴는가?

#### SWE와 terminal의 executable verifier

- **본문 출발점:** [§4.2.1–§4.2.2](https://arxiv.org/abs/2602.15763v2). RepoLaunch로 SWE F2P/P2P를, Harbor task schema/Docker/validator로 terminal task를 만든다.
- **작동과 필요:** environment는 benchmark가 아니라 policy가 outcome reward를 받을 수 있는 실행 계약이다. SWE는 issue–PR, setup, test/log parsing을 묶고, terminal construction agent는 자기 task를 Harbor validator로 고쳐 검증한다.
- **원전 경로:** 직접 인용한 [SWE-bench Goes Live! v1 §3–§4](https://arxiv.org/abs/2505.23419v1), [Harbor task tutorial](https://harborframework.com/docs/tasks/task-tutorial)를 읽는다. synthesis pipeline은 GLM-5 **자체 원전**이다.
- **경계:** Docker construction accuracy는 environment build 성공률이지 agent task success율이 아니다. verifier가 있어도 task specification의 ambiguity를 없애지는 않는다.
- **확인 질문:** F2P/P2P test를 모두 만족시키는 patch가 여전히 issue 요구를 놓칠 수 있는 경우는 무엇인가?

#### search WKG와 hierarchical context management

- **본문 출발점:** [§4.2.3–§4.2.4, Figure 8](https://arxiv.org/abs/2602.15763v2). WKG로 multi-hop QA를 만들고, old observation을 접는 keep-recent-k와 threshold Discard-all을 합친 HCM을 사용한다.
- **작동과 필요:** WKG는 early agent trajectory의 URL을 entity/relation graph로 정리해 multi-hop subgraph에서 query를 만든다. keep-recent-k는 최근 action/reasoning 흐름은 두되 오래된 tool observation만 `omitted` 처리하여 context budget을 되찾는다.
- **원전 경로:** WKG synthesis/HCM은 GLM-5 **자체 원전**이다. BrowseComp judge prompt/model dependence는 §4.2.4의 한계도 함께 읽는다.
- **경계:** HCM gain은 GLM-5의 BrowseComp setup에 대한 결과다. discard/fold가 모든 search task의 optimal memory policy라는 뜻은 아니다.
- **확인 질문:** Keep-recent-k는 과거 tool *observation*을 접고 reasoning/action은 어떤 형태로 남기는가? 이것이 단순 context truncation과 왜 다른가?

#### slide generation의 multi-level reward

- **본문 출발점:** [§4.2.5, Figure 9](https://arxiv.org/abs/2602.15763v2). static HTML attribute, runtime layout geometry, rendered perceptual feature의 세 reward level과 rejection/masking refinement를 쓴다.
- **작동과 필요:** markup parser만 통과시키면 overflow를 숨기거나 spacing을 조작하는 reward hacking이 가능하다. renderer의 bounding box와 perceptual whitespace를 함께 보면 declaration과 rendered outcome의 차이를 줄인다.
- **원전 경로:** reward hierarchy·renderer loop·mask refinement는 GLM-5 **자체 원전**이다.
- **경계:** report가 제시한 human win rate는 이 internal task/evaluation의 결과다. perceptual reward가 인간 미감을 완전히 대표한다는 보장은 없다.
- **확인 질문:** static attribute reward가 pass했는데 runtime geometry reward가 fail하는 HTML layout 예를 하나 만들 수 있는가?
