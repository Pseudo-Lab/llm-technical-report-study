# W13 — VibeThinker-1.5B → 3B를 읽기 위한 구성요소 지도

[W13 학습목표](../weeks/w13/README.md) · [배경 읽기 지도](README.md)

이 문서는 [VibeThinker-1.5B v1](https://arxiv.org/abs/2511.06221v1)과 [VibeThinker-3B v1](https://arxiv.org/abs/2606.16140v1)를 함께 읽는다. 두 보고서는 1.5B에서 제안한 SSP/MGPO를 3B가 그대로 계승하면서, data construction·long-context RL·offline distillation·instruction alignment를 구체화한다. 따라서 “3B가 새 알고리즘을 모두 발명했다”로 합치지 않는다.

## 1. base와 SFT: 정확도 하나가 아닌 solution spectrum

### base model과 주장 범위

- **본문 출발점:** [1.5B §1, §4.1–§4.2](https://arxiv.org/abs/2511.06221v1), [3B §2, §3.1–§3.2](https://arxiv.org/abs/2606.16140v1). 1.5B는 Qwen2.5-Math-1.5B, 3B는 Qwen2.5-Coder-3B를 base로 명시한다.
- **작동과 필요:** 보고서의 기여는 새로운 Transformer block/tokenizer가 아니라, 이미 존재하는 compact dense base 위의 post-training recipe다. 따라서 architecture 차이를 만들어내지 말고 base의 math-vs-code prior가 결과 해석에 미치는 영향을 분리한다.
- **원전 경로:** base 계열의 tokenizer/architecture 및 data를 이해하려면 [W02 Qwen 가이드](qwen.md)를 읽는다. Vibe 보고서는 base model의 hidden size, head, tokenizer, pre-training corpus를 재명세하지 않으므로 그 세부를 Vibe의 신규 기여로 쓰지 않는다.
- **경계:** 1.5B/3B의 새로움은 **후학습**이다. 1.5B가 knowledge benchmark에서 큰 모델과 gap을 인정하고, 3B도 broad knowledge에서는 보수적으로 해석한다는 범위를 Table 2와 §3.2에서 확인한다.
- **확인 질문:** 같은 “small model” 주장이라도 1.5B의 Qwen2.5-Math base와 3B의 Qwen2.5-Coder base는 code 결과를 비교할 때 어떤 교란 요인이 되는가?

### Pass@K와 solution spectrum

- **본문 출발점:** [1.5B §2, §3.1](https://arxiv.org/abs/2511.06221v1). Spectrum phase는 Pass@K가 높은 checkpoint를 먼저 확보하고, Signal phase가 RL로 correct path를 증폭한다.
- **작동과 필요:** `Pass@K = E[max_i R(x,y_i)]`는 K개의 independent rollout 중 하나라도 verifier를 통과할 확률이다. Pass@1만 높으면 동일한 한 path를 자주 낼 수 있지만, Pass@K가 높으면 verifier를 통과하는 alternative path가 rollout group에 나타날 확률이 더 크다.
- **원전 경로:** Pass@K와 solution diversity의 관계를 검토하려면 보고서가 직접 인용한 [Leveraging LLM Inconsistency to Boost Pass@K](https://arxiv.org/abs/2505.12938v1)를 읽는다. Spectrum-to-Signal의 정의는 1.5B §3.1 **자체 원전**이다.
- **경계:** Pass@K는 semantic diversity 자체의 완전한 측정이 아니라 verifier-positive alternative의 operational proxy다. 3B는 이 원칙을 **계승**한다.
- **확인 질문:** `Pass@1`이 같은 두 checkpoint에서 `Pass@K`가 다르면, RL rollout으로 얻을 수 있는 positive trace의 확률은 왜 달라지는가?

### domain-aware probing과 parameter fusion

- **본문 출발점:** [1.5B §3.2–§3.3, Figure 3](https://arxiv.org/abs/2511.06221v1). algebra/geometry/calculus/statistics probe별 `argmax_t P_i(t)` checkpoint를 고르고 `Σw_i M_i*`로 fuse한다.
- **작동과 필요:** 한 global checkpoint가 모든 math subdomain의 solution spectrum을 가장 넓게 갖는다고 전제하지 않는다. domain probe로 specialist checkpoint를 고른 다음 parameter average로 하나의 initial policy를 만든다.
- **원전 경로:** checkpoint selection과 weighted parameter fusion은 1.5B §3.2–§3.3 **자체 원전**이다. GRPO의 공통 objective만 [DeepSeekMath v3 §4.1](https://arxiv.org/abs/2402.03300v3)에서 읽는다.
- **경계:** parameter fusion은 verified trajectory를 SFT하는 3B의 offline self-distillation과 다른 통합 방식이다. report는 probe set의 완전한 분포나 fusion weight selection rule을 공개하지 않는다.
- **확인 질문:** parameter average로 fused model을 만드는 것과 여러 specialist output을 student SFT data로 넣는 것은 어떤 학습 signal이 다른가?

### trusted seed와 query expansion

- **본문 출발점:** [3B §2.1.1, Figure 3](https://arxiv.org/abs/2606.16140v1). credible answer/rationale가 있는 math seed와 executable test/rule가 있는 code seed에서 query를 확장한다.
- **작동과 필요:** seed answer의 신뢰 가능한 검증 고리를 먼저 두고 concept composition, constraint, evaluation objective를 바꾸면 query diversity를 늘리면서 target answer의 근거를 잃지 않는다.
- **원전 경로:** seed 조건과 expansion dimensions는 3B §2.1.1의 **자체 원전**이다.
- **경계:** report는 seed source license, exact prompting, generation count를 공개하지 않는다. trusted seed는 생성된 모든 new query의 정답성을 자동 보증하지 않는다.
- **확인 질문:** query expansion에서 concept만 바꾸는 경우와 evaluation objective까지 바꾸는 경우가 어떤 difficulty 축을 다르게 만드는가?

### multi-path teacher trace와 quality control

- **본문 출발점:** [3B §2.1.1](https://arxiv.org/abs/2606.16140v1). teacher multi-sampling/majority vote 뒤 n-gram, LLM, trace filter와 answer verification/code execution을 적용한다.
- **작동과 필요:** 여러 trace를 하나의 canonical rationale로 붕괴시키지 않고 verified path pool을 만든다. n-gram filter는 contamination/near-duplicate를, answer execution은 outcome을, LLM/trace filter는 reasoning format·quality를 각각 겨냥한다.
- **원전 경로:** 이 multi-path pipeline은 3B §2.1.1 **자체 원전**이다. 10-gram decontamination의 정의는 1.5B [§3.5](https://arxiv.org/abs/2511.06221v1)에서 함께 확인한다.
- **경계:** majority vote가 reasoning trace의 논리적 정당성을 보증하지는 않는다. 각 filter의 false-positive/false-negative rate는 보고하지 않는다.
- **확인 질문:** code execution이 통과한 trace라도 LLM trace-quality filter가 거를 수 있는 failure는 무엇인가?

### broad SFT→hard·long SFT curriculum

- **본문 출발점:** [3B §2.1.2, Figure 3](https://arxiv.org/abs/2606.16140v1). broad SFT 뒤 5K 이상 trace 및 1.5B 8 rollout error rate가 0.75 이상인 query로 hard·long SFT를 한다.
- **작동과 필요:** stage 1은 wide coverage와 basic format을 먼저 주고, stage 2는 long trajectory와 low-success prompt로 distribution을 옮긴다. 8 rollout accuracy가 25%를 넘는 easy query를 빼면 later SFT의 token budget이 이미 쉬운 target에 집중되는 것을 줄인다.
- **원전 경로:** two-stage filter와 threshold는 3B §2.1.2 **자체 원전**이다.
- **경계:** 0.75는 universal difficulty threshold가 아니라 이 report의 1.5B probe policy/8-sample 기준이다. stage 2가 모든 model size에서 더 낫다는 ablation은 없다.
- **확인 질문:** stage 2의 “error rate < 0.75 제거”는 정확도 25% 초과인 query를 제거한다는 뜻인데, 이것이 단순히 최저 accuracy example만 남기는 것과 다른 이유는 무엇인가?

## 2. RL: capability boundary와 output efficiency

### MGPO의 max-entropy weighting

- **본문 출발점:** [1.5B §3.4](https://arxiv.org/abs/2511.06221v1), [3B §2.2.1, 식 (1)–(3)](https://arxiv.org/abs/2606.16140v1). group accuracy `p(q)`가 0.5 근처인 query의 advantage에 `w(q)=exp(-γ D_ME(p(q)||0.5))`를 곱한다.
- **작동과 필요:** 모두 틀린 query는 positive signal이 없고 모두 맞는 query는 학습 여지가 작다. `p≈0.5`는 correct/incorrect rollout이 공존하는 capability boundary이므로, MGPO는 GRPO의 token ratio/clipping은 유지하면서 **prompt별** learning signal만 재가중한다.
- **원전 경로:** GRPO 는 [DeepSeekMath v3 §4.1](https://arxiv.org/abs/2402.03300v3). max-entropy deviation과 advantage weighting의 수식은 1.5B §3.4가 **제안 원전**, 3B는 같은 식을 **계승**한다.
- **경계:** “p=0.5가 항상 최적 curriculum”은 증명된 보편 법칙이 아니라 authors의 training hypothesis다. 1.5B의 `λ=0`이 standard GRPO로 돌아가는 식과 3B의 `p0=0.5`를 직접 대조한다.
- **확인 질문:** `p(q)=0`인 문제와 `p(q)=1`인 문제는 서로 다른 이유로 낮은 weight를 받는다. 각 경우 group-relative advantage에 어떤 정보가 부족한가?

### long-context RL과 Long2Short

- **본문 출발점:** [3B §2.2.2](https://arxiv.org/abs/2606.16140v1). 1.5B의 16K→32K progressive expansion과 달리 3B는 start부터 64K RL을 하고, accuracy-first MGPO 뒤 Long2Short을 둔다.
- **작동과 필요:** high-truncation warm-up은 3B의 이미 좋은 long trace를 잘라 incomplete reasoning을 선호하도록 만들 수 있다고 보고서는 해석한다. Long2Short은 binary reward가 1인 trace 집합 `C`에서만 `s_i=1/L_i` 기반 centered shift를 적용한다. 틀린 trace reward는 그대로여서 concise-but-wrong 답을 보상하지 않고, correct subset에서 shift 합이 0이라 group baseline을 체계적으로 밀지 않는다.
- **원전 경로:** progressive context baseline은 보고서가 직접 인용한 [FastCuRL](https://arxiv.org/abs/2503.17287v1)이다. single-64K 전환과 `λ=0.2` Long2Short 식은 3B **자체 원전**이다.
- **경계:** 1.5B와 3B의 context curriculum 결론이 반대라는 것은 모순이 아니라 initialization/data quality가 다른 두 보고서의 관찰이다. Long2Short은 output length를 무조건 최소화하는 objective가 아니다.
- **확인 질문:** correct trace들의 reward shift 합을 0으로 만들면, 긴 correct trace를 덜 선호하면서도 GRPO group mean에 어떤 불필요한 변화를 피하는가?

## 3. RL 후의 통합·정렬·test-time verification

### offline self-distillation의 learning-potential filter

- **본문 출발점:** [3B §2.3, 식 (4)](https://arxiv.org/abs/2606.16140v1). Math/Code/STEM RL checkpoint의 verified trajectory를 unified student로 SFT하며, `SLP(q,y)=-(1/|y|)Σlog π_stu(y_t|q,y_<t)`로 distillation value를 정한다.
- **작동과 필요:** teacher가 맞힌 trace도 student가 이미 높은 확률로 낼 수 있으면 새 학습 신호가 작다. length-normalized NLL이 높은 verified trace를 우선하되, domain별 length bucket 안에서 고르고 extreme short/high-score outlier는 걸러 length·format artifact를 피한다.
- **원전 경로:** 이 SLP, bucketing, middle-to-high priority는 3B **자체 원전**이다. 1.5B의 parameter fusion과 혼동하지 말고, 여기서는 output trajectory를 SFT해 capability를 통합한다.
- **경계:** 높은 student NLL이 항상 좋은 pedagogical sample을 뜻하지 않으므로 verifier와 outlier filter가 먼저 필요하다. teacher/student architecture·sampling rate 세부는 공개되지 않는다.
- **확인 질문:** verified trace를 global NLL 순으로만 뽑으면 length bucket을 둔 경우보다 어떤 편향이 생길 수 있는가?

### Instruct RL의 constraint validator와 rubric reward

- **본문 출발점:** [3B §2.4](https://arxiv.org/abs/2606.16140v1). Instruct RL은 executable constraint validator와 rubric reward model을 함께 사용한다.
- **작동과 필요:** format/order/count/keyword처럼 기계적으로 판단할 조건은 validator가 직접 평가하고, helpfulness/coherence 같은 열린 품질은 rubric RM이 평가한다. 이 둘을 분리하면 “형식은 맞지만 도움이 안 되는 답”과 그 반대의 failure를 구별해 on-policy reward를 준다.
- **원전 경로:** Instruct RL의 reward 구성은 3B §2.4 **자체 원전**이다. IFEval은 결과 평가 benchmark이지 이 RL data-generation method의 원전이 아니다.
- **경계:** report는 RM training data와 reward mixture weight를 공개하지 않는다. validator pass가 semantic correctness 보증은 아니다.
- **확인 질문:** count constraint를 만족하지만 user intent를 놓친 답에서 validator와 rubric RM은 각각 어떤 점수를 줄 수 있는가?

### CLR의 claim-level test-time verification

- **본문 출발점:** [3B §3.1, 식 (5)–(6), Tables 1–2](https://arxiv.org/abs/2606.16140v1). K=32 candidate에서 M=5 decision-relevant claim을 self-verify하고 reliability-weighted answer cluster를 고른다.
- **작동과 필요:** CLR은 parameter를 update하지 않는다. long trace 전체를 다시 judge하지 않고 answer의 핵심 claim별 binary verdict를 평균·거듭제곱해 reliability로 쓰고, equivalent answer cluster에 candidate evidence를 합쳐 선택한다.
- **원전 경로:** claim selection, reliability score, clustering은 3B §3.1 **자체 원전**이다.
- **경계:** self-verifier가 자기 오류를 독립적으로 잡는다는 보장은 없으며 CLR은 answer-verifiable task에서만 제시된다. Table 2의 `+ CLR`은 single-pass base result와 같은 inference budget이 아니다.
- **확인 질문:** CLR에서 candidate answer를 trajectory 단위가 아니라 equivalence cluster로 모으는 이유와, `r_k`가 한 claim 오류를 강하게 벌하는 이유를 각각 설명할 수 있는가?
