# W15 — Motif 2 → Motif 3: 본문 구성요소와 선행 개념

[W15 학습목표](../weeks/w15/README.md) · [전체 읽기 지도](README.md) · [읽기 분담](workload.md)

## 이번 주 읽기 범위

Motif 3는 GDLA·Parallel Muon·MOPD만 추가한 한 단계짜리 보고서가 아니다. Motif 2의 기능 보존 확장과 mixture scheduling 위에, Motif 3가 latent attention·multi-stream residual·expert 안정화·long-context system·specialist RL을 각각 바꾼 경로다. 다음은 보고서 본문에서 실제로 필요한 개념을 기능 단위로 나눈 읽기 지도다.

공통 읽기는 [주차별 분담표](workload.md)에 적힌 대상 본문으로 시작한다. 담당 심화에서는 아래 구성요소 중 한 갈래와 필요한 선행 원전의 지정 절을 읽는다.

## 본문 구성요소와 선행 개념

### 1. Motif 2의 확장: clone, depth, data schedule은 다른 축이다

[Motif 2 v1 §2·Table 1](https://arxiv.org/abs/2511.07464v1)는 2.6B→12.7B를 [Scaling Smart v1 §2·Appendix A](https://arxiv.org/abs/2409.12903v1)의 **HyperCloning**으로 width 확장한 뒤, [LLaMA-Pro v1 §1·§3.1](https://arxiv.org/abs/2401.02415v1)의 depth expansion으로 layer를 늘렸다고 쓴다. HyperCloning은 작은 model의 hidden representation을 복제하고 선형·attention·normalization 초기값을 맞춰 큰 width에서도 초기 function을 보존한다. LLaMA-Pro는 copy한 새 Transformer block의 linear layer를 zero-initialize해 identity로 시작시키는 depth 확장이다. Motif 2의 구체적 복제·통합 순서는 §2에서 확인한다. 복제해 표현 공간/초기 통계를 보존하는 width expansion, 새 layer를 넣는 depth expansion, GDA attention을 넣는 것은 별개다.

[Motif 2 §3.1–§3.2](https://arxiv.org/abs/2511.07464v1)는 early web 중심 mixture에서 reasoning/math/code 비율을 점차 높이고, final annealing에서 reasoning 비율을 10% 아래로 제한하며 4K→16K length로 늘린다. 이 **data-mixture scheduler**는 optimizer learning-rate schedule과 비슷하게 step마다 data ratio를 바꾸지만, gradient update 규칙은 바꾸지 않는다.

**작은 점검.** 어떤 block을 네 번 복제해 width를 늘리는 일과, 동일 block 사이에 새 layer를 넣어 depth를 늘리는 일을 그림으로 구분한다. 둘 다 pretraining을 더 해야 하지만, 어느 것이 새 representation을 초기화하는지 본문 범위에서만 답한다.

#### Motif 2의 three-stage SFT는 RL의 축약판이 아니다

[Motif 2 §5.1.1–§5.1.3](https://arxiv.org/abs/2511.07464v1)는 Stage 1에서 약 28M open/proprietary instruction sample로 일반 instruction-following을 세우고, Stage 2에서 합성 compositional reasoning·algorithm/math data를 더해 curriculum을 이어 간다. Stage 3은 Stage-2 합성 data 중 redundant/low-utility sample을 **제거한** subset으로 다시 학습하는 data-pruned refinement다. 이때 pruning criterion은 diversity·reasoning coherence·linguistic fidelity이고, reward를 maximize하거나 policy rollout을 새로 생성하는 RL objective가 아니다.

**sequence packing의 국소 용례.** §5.1.1의 16,384-token packing은 길이가 다른 examples를 한 sequence 안에 넣어 padding을 줄이고 GPU token utilization을 높이는 batching 방식이다. packing이라는 표현만으로 example 사이 attention mask까지 적용했다고 추정하지 않는다. 이 절은 그 mask 설계를 공개하지 않는다. Stage 1의 all-parameter unfreeze와 Stage 3의 data selection은 각각 *무엇을 update하는가*와 *무엇을 보여 주는가*라는 다른 선택이다.

**작은 점검.** Stage 2의 “synthetic augmentation”과 Stage 3의 “synthetic data pruning”이 dataset 크기·분포·학습 목적에서 어떻게 반대 방향인지, 그리고 왜 둘 다 RL이라고 할 수 없는지를 적는다.

#### Motif 2의 FP8 학습과 fused PolyNorm

[Motif 2 §4.1–§4.2](https://arxiv.org/abs/2511.07464v1)는 TorchTitan을 사용한 분산 학습에서 **row-wise scaling FP8와 BF16 gradient**를 조합한다. FP8은 작은 값 범위를 scale과 함께 표현하는 저정밀 형식이며, gradient를 BF16에 남기는 선택은 모든 tensor를 같은 dtype으로 낮추는 것과 다르다. FP8의 scale·accumulation 기초는 [W06](w06.md)에서 읽고 Motif 2의 dtype 배치를 확인한다.

같은 보고서는 기존 Motif-2.6B의 **PolyNorm**을 채택해 scaling·reduction·normalization을 CUDA kernel 하나로 묶고, 다음 FFN elementwise multiplication까지 fuse한다. 목적은 중간 tensor의 메모리 왕복과 kernel launch overhead를 줄이는 것이다. 이는 아래 Motif 3의 **expert마다 다른 계수를 학습하는 Expert-Specific PolyNorm**과 구별할 변경점이다. PolyNorm 함수 자체, 같은 함수의 fused 실행, expert별 함수 shape를 차례로 비교한다. 공개 구현은 본문이 연결한 [Motif activation 저장소](https://huggingface.co/Motif-Technologies/activation)이며 선택 읽기다.

**점검:** BF16으로 비교한 Table 3의 kernel speedup을 FP8 pre-training 전체의 speedup으로 옮겨 써도 되는가? 연산 구현 비교와 training precision 설정의 조건을 나눈다.

### 2. Differential Attention → GDA → GDLA: 세 문제를 한 효과로 합치지 않기

[Differential Transformer v2 §2.1](https://arxiv.org/abs/2410.05258v2)은 두 attention map 차분으로 common-mode noise를 누르려 한다. [Grouped Differential Attention v1 §2.2](https://arxiv.org/abs/2510.06949v1)은 signal/noise head를 비대칭 group으로 나누고 noise path를 repeat해 signal head와 짝짓는다. Motif 2 §2는 그 GDA를 4:1 signal/noise head ratio로 넣었다고 보고한다.

[Motif 3 §2.2.1–§2.2.3·식 (1)–(15)·Fig. 1](https://arxiv.org/abs/2608.09119v1)는 이를 **GDLA**로 바꾼다. query/KV를 low-rank latent로 압축해 하나의 latent KV를 확장한 뒤 signal/noise query path를 만들고, `D_t=H^S_t−λ_t⊙Repeat_g(H^N_t)`로 noise path를 뺀다. `λ`는 sigmoid라 억제만 하고 반전·증폭은 하지 않으며, 마지막 output gate는 query latent에서 각 signal-value channel에 걸린다. [DeepSeek-V2 v5 §2.1](https://arxiv.org/abs/2405.04434v5)은 latent KV cache를 줄이는 MLA의 배경이다.

여기서 차분은 signal/noise 분리, latent는 KV cache 압축, output gate는 channel별 출력 조절을 해결하려는 서로 다른 장치다. GDLA가 MLA와 “동일한 attention”이라는 말도, differential attention이 noise를 반드시 0으로 만든다는 말도 본문보다 강하다.

**작은 점검.** 한 noise head를 group의 여러 signal head에 repeat한 이유와 `λ=1`·두 map 값이 같을 때 차분이 0이 되는 toy case를 나눠 설명한다.

### 3. residual route와 expert activation: mHC·PolyNorm은 attention의 일부가 아니다

[Motif 3 §2.3·식 (16)–(23)](https://arxiv.org/abs/2608.09119v1)는 ordinary residual addition 대신 네 parallel residual stream을 read/transform/write로 섞는 modified mHC를 쓴다. 직접 인용한 [mHC v2 §3–§4.2](https://arxiv.org/abs/2512.24880v2)에서 residual mixing을 doubly stochastic matrix로 제한하는 이유와 Sinkhorn–Knopp projection을 먼저 읽는다. HC 자체가 낯설면 이 원전이 인용한 [Hyper-Connections v3 §2.1–§2.3](https://arxiv.org/abs/2409.19606v3)을 앞 단계로 보충한다. 이후 Motif 3가 post-mapping multiplier를 2에서 1로 anneal해 activation outlier 누적을 줄였다는 본문을 확인한다. 이는 attention head grouping과 다른 **layer 간 경로** 선택이다.

[Motif 3 §2.4·식 (24)–(27)](https://arxiv.org/abs/2608.09119v1)는 MoE expert마다 polynomial coefficient/bias가 다른 Expert-Specific PolyNorm을 쓴다. 입력의 각 power를 RMS-normalize하고 constrained coefficient로 합쳐, routed token 분포가 다른 expert가 같은 SiLU shape에 묶이지 않도록 한다. `effective rank`는 gate-weight singular-value energy가 여러 방향에 얼마나 퍼졌는지 보는 측정이며, expert routing의 load balance 그 자체가 아니다.

**작은 점검.** “어느 residual stream에서 읽는가”와 “expert의 gated FFN이 어떤 비선형 곡선을 쓰는가”를 각각 한 문장으로 적는다. 둘 다 MoE stability와 관계가 있어도 같은 parameter를 조절하지 않는다.

### 4. MoE는 routing balance, functional diversity, numerical range를 모두 감시한다

[Motif 3 §4.2·식 (28)–(33)·Table 3](https://arxiv.org/abs/2608.09119v1)은 다음 failure mode를 구분한다.

| 본문 장치 | 필요한 이유 | 확인할 값 |
| --- | --- | --- |
| FP32 router + expert-selection bias + sequence-wise auxiliary loss | discrete top-k 선택의 수치 오차와 early-layer load collapse | `min_i N_i / median_i N_i` |
| 초기 Gaussian router noise의 cosine decay | 아직 학습되지 않은 expert에 token이 전혀 가지 않는 self-reinforcement 완화 | 초기에는 탐색, 역할 형성 뒤에는 noise 제거 |
| FFN output의 soft magnitude penalty | gated product의 outlier를 hard clipping 없이 억제 | `ReLU(|y|-τ)^2` |
| routed/shared output과 expert-output cosine monitor | token count가 균등해도 expert가 같은 함수가 되는 collapse 발견 | routed/shared RMS, output cosine |

[DeepSeek-V3 v2 §2.1.2](https://arxiv.org/abs/2412.19437v2)를 보면 auxiliary-loss-free bias의 배경을 확인할 수 있지만, Motif 3은 실제로 auxiliary loss도 함께 사용한다. 그래서 “bias만 써서 balance한다”는 식으로 바꾸어 말하면 안 된다. Motif 3의 router collapse 때 adjacent stable layer의 router/bias로 교체한 회복 절차는 이 보고서의 recipe다.

**작은 점검.** 두 expert가 동일 token 수를 받되 output cosine이 0.95이면 어떤 failure가 남는지, 반대로 cosine은 낮지만 dispatch min/median이 0.1이면 어떤 failure인지 나눈다.

### 5. Parallel Muon과 long context: optimizer geometry와 attention communication을 분리한다

[Muon Is Scalable v1 §2.1–§2.3·Algorithm 1](https://arxiv.org/abs/2502.16982v1)은 2D matrix update를 Newton–Schulz로 semi-orthogonal하게 만드는 Muon의 분산 배경이다. [Motif 2 §4.3·Algorithm 1·Fig. 1·Table 4](https://arxiv.org/abs/2511.07464v1)는 full gradient를 rank마다 모두 재구성해 같은 Newton–Schulz를 반복하는 방식 대신, All-to-All로 shard를 바꾸어 서로 다른 matrix block을 계산하고 다시 scatter한다. FSDP/TP+HSDP에서도 “full logical matrix의 update”라는 의미를 유지하려는 것이다. pipelining/FLOPs-sorted scheduling은 communication과 computation overlap/straggler를 줄이는 배치 기법이지 Muon 목적식이 아니다.

[Motif 3 §3.1–§3.5](https://arxiv.org/abs/2608.09119v1)는 TP/PP/CP/FSDP2, FP8, FlashAttention, Ring/Ulysses 계열 context parallelism, 256K length stage를 함께 다룬다. attention communication은 long sequence의 activation/KV를 어떻게 rank에 나누는 문제이고, Muon All-to-All은 optimizer gradient matrix를 재배치하는 문제다. 둘 다 collective를 써도 교환하는 tensor와 시점이 다르다.

#### FSDP·EP·CP는 같은 “GPU 병렬화”가 아니다

[Motif 3 §3.1·§3.2·Fig. 3](https://arxiv.org/abs/2608.09119v1)에서 **EP=8**은 한 8-GPU node 안에서 routed token을 해당 expert로 dispatch/combine하는 축이다. **DP-shard=8**은 parameter·gradient shard를 나누는 FSDP group, **DP-replicate**는 그 shard group의 복제본 사이에 최종 gradient를 합치는 축이다. 따라서 Reduce-Scatter는 gradient를 목적 rank별 shard로 나눠 교환·합산한 뒤 shard 상태로 남기고, intermediate microbatch에서는 DP-replicate All-Reduce를 미루며 마지막에만 전역 gradient를 맞춘다. 이는 모든 rank가 full parameter/gradient를 들고 있는 data parallel과 다르다.

**activation recomputation**은 backward 때 저장하지 않은 forward를 다시 계산해 activation memory를 compute와 맞바꾸는 선택이다. Motif 3는 128K까지 필요한 operator만, 256K stage에서는 full block을 recompute한다(§3.1). Expert weight를 microbatch 사이에 MXFP8 unsharded copy로 남겨 All-Gather를 줄이는 것(§3.1)도 activation checkpoint와 같은 memory 항목을 줄이는 기법이 아니다.

**MXFP8의 국소 용례.** §3.2·Fig. 3은 expert weight/dispatch activation을 MXFP8로 두되 gradient shard 교환은 BF16으로 하고 각 rank에서 FP32으로 reduce한다고 명시한다. activation을 EP dispatch *전에 한 번* quantize해 dispatch 통신량을 줄이고, row-wise expert weight만 All-Gather한 뒤 column-wise copy는 local transcode한다. 그러므로 “Motif 3 전체를 FP8로 학습했다”가 아니라 MoE의 compute·communication 병목에 정밀도를 선택적으로 쓴 recipe다.

#### 긴 문맥에서 왜 layer마다 다른 collective를 고르는가

Motif 3 §3.5는 **CP=8**을 long sequence에서만 EP dimension 위에 재사용한다. full-attention layer에는 [Ulysses v1 §1·§3](https://arxiv.org/abs/2309.14509v1)를, 128-token sliding-window layer에는 [Ring Attention v1 §1–§3](https://arxiv.org/abs/2310.01889v1)의 window-aware 경로를 쓴다. Ulysses는 sequence/head dimension을 All-to-All로 transpose해 document-packed input의 rank imbalance를 피하지만, communication `Θ(L)`은 window가 작아도 줄지 않는다. 반대로 sliding window는 이전 rank의 trailing `W` KV만 halo exchange하면 되어 `Θ(W)`이고, 이 보고서는 해당 layer에서 이 경로를 택한다. 이 선택은 GDLA의 latent KV나 Parallel Muon과 별개인 **context-parallel runtime** 결정이다.

#### MTP는 teacher distillation이 아니라 draft-token 보조 head다

[Motif 3 §2.5](https://arxiv.org/abs/2608.09119v1)는 [DeepSeek-V3 v2 §2.1.3](https://arxiv.org/abs/2412.19437v2)의 multi-token prediction을 auxiliary pretraining objective로 두고, 이를 self-speculative decoding draft head로 쓴다. primary autoregressive decoder를 구조적으로 바꾸지는 않는다. Motif 3가 specialist RL/MOPD에서 MTP weights를 freeze하는 이유(§5.2.3)는 draft acceptance와 routing configuration을 보존하려는 것이며, MTP가 seven teacher의 supervised signal을 낸다는 뜻은 아니다.

### 6. Motif 3의 tokenizer·mixture와 specialist pipeline

[Motif 3 §4.1·Appendix A.1·Table 2](https://arxiv.org/abs/2608.09119v1)는 [SuperBPE v1](https://arxiv.org/abs/2503.13423v1)의 two-stage idea처럼 1단계 BPE 뒤에 공백으로 구분된 letter run을 하나의 pre-tokenization unit으로 허용한다. “of the”, “수 있다” 같은 superword가 가능한 이유는 merge 규칙만이 아니라 pre-tokenization boundary를 바꾸었기 때문이다. [BPE v1 §3.2](https://arxiv.org/abs/1508.07909v1)는 BPE의 최소 배경이고, Motif 3의 Stage-2 regex·compression 결과는 본문/Appendix에서 확인한다. bytes per token은 tokenizer compression 지표이지 downstream capability 점수가 아니다.

원전에서는 [SuperBPE v1 §2.1–§2.3](https://arxiv.org/abs/2503.13423v1)가 기존 BPE pre-tokenization, Stage-2 superword pre-tokenization, bytes-per-token 효율을 차례로 정의한다. 따라서 Stage-2를 “BPE merge를 더 많이 한 것”으로 바꾸어 읽지 않는다.

같은 §4.1의 19→57 dataset dynamic mixture schedule은 early general data에서 STEM/math/code/synthetic QA/reasoning 비중을 step-level로 늘린다. Motif 2의 방향을 계승했지만 training token 수·tokenizer·각 dataset 비율이 같다는 뜻은 아니다.

마지막으로 [Motif 3 §5.1–§5.2.4·식 (35)–(37)·Table 5](https://arxiv.org/abs/2608.09119v1)는 general SFT 뒤 **6 GRPO specialist + 1 software-engineering SFT teacher**를 만들고, 13 verifier domain을 latency/reward variance가 비슷한 job으로 나눈다. asynchronous collector는 one-step age bound와 token importance correction을 쓰며, MOPD에서는 prompt별 routed teacher가 student의 on-policy token에 준 scalar log probability만 쓴다. environment reward와 reference KL은 MOPD loss에 넣지 않는다. §5.2.4가 직접 인용한 [Every Step Evolves (IcePop) v1 §2.3.2·식 (1)–(3)](https://arxiv.org/abs/2510.18855v1)은 training/inference probability mismatch가 큰 token의 update를 양쪽 경계 밖에서 mask하는 GRPO 변형이다. Motif는 그 **interval filter**를 `πold/πgen` importance weight에 재사용해 범위 밖 token을 0으로 만들지만, IcePop의 full RL objective·advantage·KL 항을 MOPD에 그대로 채택한 것은 아니다.

**작은 점검.** 7명이 “7개 domain”이 아니라 13 verifier domain을 맡는 7 teacher임을 표로 적는다. agent tool-use의 binary outcome, professional work의 pairwise judge, SWE의 tests-passing trajectory SFT가 왜 한 reward distribution이 아닌지 설명한다.

### 연결 주차와 범위

- **W15:** GDLA·Parallel Muon·specialist/MOPD 목표를 읽는 핵심 경로다.
- **W06/W10:** FP8/MoE balance·OPD와 겹치는 용어가 있어도, W15에서는 Motif 3의 actual router recovery·teacher routing·importance filter에만 집중한다.

### 원전 사용 원칙

- 숫자·식·구성값·seven-teacher 정의는 [Motif 2 v1](https://arxiv.org/abs/2511.07464v1) 및 [Motif 3 v1](https://arxiv.org/abs/2608.09119v1)의 본문/appendix에서만 가져온다.
- Hypercloning, GDA, MLA, mHC, Muon, BPE, GRPO는 필요한 원전 경로다. 그 원전의 구현이나 실험을 Motif가 재현·채택했다고 본문보다 넓게 주장하지 않는다.
