## 이번 주 읽기 범위

Qwen1.5에는 이 주차의 비교에 쓸 technical report가 없다. 따라서 **공식 출시 글과 고정 checkpoint config**가 Qwen1.5의 1차 자료이고, Qwen2 v4가 구조·data method의 1차 자료다. 출시 글이 말한 32K 지원·PPO/DPO와 config가 보여 주는 head 수를 논문 실험이나 미공개 학습 recipe로 확대하지 않는다.

공통 읽기는 [주차별 분담표](workload.md)에 적힌 대상 본문으로 시작한다. 담당 심화에서는 아래 구성요소 중 한 갈래와 필요한 선행 원전의 지정 절을 읽는다.

**연결 자료:** [W04의 Qwen2.5 → Qwen3 가이드](w04.md#qwen25-handoff)

## 본문 구성요소와 선행 개념

<a id="qwen-architecture"></a>
### 1. 같은 7B checkpoint로 MHA → GQA를 확인한다

`max_position_embeddings`는 공개 checkpoint의 configured maximum이다. native pre-training length와 DCA+YaRN으로 처리할 수 있다고 쓴 length는 별도의 숫자다.

| 대응 model | 고정 config / 공식 자료 | Qwen2 본문으로 확인할 변화와 경계 |
| --- | --- | --- |
| [Qwen1.5-7B](https://huggingface.co/Qwen/Qwen1.5-7B/blob/831096e3a59a0789a541415da25ef195ceb802fe/config.json) | 32 layers, Q/KV heads=32/32, `rope_theta=1,000,000`, maximum=32,768, `vocab_size=151,936`. [공식 출시 글](https://qwenlm.github.io/blog/qwen1.5/)은 32K 지원과 PPO/DPO 정렬을 공개한다. | `Q=KV=32`는 MHA다. token 하나마다 32 K/V head cache가 있다. |
| [Qwen2-7B](https://huggingface.co/Qwen/Qwen2-7B/blob/453ed1575b739b5b03ce3758b23befdb0967f40e/config.json) | 28 layers, Q/KV=28/4, `rope_theta=1,000,000`, configured maximum=131,072, `vocab_size=152,064`. | [Qwen2 v4 §2.2.1](https://arxiv.org/abs/2407.10671v4)은 MHA 대신 GQA를, §3.2는 4,096→32,768 native long-context training과 DCA+YaRN 131,072 처리 주장을 구분한다. `28/4`이면 7 query head가 한 KV head를 공유한다. |
| [Qwen2.5-7B](https://huggingface.co/Qwen/Qwen2.5-7B/blob/d149729398750b98c0af14eb82c78cfe92750796/config.json) | Q/KV=28/4와 configured maximum=131,072은 Qwen2-7B와 같다. | **W04 handoff 전용 비교 행**이다. Qwen2.5의 BBPE control token, task-specific synthesis, long-context recipe는 [W04](w04.md#qwen25-handoff)에서 Qwen3와 함께 읽는다. |

**계열 일반화 금지.** [Qwen1.5-110B의 고정 config](https://huggingface.co/Qwen/Qwen1.5-110B/blob/16659038ecdcc771c1293cf47020fa7cc2750ee8/config.json)는 Q/KV=64/8이고, [Qwen1.5-MoE-A2.7B](https://huggingface.co/Qwen/Qwen1.5-MoE-A2.7B/blob/1a758c50ecb6350748b9ce0a99d2352fd9fc11c9/config.json)는 60 expert/top-4다. 그러므로 7B의 MHA→GQA를 Qwen1.5 전체의 변화로 쓰거나, Qwen2 MoE를 7B의 직접 후속 구조로 쓰면 안 된다.

| Qwen2 본문 근거 | 함께 읽을 원전과 범위 | 작동·점검 |
| --- | --- | --- |
| [§2.2.1](https://arxiv.org/abs/2407.10671v4)의 GQA | [GQA v3 §2–§3](https://arxiv.org/abs/2305.13245v3) | MHA는 `Q=KV`, MQA는 `KV=1`, GQA는 그 중간이다. Qwen2-7B의 `28/4`를 써서 KV cache head 수가 왜 줄어드는지 계산한다. |
| [§2.2.1·§3.2](https://arxiv.org/abs/2407.10671v4)의 DCA+YaRN과 32K training | [DCA v2 §1·§3.1–§3.4](https://arxiv.org/abs/2402.17463v2), [YaRN v3 §2–§4](https://arxiv.org/abs/2309.00071v3) | DCA는 chunk 안/사이/인접 chunk의 position 처리를, YaRN은 RoPE context extension을 다룬다. 32K training, 128K/131K inference handling, config maximum을 한 숫자로 합치지 않는다. |
| [§2.1](https://arxiv.org/abs/2407.10671v4)의 Qwen tokenizer | [Qwen v1 §2.2](https://arxiv.org/abs/2309.16609v1) → [Byte-Level Subwords v2 “Byte Level Text Representation”](https://arxiv.org/abs/1909.03341v2) → [BPE v1 §3.2](https://arxiv.org/abs/1508.07909v1) | Qwen2는 Qwen tokenizer의 byte-level BPE와 151,643 regular/3 control token을 쓴다. config vocabulary와 논문이 말하는 logical regular/control token 수는 같은 종류의 수가 아니다. Qwen2.5의 control-token 확장은 W04에서만 확인한다. |

#### Qwen2 dense checkpoint를 MoE로 옮기는 초기화

[Qwen2 v4 §2.2.2, Eq. (1)–(2), Table 1](https://arxiv.org/abs/2407.10671v4)을 먼저 읽는다. 그 뒤 [DeepSeekMoE v1 §3.1–§3.2, Fig.2](https://arxiv.org/abs/2401.06066v1)의 fine-grained/shared-routed expert와 [Sparse Upcycling v2 §3·§3.1·§4.2.2](https://arxiv.org/abs/2212.05055v2)의 dense MLP 복제·router initialization을 읽는다. Qwen2의 intermediate-dimension shuffle과 expert별 50% random re-initialization은 **Qwen2 자체 공개**다. 이 절은 W03에서 initialization을, W05에서 V2의 expert 분할·통신을 읽도록 나눈다.

<a id="instruction-pool"></a>
### 2. instruction pool: 고르기와 어렵게 만들기를 분리한다

[Qwen2 §4.1.1](https://arxiv.org/abs/2407.10671v4)의 순서는 `open-set ontology → tag/representative selection → constraint addition → human ranking → demonstration/preference`다. ontology extraction은 evolution 내부 단계가 아니다. §4.1.2의 자동 합성은 다음 절의 별도 경로다.

| Qwen2 본문 근거 | 필요한 읽기와 범위 | 작동·공개 경계 |
| --- | --- | --- |
| §4.1.1의 InsTag 기반 ontology와 selection | [InsTag v2 §3.1–§3.4, §4–§4.1](https://arxiv.org/abs/2308.07074v2) | predefined label set 없이 intent tag를 붙이고 lexical/semantic/association noise를 정리한다. Qwen은 diversity·semantic richness·complexity·intent completeness를 썼지만, selection score와 threshold는 공개하지 않았다. |
| §4.1.1의 representative selection 인용 | [SFT Data Composition v4 §2–§3](https://arxiv.org/abs/2310.05492v4) | data amount/domain composition/SFT strategy의 관계를 확인한다. 이 원전에는 Qwen의 네 selection criterion을 계산하는 알고리즘이 없으므로 그 점수식으로 귀속하지 않는다. |
| §4.1.1의 constraint-based self-evolution | [Tree-Instruct §3, Fig.2](https://aclanthology.org/2024.lrec-main.1460/) | `instruction → semantic tree → meaningful node 추가 → 새 instruction`은 Tree-Instruct의 구체 방법이다. Qwen이 semantic tree나 node count를 썼다고 보고하지 않았다. |

**작은 점검.** “JSON API 예제와 오류 처리를 설명하라”에 API 작성·JSON 형식·오류 처리 tag를 붙인다. 이후 “두 labeled section으로 정상·실패 응답을 비교하라”를 더할 때, 전자는 pool coverage/selection이고 후자는 evolution이다.

<a id="qwen2-synthesis"></a>
### 3. Qwen2의 scalable synthesis: 어떤 신호가 무엇을 판정하는가

아래는 저자가 선수 학습 순서로 제시한 것이 아니라 Qwen2 본문의 직접 인용을 따라 편집한 읽기 순서다. Qwen2.5의 확장된 instruction/math/code/system-prompt recipe는 [W04](w04.md#qwen25-synthesis)에서 다룬다.

| Qwen2 본문 근거 | 함께 읽을 원전과 범위 | 작동·경계·작은 점검 |
| --- | --- | --- |
| [§4.1.2 Data Repurposing](https://arxiv.org/abs/2407.10671v4)의 profile role-play | [Ditto v1 §3.2–§3.4](https://arxiv.org/abs/2401.12474v1) | profile → role-conditioned question/contrast question → profile-conditioned response → SFT다. profile 밖 사실을 묻는 질문에는 모른다고 해야 한다. Qwen2가 Ditto의 모든 database/template를 그대로 채택했다고 쓰지 않는다. |
| [§4.1.2 Execution Feedback](https://arxiv.org/abs/2407.10671v4)의 code test와 instruction Python verifier | [AutoIF v1 §3.2–§3.4](https://arxiv.org/abs/2406.13542v1) | `instruction → checker/test → execute → pass response 보존`은 실행 가능한 제약을 판정한다. checker가 뜻하는 제약과 원 instruction의 의미는 별도 문제다. Qwen2.5의 verification-code cross-validation과 DPO reuse는 W04의 변경이다. |
| [§4.1.2 Rejection Sampling](https://arxiv.org/abs/2407.10671v4)의 math reasoning path | Qwen2 §4.1.2 | definitive final answer가 맞고 reasoning도 reasonable한 path를 demonstration으로 보존하고, correct/incorrect path로 preference를 만든다. final answer check가 process-quality model 전체를 대체한다고 쓰지 않는다. |
| [§5.2.1](https://arxiv.org/abs/2407.10671v4)의 IFEval 사용 | [IFEval v1 §2.1–§2.2](https://arxiv.org/abs/2311.07911v1); [AutoIF v1 §4.1](https://arxiv.org/abs/2406.13542v1) | IFEval은 instruction-following **evaluation benchmark**다. generated checker/unit-test SFT data와 같은 데이터로 취급하면 train/evaluation boundary가 사라진다. |

Qwen2는 collaborative annotation(`tag/selection/evolution/human ranking`)과 automated synthesis(`rejection/execution/role-play/constitutional feedback`)를 구분한다. 같은 “품질”이라는 말로 human preference, exact answer, executable test, profile faithfulness를 한 점수로 합치지 않는 것이 이 주차의 확인 질문이다.
