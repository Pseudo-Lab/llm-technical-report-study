## 이번 주 읽기 범위

[Llama 2 v2](https://arxiv.org/abs/2307.09288v2)의 §2.1–§2.2, Table 1, Appendix A.2.1, §3.2.1–§3.2.3, Eq. (1)–(4), Figures 6–8, §5.1–§5.2가 1차 범위다. **공통**으로는 LLaMA 1에서 계승한 recipe와 실제 구조 변화를 표로 분리하고, §3.1–§3.2의 SFT→선호/RM→RLHF 흐름을 확인한다. 세부 유도는 담당 심화로 나누며, 각자는 아래에서 **한 갈래**를 맡아 필요한 원전의 지정 범위만 깊게 읽는다.

| 공통 또는 담당 갈래 | 이번 주에 확인할 대상 본문 | 깊게 읽을 때의 질문 |
| --- | --- | --- |
| 공통: 계승과 구조 변화 | §2.2, Table 1 | tokenizer·RMSNorm·SwiGLU·RoPE·AdamW의 계승과 2K→4K context/GQA를 구분할 수 있는가? |
| 담당: GQA와 KV cache | Appendix A.2.1, Tables 16–18, Figure 24 | MHA/MQA/GQA의 KV projection 수와 34B·70B 적용 범위를 설명할 수 있는가? |
| 담당: preference RM | §3.2.1–§3.2.2, Eq. (1)–(2), Table 7–8, Figure 6 | chosen/rejected 및 rating margin이 reward-model ranking loss에 어떻게 들어가는가? |
| 담당: iterative RLHF | §3.2.3, Eq. (3)–(4), Figures 7–8, §5 | rejection-sampled SFT와 PPO/KL penalty는 어떤 순서와 역할 차이가 있는가? |

BPE·RMSNorm·SwiGLU·RoPE·AdamW의 원전은 [W01 가이드](w01.md)에서 이미 읽은 부품이다. 이 주차에서는 Llama 2 §2.2의 “계승” 주장을 확인하는 데 필요한 만큼만 재방문하며, LLaMA 1 recipe의 원전 완독을 반복하지 않는다.

## 본문 구성요소와 선행 개념

<a id="llama2-delta"></a>
### 본문 근거: LLaMA 1에서 유지한 것과 실제 구조 변화를 나눈다

[Llama 2 §2.2](https://arxiv.org/abs/2307.09288v2)는 standard Transformer, pre-norm RMSNorm, SwiGLU, RoPE, AdamW를 LLaMA 1에서 **대부분 계승**했다고 명시한다. tokenizer도 LLaMA 1과 동일하다. 반대로 실제 primary architecture difference는 context 2K→4K와 GQA다. [Table 1과 Appendix A.2.1](https://arxiv.org/abs/2307.09288v2)을 통해 7B·13B는 GQA를 쓰지 않고 34B·70B에만 쓴 사실, MQA의 한 KV head와 달리 GQA ablation에서는 8 KV projections를 쓴 사실을 확인한다.

| 항목 | LLaMA 1 본문 | Llama 2 본문 | W02에서 말해야 할 결론 |
| --- | --- | --- | --- |
| tokenizer | §2.1 BPE/SentencePiece, 숫자 분리, byte decomposition | §2.2: **same tokenizer as Llama 1**, 32k | Llama 2의 차이가 아니다. |
| block recipe | §2.2 pre-norm RMSNorm, SwiGLU, RoPE | §2.2가 같은 네 요소를 다시 명시 | Llama 2가 RMSNorm/SwiGLU/RoPE를 새로 도입했다는 식으로 말하지 않는다. |
| optimizer | §2.3 AdamW | §2.2 AdamW | Llama 2의 primary architecture difference가 아니다. |
| context | Table 2: 2K | Table 1/A.2.1: 4K | 명시적 architecture change다. A.2.1은 150B-token 통제 비교도 제공한다. |
| attention/KV | ordinary causal MHA | Table 1/A.2.1: 34B·70B GQA; 8 KV projections 비교 | 큰 모델에서 KV-cache/throughput 병목을 겨냥한 명시적 변화다. |
| data/tokens | 1.0T 또는 1.4T | 2.0T, new public-data mix | 구조 차이와 data-scale 차이를 같은 칸에 넣지 않는다. |

### 필요한 개념: GQA는 selection이 아니라 KV 공유 방식이다

GQA의 정의는 [GQA v3 §2.1–§2.2](https://arxiv.org/abs/2305.13245v3)에서 읽는다. 이어 Llama 2 Appendix A.2.1의 MHA/MQA/GQA 비교와 Figure 24로 KV cache가 문맥·batch가 커질수록 병목이 되는 이유를 확인한다. 구현은 [Transformers v4.31.0의 `num_key_value_heads`](https://github.com/huggingface/transformers/blob/e42587f596181396e1c4b63660abf0c736b10dae/src/transformers/models/llama/configuration_llama.py#L53-L60)와 [KV head 반복](https://github.com/huggingface/transformers/blob/e42587f596181396e1c4b63660abf0c736b10dae/src/transformers/models/llama/modeling_llama.py#L233-L328)을 보조로만 대조한다. 이 구현은 논문별 모든 체크포인트 설정을 대신하지 않는다.

<a id="preference-ranking"></a>
### 본문 근거: 사람 선호를 ranking과 PPO로 잇는 경로

[§3.2.1–§3.2.3과 Eq. (1)–(4)](https://arxiv.org/abs/2307.09288v2)에서 사람의 chosen/rejected 응답을 ranking loss로 바꾸고, helpfulness와 safety reward model을 분리하며, 최신 모델의 응답을 다시 수집해 RM의 분포 이탈을 줄이려 한 과정을 읽는다.

### 필요한 개념: reward model의 순위와 policy update는 다른 단계다

[InstructGPT v1 §3.1–§3.2](https://arxiv.org/abs/2203.02155v1)로 SFT→human preference→reward model→PPO의 공통 골격을, [PPO v2 §3](https://arxiv.org/abs/1707.06347v2)로 clipped update의 목적을 확인한 뒤 Llama 2로 돌아온다. InstructGPT의 dataset 수치나 training recipe를 Llama 2의 사실로 반복하지 않는다.

### 원전 범위: ranking loss와 iterative RLHF를 따로 읽는다

- **Preference reward model:** [Llama 2 v2 §3.2.1–§3.2.2, Eq. (1)–(2), Tables 7–8, Figure 6](https://arxiv.org/abs/2307.09288v2)에서 `-log σ(rθ(x,yc)-rθ(x,yr))`와 rating-based margin을 추적한다. helpfulness/safety를 separate RM으로 둔 이유와 preference pair가 비슷해질수록 ranking이 어려워지는 한계를 구분한다.
- **Rejection sampling과 PPO:** [Llama 2 v2 §3.2.3, Eq. (3)–(4), Figures 7–8, §5.1–§5.2](https://arxiv.org/abs/2307.09288v2)에서 K개 생성·보상 선택·재학습과 policy update를 분리한다. 저자들은 V4 전에는 rejection sampling만 쓰고 이후 PPO를 순차 결합했다. safety prompt에는 safety RM을 우선 사용하고, reference-policy KL은 높은 RM score와 낮은 human evaluation으로 나타나는 reward hacking을 완화하려는 경계다.

### 변경·확인 질문

- Llama 2의 “같은 tokenizer/RMSNorm/SwiGLU/RoPE/AdamW”는 새 도입이 아니라 계승이다. data 규모 2T와 새 public-data mix도 GQA라는 구조 변화와 같은 칸에 넣지 않는다.
- MQA/GQA의 KV sharing은 sparse attention의 token selection과 다른 축이다. 7B·13B에 GQA를 일반화하지 않는다.
- K개 응답 중 하나를 재학습하는 rejection sampling과 PPO policy update는 같은 연산이 아니다. RM 분포 이탈·reward hacking·도움됨/안전성 trade-off는 §5의 한계와 함께 읽는다.
